Add the run's three guards. `run()` takes `budgetUsd`, which projects each call's cost with `projectCallCost()` (now re-exported) and ends the run with the new `budget` stop reason before a call that could pass the cap; a budgeted run on a model with no price ends `error` with `error.kind: "unknown_price"` before its first call. A default progress policy ends a run `no_progress` after 3 identical failing tool calls in a row, or 5 calls with one `progressKey` and no success; `progress` changes the thresholds or turns it off, and a tool can declare `progressKey()`. `depth` and `maxDepth` options set the nesting that tools read from `ctx`, and `run()` throws `max_depth_exceeded` for a run nested past the cap; `nestedRunDepth(ctx)` gives a spawning tool the options for its child run. Breaking Changes: `RunResult` has a new `budget` variant and `RunError.kind` a new `unknown_price` value, so an exhaustive `switch` over either stops compiling until it handles them, and runs now end `no_progress` by default.
