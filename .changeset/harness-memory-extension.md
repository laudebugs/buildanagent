Add long-term memory as a removable extension. `memoryExtension()` from the new `@buildanagent/harness/memory` entry adds a `memory` tool (`view`, `create`, `str_replace`, `delete`, `rename`) over `.agents/memory/` only, with one sourced record per Markdown file, an index capped at 200 lines or 25 KiB at the start of each run's first request, expiry from an injected clock, and low-trust writes after untrusted tool output; no write raises a record's trust, and the extension denies the built-in `write` and `edit` tools inside the folder. `fileMemoryFiles()` from `@buildanagent/harness/memory/node` keeps the folder on disk and follows no links. A delete adds the calls that held the record to a purge list, `purgeSession()` in `@buildanagent/harness/session` rewrites a session with their content removed and each entry's base fields kept, and `pruneSessions()` takes the list as `marks`. `purgeSession()` returns the spill files of the results it cleared, for the caller to delete, and lists in `residual` the summaries and assistant text it left that may still hold the fact. A mark matches by run where the log shows one, so a reused call id in another session is left alone, and `clearPurgeMarks()` takes `unmatched` marks, which leave the list after 30 days.
