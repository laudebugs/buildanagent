The gateway makes every model call for your agent, whichever provider answers. It streams one set of events, retries a failed call, caches your prompt and prices each answer. You need this to know what happens between your agent and a provider.

## An adapter reaches each provider

An adapter is an object that talks to one provider, and you make it with your own API key. `createModel()` binds one adapter to one model id, and the result is the model your code calls. The gateway ships two adapters. `anthropic()` speaks Anthropic's Messages API, and `openaiChat()` (shown as `openai-chat`) speaks OpenAI's Chat Completions API and the servers that copy it. A scripted adapter plays answers from memory and sends no request, so a test needs no key.

## Every adapter streams the same events

`model.stream()` yields one event sequence for every adapter: a `start` event, each content block's start, deltas and end, and one terminal event, `done` or `error`. The terminal event carries the finished assistant message. `model.complete()` folds the stream into that message for you.

Two more events can appear. A `retry` event comes after `start` and before any content when the gateway retries a failed call. A `warning` event reports something the call survived, such as an option the provider would reject, and can come anywhere between `start` and the terminal event. [The transcript and the stream](/concepts/transcript-and-stream/) states the four rules of the sequence.

## A retry happens only before output

A call that fails before the model has streamed any content is retried twice by default. The first retry waits 2 seconds and the second waits 4. Each wait doubles and never passes 60 seconds. Set `retries` in `createModel()` to change the count, or to 0 to turn retries off.

Four rules keep a retry from doing harm:

1. Once a content event has reached you, the gateway never retries, because a second attempt would replay text you have already seen.
2. Only an error of kind `retryable`, such as a rate limit or an overloaded server, is retried. A `quota`, `overflow` or `fatal` error ends the call at once.
3. When the provider says how long to wait, the gateway waits at least that long, up to the 60-second cap.
4. A provider that asks for more than 60 seconds ends the call at once, with no retry. The error keeps its `retryAfterMs`, so your code can wait that long and call again.

## One option sets prompt caching

The `cacheRetention` option takes `"none"`, `"short"` or `"long"`. Each adapter maps it to its provider's cache controls, and leaving it out means `"short"`. The Anthropic adapter puts up to three cache breakpoints, on the system prompt, the last tool and the last block of the last user message. `"short"` asks for the 5-minute cache, `"long"` asks for the 1-hour cache and `"none"` sends no breakpoint. OpenAI caches prompts on its own, so the OpenAI-compatible adapter acts on the option only for a model the gateway marks as taking explicit cache breakpoints or extended retention.

## Every answer carries its cost

Every assistant message arrives with its usage and its cost. Usage counts four classes of token: `uncachedInput`, `cacheRead`, `cacheWrite`, which is split by lifetime into `5m` and `1h`, and `output`. Reasoning tokens count as output. The cost is in US dollars, in `cost.total`. The gateway multiplies each class by its rate in a price catalog, which lists rates per million tokens, and you can replace the catalog.

The cost's `basis` says where the number came from. `"provider"` means the adapter reported a total that the provider billed. `"catalog"` means the gateway multiplied your usage by the catalog's rates. `"unknown"` means the catalog lacks the model, or the provider never reported usage, and `total` is `null`. The gateway never guesses a zero, because a budget that counts an unknown price as free never stops.
