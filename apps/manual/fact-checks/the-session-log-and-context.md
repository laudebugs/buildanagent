## The research question, answered before drafting

**Question.** Why should a harness keep one append-only tree of entries, and how does context policy stay reversible?

**Answer, from the todo's sources only.**

- *One tree.* Every feature after the first message is another entry on the tree: a branch is an entry whose parent is not the newest entry, and a compaction is an entry that holds a summary and names the first entry it keeps. Reading the log builds a context from one path, and nothing is deleted, so going back, forking and compacting all stay reversible ([harness guide §2](../../../docs/guides/agent-harness.md#2-the-session-log-should-be-one-append-only-tree-of-typed-entries-with-head-a-writer-lock-and-pauses-as-entries); Pi's [session format](https://github.com/earendil-works/pi/blob/v1.5.2/packages/coding-agent/docs/session-format.md) shows both at 1.5.2). Two provenance papers argue that the failed and abandoned work is the record worth keeping: Hou et al. argue that agent-output datasets drop it, and Wong computes governance metrics from an append-only ledger ([papers survey](../../../docs/research/papers/agent-research-papers.md), U22).
- *Reversible context policy.* A layer stays reversible when it either never touches the log (a view that masks old tool results at read time) or writes a visible entry that names what it replaced (a summary), so the originals stay and a later turn can reread them ([harness guide §3](../../../docs/guides/agent-harness.md#3-context-policy-should-run-five-removable-layers-cheapest-first-and-keep-every-compaction-visible-and-reversible)). The layers run cheapest first, because masking matched LLM summarization's solve rate at about half the raw agent's cost in one setting.
- *Long work.* When a task outlasts every window, Anthropic's long-running harness moves the state out of the context into files: a progress file, a JSON feature list and git commits, which each new session reads first ([Anthropic](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents); [main report](../../../docs/research/agent-sdks-and-harness-design.md)).

**Gap.** No source measures how often rereading the originals recovers a fact that a summary dropped, and none tests the five layers together as one design. Our five layers are a design that our plan and guide describe: as of November 2026 the harness package builds the log, forks and the writer lock, and its context layers (todos N8 to N10) are not built, so the chapter says so and shows no code for them.
