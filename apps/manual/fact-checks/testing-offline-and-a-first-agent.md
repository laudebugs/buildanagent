## The research question, answered before drafting

**Question.** How do you test an agent without a model key, and what does one complete small agent look like?

**Answer, from the todo's sources and the pinned docs only.** You replace the model provider with a mock that plays scripted turns and records the requests it receives, and you assert on what your code did with those turns. The AI SDK's testing guide gives the reason: models "are non-deterministic and calling them is slow and expensive" ([Testing](https://ai-sdk.dev/docs/ai-sdk-core/testing)). The seam where the mock plugs in differs by SDK. Five of our eight harnesses swap a model object inside the process, Cloudflare's swaps one inside workerd through bundler shims, and the Claude Agent SDK and Copilot SDK harnesses mock the HTTP API that a real CLI or runtime calls. OpenAI's testing guide says what an in-process double leaves untested: provider request conversion, wire payloads and authentication headers ([Testing](https://github.com/openai/openai-agents-js/blob/v0.22.0/docs/src/content/docs/guides/testing.mdx)).

A passing assertion proves only what it checks. The Agentic Benchmark Checklist paper found that τ-bench's grader passes an agent that does nothing on the benchmark's intentionally unsolvable tasks, 38% of the airline subset and 6% of the retail subset, because success there means leaving the environment unchanged ([Zhu et al., arXiv 2507.02825v5](https://arxiv.org/abs/2507.02825), §1, §5.2 and Appendix E.2). One small complete agent, in this book's capstones, is a support-triage agent with a read-only lookup tool, a risky escalation or refund tool behind an approval or a block, a typed result and a cap on the loop, written on each of the eight SDKs.

**Gap.** No source measures how often mock-based tests miss a failure that a live model would have shown, so the chapter makes no claim about that rate.
