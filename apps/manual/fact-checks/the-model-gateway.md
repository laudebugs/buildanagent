Claims about our own gateway and SDK cite their source files and READMEs at commit [`2ad5e23`](https://github.com/laudebugs/buildanagent/commit/2ad5e23), `@buildanagent/gateway@0.1.0-alpha.26`. ## The research question, answered before drafting

**Question.** What belongs between the loop and a provider, and why do retries, caching, reasoning replay and cost accounting all sit there?

**Answer, from the todo's sources only.** The [SDK guide §2](https://github.com/laudebugs/buildanagent/blob/2ad5e23d78d4489a8e9bffd3216d82c87301d8f9/docs/guides/agent-sdk.md) puts one method, `stream()`, between the loop and every provider, and adds that "retries, usage, cost and caching live in the gateway, not in each adapter". The reason is visibility. Each of those jobs needs the provider's own terms, which the loop never reads: HTTP status codes and retry hints for retries, token classes for cost, a cache prefix for caching, and a signature tied to one model for replayed reasoning. The gateway is the only layer that holds both the provider's terms and the transcript the loop owns. [ADR 0002](../../../docs/decisions/0002-first-wire-protocols.md) gives the first two wire protocols, Anthropic Messages and OpenAI Chat Completions, on plain `fetch` so the gateway owns retries. [ADR 0003](../../../docs/decisions/0003-token-usage-fields.md) stores four token classes with no field called `input`, because providers disagree on what input includes. [ADR 0004](../../../docs/decisions/0004-cost-catalog-and-basis.md) prices usage from a versioned catalog, lets a billed total win, and blocks a budgeted run on an unknown price. [ADR 0009](../../../docs/decisions/0009-pre-emptive-budget.md) checks the budget before each call against a projected cost, so the overshoot is a projection error, not a whole call. The [MCP 2026-07-28 changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog) adds a rule from the other side: servers should list tools in a deterministic order "to improve LLM prompt cache hit rates", so a stable prefix is also the tool server's job. The guide's cross-provider rule is that reasoning signatures are valid only for the model that wrote them, so one transform pass drops the foreign ones before every request.

**The one-line rule the chapter teaches.** Put every job that needs the provider's terms in the gateway, keep every job that needs the task in the loop, and let the gateway project a call's cost before the loop sends it.

**Gap.** No source in the todo measures how often real agents hit a retryable error, or what share of real prompts a cache serves, so the chapter claims no such rate.
