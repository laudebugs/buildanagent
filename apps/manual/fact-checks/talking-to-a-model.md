## The research question, answered before drafting

**Question.** What does a program send to a model and get back, what belongs in the system prompt, and how should a builder choose a model?

**Answer, from the todo's sources only.** A program sends the whole conversation on every call, because the model keeps nothing between calls. Anthropic's Messages API "is stateless, which means that you always send the full conversational history to the API" ([Using the Messages API](https://platform.claude.com/docs/en/build-with-claude/working-with-messages)), and each message carries a role: the user's turns, the model's own earlier answers as `assistant` messages, and the system prompt, which the API takes as its own `system` field. What comes back is one assistant message with a stop reason and a usage count, and with streaming it arrives first as a run of deltas that the client folds into that message; the SDK guide's gateway design ends every stream with exactly one terminal event that carries the authoritative message ([SDK guide §2](../../../docs/guides/agent-sdk.md#2-the-model-gateway-should-expose-one-versioned-streaming-method-over-a-transcript-the-sdk-owns)). The usage splits input into uncached, cache-read and cache-write tokens beside the output, and each class has its own price, so the bill is a sum over four classes ([ADR 0003](../../../docs/decisions/0003-token-usage-fields.md); [Anthropic, Pricing](https://platform.claude.com/docs/en/about-claude/pricing)). When the model thinks, its thinking blocks come back too, each with a signature, and the program must send them back unchanged: Anthropic's models with preserved thinking check each block against what came before it ([Prefix checks on thinking blocks](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking/prefix-checks); [harness plan HD3](../../../docs/plans/build-harness.md#hd3-layers-1-2-3-and-5-on-by-default-and-a-budget-capped-at-200k-tokens-provisional)).

The system prompt holds what applies to every request: the role, the surface, the output format and stable policy, kept short and frozen for the session, with volatile data such as the date in a later message ([agent guide §4](../../../docs/guides/agent.md#4-the-system-prompt-stays-short-and-frozen-skills-hold-procedures-and-only-code-enforces)). Anthropic asks for "the minimal set of information that fully outlines your expected behavior", at the "right altitude" between brittle rules and vague guidance ([Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)). A frozen prompt keeps the prompt cache and the thinking prefix valid, since a change to `system` invalidates both for everything after it (prompt caching and prefix-check pages).

To choose a model, OpenAI's guide says to "build your agent prototype with the most capable model for every task to establish a performance baseline", then "try swapping in smaller models to see if they still achieve acceptable results", under three principles: set up evals, meet the accuracy target with the best models, then replace larger models with smaller ones for cost and latency ([A practical guide to building agents](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf), page 8). Anthropic's context-engineering post starts the same way, "testing a minimal prompt with the best model available".

**Gap.** The sources give no measured comparison of a large and a small model on one agent task at the prices of November 2026, and a replay cannot price a run, because a transcript records no usage. The chapter therefore prices T28's scripted usage at each model's published rates and leaves the quality comparison to the reader's own evals, as the OpenAI guide does.
