## The research question, answered before drafting

**Question.** How does an agent pause for a person's approval and resume safely from a saved session, and why is an approval only one gate of several?

**Answer, from the todo's sources and the pinned docs only.** An approval is a pause stored as data. The SDK does not run the gated tool; it ends the run with the call pending, and the run continues from a saved copy when a decision arrives. The AI SDK's saved copy is the message array, the OpenAI Agents SDK's is a serialized `RunState`, and LangChain's is a checkpoint under a thread id ([Tool Approvals](https://ai-sdk.dev/docs/agents/tool-approvals.md), [Human-in-the-loop](https://github.com/openai/openai-agents-js/blob/v0.21.0/docs/src/content/docs/guides/human-in-the-loop.mdx), [LangChain Human-in-the-loop](https://github.com/langchain-ai/docs/blob/9d9747d0cf241e086c616a16d5ce230ad8f8f31d/src/oss/langchain/human-in-the-loop.mdx)). Because the copy lives in your storage, it is input: OpenAI's guide says the restore "does not authenticate the snapshot or the person submitting it", and the AI SDK signs approvals only when `experimental_toolApprovalSecret` is set. Our two tamper examples show the consequence: an edited saved call runs as edited unless a signature covers it.

An approval is one gate of several. OpenAI's guide calls guardrails "a layered defense mechanism" of which "a single one is unlikely to provide sufficient protection", lists seven types, and rates each tool low, medium or high to decide when to pause for a person ([A practical guide to building agents](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf), pp. 24–27, 31). OWASP's LLM01 says "it is unclear if there are fool-proof methods of prevention for prompt injection", so the design goal is containment: least privilege, human approval for high-risk actions and segregated external content ([LLM01:2025](https://raw.githubusercontent.com/OWASP/www-project-top-10-for-large-language-model-applications/main/2_0_vulns/LLM01_PromptInjection.md)).

**Gap.** No source measures how often reviewers approve a call they should have rejected, so the chapter makes no claim about approval fatigue's rate.
