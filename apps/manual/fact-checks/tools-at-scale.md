# Fact-check: Tools at scale: the registry, deferred tools, MCP and skills

The claims log for [`tools-at-scale.md`](../src/content/chapters/tools-at-scale.md), checked section by section as each was drafted (BK21). Each row names the claim, the section it sits in, the verdict and the primary source. Pages were read on 2026-11-22. Package claims are checked against the harness pins of that date: `@anthropic-ai/claude-agent-sdk@0.3.327`, `ai@7.0.162` with `@ai-sdk/mcp@2.0.90`, `agents@0.33.0`, `@github/copilot-sdk@1.0.31` and `@earendil-works/pi-coding-agent@1.5.2`. Claims about our own harness cite its source files at commit [`2174e4c`](https://github.com/laudebugs/buildanagent/commit/2174e4c2e80fff77540da496110a5ec36330273c), and the chapter says that the code is a design where its todo is not done.

## The research question, answered before drafting

**Question.** How does an agent with dozens of tools stay usable, and how do MCP servers and skills fit after MCP's 2026-07-28 revision?

**Answer, from the todo's sources and the pinned docs only.** An agent stays usable by keeping most tool definitions out of each request. One registry gives every tool, whatever its origin, one name, one exposure setting (sent, deferred or hidden) and one trust mark, and the permission pipeline decides each call from that description. A deferred tool costs a name until the model searches for it, so a request carries a handful of definitions instead of dozens. Anthropic's own measurement puts a five-server setup at about 55K tokens of definitions and its tool search at about 8.7K ([Introducing advanced tool use](https://www.anthropic.com/engineering/advanced-tool-use)). MCP supplies tools you did not write, and its 2026-07-28 revision makes each request stand alone: no `initialize` handshake, no session id, a `server/discover` call that is optional for clients, and a server's question to the user returned as an `input_required` result that the client answers by retrying ([changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog)). The same revision deprecates Roots, Sampling, Logging and dynamic client registration ([deprecated features](https://modelcontextprotocol.io/specification/2026-07-28/deprecated)). Skills are the cheaper tier: a name and a description sit in the prompt, and the body enters the context only when the model opens the skill. Both kinds of extension bring untrusted text and code into the agent, and two November 2026 papers show that a name or a description is no evidence of what the code does.

**Gaps.** No source measures how often a model fails to find the right deferred tool or to open the right skill, so the chapter claims no rate. Anthropic's accuracy figures come from its own internal tests. Our own MCP client, extension loader and skill loader are not built (todos N21 to N25 are `ready`), so the chapter describes them as design.
