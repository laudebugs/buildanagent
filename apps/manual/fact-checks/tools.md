# Fact-check: Tools: schemas, validation, errors the model can read, and identity it cannot fake

Each row names the claim, the section it sits in, the verdict and the primary source. Pages were read on 2026-11-19; package claims are checked against the harness pins of that date: `@openai/agents@0.21.0`, `@google/adk@2.5.0`, `@earendil-works/pi-coding-agent@1.5.2` and `@anthropic-ai/claude-agent-sdk@0.3.327`.

## The research question, answered before drafting

**Question.** How does a model learn what a tool does, what should it be told when a call fails, and why must a tool take identity from trusted context?

**Answer, from the todo's sources only.** A model learns a tool only from what the request carries: its name, its description and its input schema. Anthropic's tool-use page says the model "only receives the schema you provided and the result you returned", never the implementation ([How tool use works](https://platform.claude.com/docs/en/agents-and-tools/tool-use/how-tool-use-works)), and its tool-writing post asks for descriptions written as "you would describe your tool to a new hire on your team", with unambiguous parameter names such as `user_id` rather than `user` ([Writing effective tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents)). A schema describes the arguments but cannot force them, so each SDK validates the model's arguments before your function runs ([SDK guide §4](../../../docs/guides/agent-sdk.md#4-tools-should-take-standard-schema-validate-inside-the-sdk-and-return-every-failure-to-the-model-as-data)).

When a call fails, the model should get the failure back as a tool result it can read, not an exception that ends the run, and that result should say what to try next. Anthropic asks teams to "prompt-engineer your error responses to clearly communicate specific and actionable improvements, rather than opaque error codes or tracebacks" (same post). The four SDKs differ in what they send by default: ADK returns the Zod issues as `{ error }`, Pi lists each failing path with the received arguments, the Claude Agent SDK returns the raw exception message unless the handler composes one with `isError: true`, and the OpenAI Agents SDK replaces every failure with one fixed sentence unless the tool sets `errorFunction` (rows below, from each package's code and docs). Our agent guide adds the missing half from practitioner reports: the error should also say what not to do, such as invent data ([agent guide §3](../../../docs/guides/agent.md#3-tools-deserve-more-design-effort-than-the-prompt-few-workflow-shaped-tools-identity-from-trusted-context-and-errors-that-say-what-to-do-next)).

A tool must take identity from trusted context because every argument in its schema is chosen by the model, and the model's input includes text that any customer can write. Six of our eight triage capstones take a free `email`, `orderId` or `customerId` from the model, so a ticket that names another customer can put that customer's record in the context ([agent guide](../../../docs/guides/agent.md), opening and §3). OWASP's fix is to "execute extensions in user's context" and to "implement authorization in downstream systems rather than relying on an LLM to decide if an action is allowed" ([OWASP LLM06](https://raw.githubusercontent.com/OWASP/www-project-top-10-for-large-language-model-applications/main/2_0_vulns/LLM06_ExcessiveAgency.md)). Each SDK hands a tool something the model never sees: OpenAI's `RunContext`, ADK's tool `Context` with the session's user id and state, and, in Pi and the Claude Agent SDK, whatever your code closes over when it builds the tool.

**The one-line rule the chapter teaches.** Write the schema for the model and check it in code, return every failure as a result that says what to try next, and leave identity out of the schema, so the model can never choose it.

**Gap.** The sources measure tool descriptions (Anthropic's SWE-bench refinement) but no source measures how much an actionable error message changes a model's retry rate against a generic one. The chapter therefore recommends actionable errors as our judgement and claims no measured gain.
