# 0058. Publish the protocol, harness, CLI and agent-safety together as alphas, after N30, in one fixed group of six with the gateway and SDK

- **Status:** Accepted (owner, 2026-11-22; relayed by the manager session)
- **Date:** 2026-11-22
- **Amends:** [ADR 0047](0047-first-release-and-trusted-publishing.md), which covered only the gateway and SDK
- **Plan:** [publish-and-docs.md, PB4](../plans/publish-and-docs.md#pb4-publish-the-protocol-harness-and-cli-packages-after-the-gateway-and-sdk-accepted)

## Context

[ADR 0047](0047-first-release-and-trusted-publishing.md) published `@buildanagent/gateway` and `@buildanagent/sdk`, and the [publish plan](../plans/publish-and-docs.md#1-goal-and-non-goals) left the harness packages out: "They join the fixed version group when their plans ship them." On 2026-11-22 the owner decided to publish three more: `@buildanagent/protocol`, `@buildanagent/harness` and `@buildanagent/cli`. `@buildanagent/evals` stays private. The same day the owner also decided to publish `@buildanagent/agent-safety`, the safety core the harness depends on, with "yes, we're publishing agent-safety too".

As of 2026-11-22 the four packages are `private: true` at version 0.0.0. At the first check that day `npm view` returned E404 for the protocol, harness and CLI, so unlike the gateway and SDK they had no npm placeholder. The owner then published placeholders of all four by hand, and `npm view` at about 15:00 UTC listed `0.0.0-bootstrap.0` and `0.0.0-stage` for each, with `latest` and `bootstrap` on `0.0.0-bootstrap.0`; neither version is deprecated yet, and deprecation is pending owner action (rows L9-27 and L9-36). The CLI's `src/index.ts` is a stub that exports only `PACKAGE_NAME`; todo N30 builds the real CLI. The protocol's server requests, cancellation and stdio transport are unbuilt (N28 and N29). `.changeset/config.json` holds one fixed group, `["@buildanagent/gateway", "@buildanagent/sdk"]`, and `release.yml` packs and publishes `gateway sdk` in a loop. `@buildanagent/agent-safety` depends only on the gateway, with optional peers for its `byok`, `cost` and `stores/dynamodb` entries ([ADR 0043](0043-standalone-safety-core.md)).

## Decision

1. **One release, after N30.** The protocol, harness, CLI and agent-safety publish together, in one release, and nothing publishes until N30 (the CLI) is merged, so the CLI has a working binary. N30 depends on N28, which builds the protocol's server requests, and the stdio transport (N29) lands beside them, so both land first. The owner chose this on 2026-11-22, replacing an earlier plan to publish the protocol first, then the harness, then the CLI. Inside the release, the publish job still goes in dependency order, gateway, SDK, agent-safety, protocol, harness, CLI, so each package's `workspace:*` pins name a version npm already holds.
2. **Version and dist-tag.** Each package publishes as a `0.1.0-alpha.N` under npm's `alpha` dist-tag, and `latest` stays untouched. For the new packages `latest` will point at whatever placeholder the owner publishes by hand (decision 6), as it points at `0.0.0-bootstrap.0` for the gateway and SDK.
3. **One fixed group of six.** `.changeset/config.json` lists gateway, SDK, agent-safety, protocol, harness and CLI in one `fixed` group. Changesets' `fixed` option declares that "packages should be version-bumped and published together", and its fixed-packages guide says, in paraphrase, that the group's members share one version even if some had no changes. The cross-package pins are `workspace:*`, which pnpm replaces with the target package's current version when it packs, so every packed range names the version published beside it. A fixed group keeps those pins coherent and lets a user quote one version for the whole stack. The cost is that a change to any package bumps all six, so an unstable package still takes a version number and a changelog entry with the others. Unverified: whether every member reaches one version while some are `private` (L10) or absent from `pre.json` (L11) is untested, so L10's throwaway-branch test gates the config change and L11 states a fallback (rows L9-10 and L9-20).
4. **`private` drops late.** A package, agent-safety included, loses `private: true` only in the todo that bootstraps it (L11), after L10 has made it buildable, documented and checked. Until then its first alpha can't publish.
5. **The protocol imports no gateway or SDK code at run time.** It depends on both for types only. N26 checks the sources in the repo; the check on the published tarball is separate (L10), because only the tarball's JavaScript decides what a user's install loads.
6. **Placeholders by hand, trusted publishers late.** npm needs a package to exist before a trusted publisher can be added, so the owner publishes a placeholder of each package by hand, as on 2026-11-19. The owner did this for all four new packages on 2026-11-22, with deprecation still pending owner action; L11 verifies the result with `npm view`. A new trusted publisher expires unless it publishes within 2 days, so the owner adds the four only when the release is about to publish.
7. **The CLI has a binary.** It needs a `bin` entry and a shebang that survives the build, which L10 sets up and N30 fills in.
8. **First alphas only from CI.** The first alpha of each package publishes only through `release.yml`, on a push to `main`, never from a session or a developer's machine.
9. **`agent-safety` publishes as the sixth member (owner, 2026-11-22).** The harness lists it in `dependencies`, so a published harness needs it on npm, and ADR 0043 already made it standalone with no dependency on the SDK. The owner chose to publish it over vendoring or inlining what the harness imports. It publishes at the same version as the others, and its optional peers stay optional, so an install that doesn't use `byok`, `cost` or `stores/dynamodb` pulls none of them.

## Consequences

- **Todos.** L10 makes the four packages publishable while they stay private. L11 bootstraps them and changes `release.yml`; because sessions don't edit `.github/workflows`, L11 hands the owner the whole new file. L11 waits for N29 and N30, which don't depend on each other and both depend on N28.
- **Release code changes.** `release.yml` and `scripts/ci/release-plan.mjs` name only the gateway and SDK today, so L11 changes both for six packages in dependency order. Dropping `private` makes the four versioned members at 0.0.0 beside the gateway and SDK at an alpha, which `release-plan.mjs` rejects as mixed versions before its pending-changeset skip, so L11 also moves that check below the skips.
- **The `agent-safety` question is answered.** The owner chose to publish it as the sixth member (decision 9), so the harness needs no vendored copies. L10's pack test fails any package that will publish and depends on a workspace package outside the six, so a private dependency can't slip through.
- **Owner setup.** The owner has reported publishing the four placeholders (L11 verifies them), commits the new `release.yml` in the same merge as L11, adds the four trusted publishers immediately before that merge, whose changeset starts the auto-merged Version packages pull request and so the publish, and so the first publish lands within the 2 days ([plan §3](../plans/publish-and-docs.md#3-what-the-owner-sets-up)).
- **ADR 0047 stands** for trusted publishing, the `release` environment and the Changesets flow. This record widens the group it names and adds the readiness gates.
