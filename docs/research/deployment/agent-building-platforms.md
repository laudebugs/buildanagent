# Every builder generates agents, but none ships tested code to the user's own cloud

As of November 2026, nobody sells the full "agent that builds agents" product. That product would be a cloud service that turns a description into an agent, tests it, and deploys it to the user's own Cloudflare, AWS, GCP, Azure or Vercel account with the user's own model key. The pieces exist, spread across four groups. Vendor platforms (OpenAI, Google, AWS, Microsoft, Salesforce, Anthropic) and low-code builders (n8n, Langflow, Dify, CrewAI, Relevance, Lindy, Gumloop, Zapier, Botpress and others) all now generate a draft agent from natural language, so prompt-to-agent is table stakes. Almost all of them emit their own configuration, and that configuration runs only on their own runtime. Developer hosting platforms (LangSmith, Mastra, Vercel, Cloudflare, Inngest, Trigger.dev, Temporal) supply portable code, durable waits and credential-brokering sandboxes, but they leave the generating to the user. Research systems (ADAS, AFlow, DGM) show that machine-designed agents beat hand-designed ones on benchmarks, and they also show that a generator will game an evaluator it can see. Each group holds some of the pieces, and none holds them all.

Across all four groups, five things are missing or rare. First, few builders hand the user portable code: CrewAI's ZIP export and the AWS and Google exports to their own SDKs are the documented cases, and OpenAI's export closes on 2026-11-30. Second, none of the platforms deploys a built agent to Cloudflare Workers or Vercel. Third, bring-your-own key usually means "models we resell" or a paid tier with a markup, and AWS's AgentCore harness is the main vendor exception. Fourth, no product tests a generated agent before showing it. Fifth, none signs approvals or reverses the side effects an agent caused. buildanagent's planned strengths sit on exactly those gaps, but **nothing of ours is built**: we have eight verified SDK references and reviewed plans, not a product. The opening is therefore a narrow first slice: generate agent code against an SDK we have already verified, ship it with its own eval set, and deploy it into the user's own Cloudflare account behind a BYO key.

This report is for the project owner, who will decide whether an agent-building platform becomes a plan. It covers how each group builds agents, where those agents can run, how safe and testable they are, what they cost, and how our plans compare. It ends with a recommended first product slice. A note on sources: the research notes read many vendor pages through search summaries, and the fact-check then re-read most of them directly ([fact-check log](fact-check-agent-building-platforms.md)). Claims whose primary page still could not be read, mostly Salesforce's, are marked "(search summary)". Third-party blogs and aggregators are marked "(secondary)". Everything is as of November 2026.

## Prompt-to-agent is table stakes, and its output is vendor configuration

Every major platform now ships a builder agent, but the artefact it produces is configuration for that vendor's runtime. The market has converged on one shape: an agent is a model plus instructions, tools, skills and MCP servers, stored as a config object and run by a vendor-operated loop. Only a few platforms emit anything the user can run elsewhere.

Every vendor now defines an agent as configuration, and Microsoft and Salesforce generate the most of it from a prompt. Copilot Studio's standard harness takes a short prompt and generates the agent's name, description and instructions, then suggests triggers, channels, knowledge and tools ([Copilot Studio quickstart](https://learn.microsoft.com/en-us/microsoft-copilot-studio/fundamentals-get-started)). A newer Copilot harness generates the whole configuration from a description in preview. Copilot Studio can upgrade a standard agent to it, but an agent on the new harness "can't be transferred to the standard harness" ([Copilot harness overview](https://learn.microsoft.com/en-us/microsoft-copilot-studio/agents-experience/overview)). Salesforce's Agentforce Vibes writes Agent Script, a YAML-based language that mixes natural-language instructions with programmatic expressions, and it ships `developing-agentforce`, `testing-agentforce` and `observing-agentforce` skills ([Agentforce Vibes](https://developer.salesforce.com/docs/platform/code-builder/guide/afv-agentdev-overview.html); [Agent Script](https://developer.salesforce.com/docs/ai/agentforce/guide/agent-dx-nga-script.html)) (search summary). Agent Script is a text artefact, but it runs only on Salesforce. AWS took the config route. Its AgentCore harness, GA on 2026-06-17, defines an agent as model, tools, skills and instructions through `CreateHarness` ([AgentCore harness GA](https://aws.amazon.com/about-aws/whats-new/2026/06/amazon-bedrock-agentcore-harness-generally-available/); [AWS ML blog](https://aws.amazon.com/blogs/machine-learning/amazon-bedrock-agentcore-harness-is-now-generally-available-go-from-idea-to-production-grade-agent-in-minutes/)). Kiro CLI 1.27 generates agent configuration from a description, but those are Kiro agents, not AgentCore deployments ([Kiro changelog 1.27](https://kiro.dev/changelog/cli/1-27/)). Anthropic's Claude Managed Agents, in beta under header `managed-agents-2026-04-01`, defines an Agent as "the model, system prompt, tools, MCP servers, and skills", created once through `/v1/agents` ([Managed Agents overview](https://platform.claude.com/docs/en/managed-agents/overview)). Google renamed Vertex AI Studio to Agent Studio when Gemini Enterprise Agent Platform launched on 2026-04-22. Agent Studio lets users "move seamlessly from building simple prompts to deploying complex agents" and export to the open-source Agent Development Kit (ADK) ([Gemini Enterprise Agent Platform](https://cloud.google.com/blog/products/ai-machine-learning/introducing-gemini-enterprise-agent-platform); [name changes](https://docs.cloud.google.com/gemini-enterprise-agent-platform/vertex-ai-name-changes)).

The vendors' retreat from their first-generation builders is the clearest market signal. OpenAI deprecated its Agent Builder canvas on 2026-06-03 and shuts it down on 2026-11-30. The replacements are the Agents SDK (code) and ChatGPT Workspace Agents (natural language) ([OpenAI deprecations](https://developers.openai.com/api/docs/deprecations.md)). The migration guide exports a workflow to Agents SDK code but warns that it "does not convert your workflow graph or guarantee that every behavior transfers unchanged" ([Migrate from Agent Builder](https://developers.openai.com/api/docs/guides/agent-builder/migrate-from-agent-builder)). AWS closed Bedrock Agents Classic to new customers on 2026-07-30 and froze its model catalogue ([Agents Classic maintenance mode](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-classic-maintenance-mode.html)). Two vendors have therefore retired a first-generation agent builder. OpenAI's canvas lasted about 14 months from its October 2025 launch, and Bedrock Agents about two and a half years from its November 2023 GA ([Bedrock Agents GA](https://aws.amazon.com/about-aws/whats-new/2023/11/boost-generative-ai-development-agents-bedrock)) (search summary for both launch dates). Both now treat code, or config plus a builder agent, as the durable form.

Low-code builders have all added a builder agent on top of their canvas. n8n's AI Workflow Builder creates and debugs workflows "using natural language descriptions… including node selection, placement, and configuration", at one credit per message ([n8n docs](https://docs.n8n.io/build/ways-of-building-workflows/ai-workflow-builder.md)). Langflow Assistant "can build complete flows or create individual components from natural language prompts" ([Langflow Assistant](https://docs.langflow.org/langflow-assistant)). Botpress's Vibe "translates your requests into structured agent configuration" ([How Viber works](https://botpress.com/docs/viber/get-started/how-viber-works.md)). Relevance AI's Invent goes furthest: a "forward deployed agent" that creates agents, tools, triggers and workforces, then "reviews live performance… proposes and tests improvements" ([Invent docs](https://relevanceai.com/docs/build/invent/invent.md)). Lindy and Zapier (with Copilot) ship the same kind of builder ([Lindy docs](https://docs.lindy.ai/index.md); [Zapier Agents](https://zapier.com/agents)), and the research notes report one at Gumloop, Sim, Voiceflow (Atlas) and Stack AI, which the pages cited here do not show. Only CrewAI Crew Studio hands its output over as code. In Studio, "the AI generates agents, tasks, and tools", and the user can **Publish** to CrewAI's hosted AMP platform or **Download** the source as a ZIP ([Crew Studio](https://docs-platform.crewai.com/platform/en/features/crew-studio.md)). That ZIP export is the only documented case in this group of a builder agent handing the user code they own.

Developer platforms mostly stay code-first, with four exceptions. LangSmith Agent Builder, now renamed LangSmith Fleet, is "an agent builder, not a visual workflow builder" built on the `deepagents` package. Its output is a hosted agent, and search found no export to standalone code ([LangChain blog](https://blog.langchain.com/langsmith-agent-builder); [LangSmith Fleet](https://docs.langchain.com/langsmith/fleet/index)). Replit's Routines, which replaced the Agents & Automations page, schedule agent work from a chat and run it on Replit ([Replit Routines](https://docs.replit.com/chat/routines.md)). Mastra's `@mastra/core` 1.85.0 ships an enterprise-licensed `agent-builder/ee` module with model allowlists and policies ([npm @mastra/core](https://registry.npmjs.org/@mastra/core)), which points to a governed builder whose release status is unverified. The closest analogue to our idea is **Vercel's v0 API**, GA in 2026. It generates and runs an app in an isolated Vercel Sandbox, returns a preview URL, deploys through `chats.deploy`, and can be called as a tool from other agents over MCP ([InfoQ](https://infoq.com/news/2026/08/vercel-v0-api) (secondary); [v0 docs](https://v0.app/docs/llms.txt)). It builds apps, though, and it deploys to Vercel.

| Group | How the agent is built | What the builder agent emits | Code the user owns |
| --- | --- | --- | --- |
| Vendor platforms | config harness plus code SDK; builder agents at Microsoft, Salesforce, Google, AWS (Kiro) | vendor config (Copilot Studio, Agent Script, AgentCore harness, Managed Agents) | AWS exports a harness to Strands code; Google Agent Studio exports to ADK; OpenAI's export ends 2026-11-30 |
| Low-code builders | canvas plus builder agent | the vendor's graph JSON (n8n, Langflow, Dify, Flowise, Sim) or hosted config (Relevance, Lindy, Zapier, Botpress) | CrewAI Studio ZIP; Botpress ADK is code but Botpress-hosted |
| Developer hosting | code SDK plus optional hosted studio | LangSmith Fleet and Replit agents are hosted; v0 generates apps | all frameworks are code, but none generates the agent for you |
| Research | a meta-agent writes and searches agent code | Python agents scored on benchmarks | yes, but tuned to academic tasks |

The table supports one conclusion. A builder agent whose output is plain, portable code that passes tests is still scarce, even though the builder agent itself is now standard.

## No platform deploys a built agent to Cloudflare or Vercel, and BYO key usually carries a markup

Portability today means either "run our server in Docker on any cloud" or "export open SDK code and deploy it yourself". None of the vendors, low-code builders or prompt-to-app products documents deploying a built agent onto Cloudflare Workers or Vercel Functions as a first-class target. The deploy-anywhere niche is open, but the reason is structural. Every builder's runtime assumes a long-running, stateful server.

Among vendors, AWS, Google and Anthropic offer the most portability, and each keeps the user inside its own model family or cloud. One AgentCore CLI command exports a harness to Strands-based code; export to the Claude Agent SDK is "coming soon" ([AWS ML blog](https://aws.amazon.com/blogs/machine-learning/amazon-bedrock-agentcore-harness-is-now-generally-available-go-from-idea-to-production-grade-agent-in-minutes/)). AgentCore Runtime also hosts LangGraph, CrewAI and Strands agents, and harness sessions run in microVMs ([AgentCore overview](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/what-is-bedrock-agentcore.html)). Google's ADK deploys with `adk deploy cloud_run`, `agent_engine` or `gke` ([ADK CLI reference](https://adk.dev/api-reference/cli/)), and a cross-cloud Agent Gateway for non-Google Kubernetes clusters entered limited preview on 2026-11-11 ([Agent Platform release notes](https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes)). Anthropic sells the closest vendor analogue to "the harness in your own cloud". Self-hosted Claude Managed Agents runs `cma-server` with PostgreSQL 16+ and workers on "a cloud account or an on-premise data center", with inference through Bedrock, Google, Foundry or your own gateway. The self-hosted server is gated by the account team, licensed under a proprietary server agreement, and limited to Claude models ([Self-hosted Claude Managed Agents](https://platform.claude.com/docs/en/managed-agents/self-hosted)). OpenAI's Agents API can run its Codex harness against compute you host with `codex exec-server` ([Self-hosted sandboxes](https://developers.openai.com/api/docs/guides/agents-api/environments/self-hosted)). Copilot Studio and Agentforce stay inside their vendor's cloud, although Agentforce agents built with Agent Script can be exposed as MCP tools ([MCP for Agentforce](https://help.salesforce.com/s/articleView?id=ai.agent_mcp.htm&language=en_US)) (search summary).

The self-hostable low-code builders are all long-running servers. Sim's Docker Compose stack bundles PostgreSQL, Redis and a scheduler ([Sim self-hosting](https://docs.sim.ai/platform/self-hosting)). Flowise's deployment guides cover AWS, Azure, GCP, Railway, Render and others, but neither Vercel nor Cloudflare ([Flowise deployment](https://docs.flowiseai.com/configuration/deployment.md)). Langflow's `lfx` executor serves exported flows with a lighter runtime, but it is still Python ([PyPI lfx](https://pypi.org/project/lfx/)). Stack AI's on-prem option is a Docker CLI that orchestrates a "50+ service platform" ([Stack AI CLI](https://docs.stackai.com/stackai-auto-cli/docs.md)). Botpress, Voiceflow, Zapier, Make, Relevance, Lindy and Gumloop are hosted only, and Botpress has sunset its self-hosted v12 ([Botpress v12](https://botpress.com/docs/studio/guides/advanced/v12.md)). The de facto interop path is "export as MCP server", offered by n8n, Langflow, Dify and CrewAI ([n8n MCP Server Trigger](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-langchain.mcptrigger.md); [Dify MCP server](https://docs.dify.ai/en/self-host/use-dify/publish/publish-mcp.md)). A generated agent could call any of those flows as a tool.

The developer platforms show where portability actually comes from: a pluggable durable-state layer. Vercel's Workflow DevKit runs off Vercel through "Worlds". The Postgres World "needs a long-lived process to run its worker, so it does not work on serverless platforms" ([Postgres World](https://useworkflow.dev/worlds/postgres)), and a search summary reports that it passed 304 of 312 end-to-end tests. Mastra publishes deployers for Cloudflare and Vercel (`@mastra/deployer-cloudflare` 1.2.44) and server adapters for Express and Hono ([npm @mastra/deployer-cloudflare](https://registry.npmjs.org/@mastra/deployer-cloudflare)), which makes it the most deploy-anywhere framework found. Cloudflare Agents bind each agent to a Durable Object and its SQLite ([Cloudflare Agents](https://developers.cloudflare.com/agents/)). LangGraph's library is MIT, but its Python Agent Server (`langgraph-api` 0.18.3) is Elastic-2.0, and self-hosting with a control plane needs an Enterprise plan ([PyPI langgraph-api](https://pypi.org/pypi/langgraph-api/json); [LangSmith deployment](https://docs.langchain.com/langsmith/deployment)). Lovable Cloud runs on a Lovable-managed Supabase that is invisible in your own Supabase account ([RapidDev](https://rapidevelopers.com/lovable-issues/what-is-lovable-cloud)) (secondary). Our portability report reached the same conclusion from the runtime side: portability is mostly a storage-and-wake problem, and Cloudflare and Vercel now host third-party harnesses through exactly those seams ([portable agents report](portable-agents.md#seven-seams-let-our-harness-deploy-anywhere)).

Bring-your-own model key splits cleanly by business model. **AWS is the one vendor whose hosted harness takes other providers' keys.** The AgentCore harness calls Bedrock models, OpenAI's API, Gemini or any LiteLLM provider, keeps the keys in AgentCore Identity's token vault, and can switch provider mid-session ([AWS ML blog](https://aws.amazon.com/blogs/machine-learning/amazon-bedrock-agentcore-harness-is-now-generally-available-go-from-idea-to-production-grade-agent-in-minutes/)). OpenAI's Agents API bills "at the selected model's API rates" ([Agents API overview](https://developers.openai.com/api/docs/guides/agents-api/overview)), and Anthropic's hosted Managed Agents runs Claude only. Self-hosted open-source builders accept any key. n8n says self-hosted users "bring your own key (BYOK), so no credit limits apply" ([n8n pricing](https://n8n.io/pricing/)). Hosted builders gate BYO key or mark it up. Relevance includes BYOK from its Pro tier ([Relevance pricing docs](https://relevanceai.com/docs/get-started/pricing.md)), Make allows custom AI provider connections only on paid plans ([Make credits](https://help.make.com/credit-usage-for-ai-agents.md)), and Gumloop adds an "Orchestration Fee 8%" ([Gumloop pricing](https://www.gumloop.com/pricing)). Botpress bills AI usage through its own account ([Botpress pricing](https://botpress.com/pricing)), and the Zapier Agents page offers no BYOK option ([Zapier Agents](https://zapier.com/agents)). Gateways set the best practice. Cloudflare AI Gateway stores BYOK keys in Secrets Store and, since 2026-09-14, offers an opt-in `byok_only: true` that refuses to fall back to Cloudflare-billed credentials ([BYOK](https://developers.cloudflare.com/ai-gateway/configuration/bring-your-own-keys/); [Unified Billing](https://developers.cloudflare.com/ai-gateway/features/unified-billing/); [changelog 2026-09-14](https://developers.cloudflare.com/changelog/post/2026-09-14-require-provider-credentials/)). Vercel AI Gateway charges no token markup on BYOK ([AI Gateway FAQ](https://vercel.com/docs/ai-gateway/faq)), but when a BYOK request fails it retries on Vercel's own provider keys and bills your credits. That fallback "is on by default", and turning it off costs $0.20 per 1,000 BYOK requests ([Vercel BYOK](https://vercel.com/docs/ai-gateway/authentication-and-byok/byok)). A BYO-key product should make Cloudflare's setting its default and design against Vercel's.

Lock-in therefore concentrates in three places. The first is the data and identity plane: Salesforce org data, Microsoft 365 and Entra, Google Workspace seats. The second is hosted state: sessions, memory and approval queues held by the vendor. The third is the definition format itself, as OpenAI's lossy export and Copilot Studio's one-way harness upgrade show ([Migrate from Agent Builder](https://developers.openai.com/api/docs/guides/agent-builder/migrate-from-agent-builder); [Copilot harness overview](https://learn.microsoft.com/en-us/microsoft-copilot-studio/agents-experience/overview)). Ownership churn adds a fourth risk. IBM now sells Langflow, which it acquired with DataStax (the acquisition is not on the cited page), and Workday bought Flowise on 2025-08-14 ([IBM Langflow](https://www.ibm.com/products/langflow); [Workday press release](https://newsroom.workday.com/2025-08-14-Workday-Acquires-Flowise%2C-Bringing-Powerful-AI-Agent-Builder-Capabilities-to-the-Workday-Platform)).

## Approvals are common, but signed approvals and side-effect undo exist nowhere

Tool-level human approval is now standard, so a new platform gains nothing by merely having it. What separates the platforms is how durable an approval is and what happens to side effects. No platform signs its approval records, and no platform reverses or compensates what an agent did to external systems.

Approval durability varies widely. Anthropic's `always_ask` policy idles the session with `stop_reason.type = requires_action`, and "the session waits indefinitely for a response". Each tool-use event carries an `evaluated_permission` whose `reason_code` is meant for audit records ([Permission policies](https://platform.claude.com/docs/en/managed-agents/permission-policies)). AWS AgentCore Policy, GA on 2026-03-03, is the only vendor policy engine found with a formal language. It converts natural-language rules to Cedar and checks every tool call at the gateway ([Policy GA](https://aws.amazon.com/about-aws/whats-new/2026/03/policy-amazon-bedrock-agentcore-generally-available/)). Among builders, Dify's Human Input node has a timeout branch, and each run has a 7-day limit by default ([Dify Human Input](https://docs.dify.ai/en/self-host/use-dify/nodes/human-input.md)). Flowise saves each checkpoint, so a paused workflow resumes "even after an application restart" ([Flowise Agentflow V2](https://docs.flowiseai.com/using-flowise/agentflowv2.md)). Sim's pause "has no automatic response timeout" ([Sim HITL](https://docs.sim.ai/workflows/blocks/human-in-the-loop)). CrewAI AMP routes approvals by email with "automatic fallback responses when no human replies in time" ([CrewAI HITL](https://docs-platform.crewai.com/platform/en/features/flow-hitl-management.md)). n8n, Gumloop, Lindy and Relevance gate tools too, though n8n does not say whether a paused approval survives a restart ([n8n HITL](https://docs.n8n.io/build/integrate-ai/ai-examples/human-in-the-loop-for-tools.md); [Gumloop HITL](https://docs.gumloop.com/core-concepts/human_in_the_loop.md)). Developer platforms turn the long wait into a primitive. Trigger.dev waitpoint tokens, Inngest `step.waitForEvent()`, Temporal signals and Cloudflare fibers with an `idempotencyKey` all pause without consuming compute ([Cloudflare durable execution](https://developers.cloudflare.com/agents/agent-class/durable-execution/); [AgentKit HITL](https://agentkit.inngest.com/advanced-patterns/human-in-the-loop)). Across all four groups, **no documentation describes a signed or tamper-evident approval**.

Reversibility stops at the agent definition. Builders version the definition: n8n keeps workflow history and Git environments, Dify separates drafts from published versions, and Voiceflow lets you "roll back when you need to" ([n8n pricing](https://n8n.io/pricing/); [Dify version control](https://docs.dify.ai/en/self-host/use-dify/build/version-control.md); [Voiceflow publishing](https://www.voiceflow.com/docs/documentation/deploy/environments/publishing.md)). None documents reversing the side effects an agent caused, and none offers idempotency keys on tool calls. The vendors fare no better. Microsoft says hosted-agent recovery still depends on application checkpoints and "safe handling of repeated work" ([Foundry October 2026](https://devblogs.microsoft.com/foundry/whats-new-in-microsoft-foundry-october-2026/)). Anthropic marks an automatic retry with `session.status_rescheduled` ([Managed Agents reference](https://platform.claude.com/docs/en/managed-agents/reference)). Salesforce's Simulate mode, which "does not change real data", is the nearest thing to a dry run ([Debug Agent Script](https://developer.salesforce.com/blogs/2026/03/agent-script-decoded-how-to-debug-agent-script)) (search summary). Retries without idempotency or compensation make repeated side effects the builder's problem on every platform. Cloudflare's per-tool `replay: "safe" | "unsafe"` flag for Pi is the most explicit design found ([Cloudflare filesystem tools](https://developers.cloudflare.com/agents/tools/filesystem/)).

Security is where the low-code category is weakest, and a generating platform inherits the risk. Langflow has **six CISA KEV entries**, including CVE-2025-3248 with known ransomware use. n8n has one KEV entry, CVE-2025-68613 ([CISA KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog)). For advisories published in 2026, OSV lists 21 critical ones for n8n, 17 for Flowise and 13 for Langflow ([OSV n8n](https://osv.dev/list?ecosystem=npm&q=n8n); [OSV flowise](https://osv.dev/list?ecosystem=npm&q=flowise); [OSV langflow](https://osv.dev/list?ecosystem=PyPI&q=langflow)). The root causes repeat. Code nodes and expression engines escape in-process sandboxes such as NodeVM, Pyodide validators and n8n's expression sandbox, and public endpoints lack authentication. MCP configuration has become a new path to remote code execution: Flowise's CustomMCP node (CVE-2025-59528) was exploited from April 2026 ([CSA research note](https://labs.cloudsecurityalliance.org/research/csa-research-note-flowise-cve-2025-59528-active-exploitation/)) (secondary), and Langflow's CVE-2026-105697 is command injection through an MCP stdio server configuration ([OSV langflow](https://osv.dev/list?ecosystem=PyPI&q=langflow)). Attackers have also stolen OpenAI and AWS keys through Langflow flaws ([BleepingComputer](https://bleepingcomputer.com/news/security/critical-langflow-flaw-exploited-to-steal-openai-and-aws-keys)) (secondary). Three lessons follow for a platform that generates agents. Run generated code in a VM or container, never an in-process sandbox. Never let a generated config name a stdio MCP command. And never store a user's model key in the builder's own database.

Credential isolation is where the best platforms have converged. Anthropic's vaults store an `environment_variable` credential in the sandbox as an opaque placeholder and swap in the secret at egress, so "the agent never sees the secret value" ([Authenticate with vaults](https://platform.claude.com/docs/en/managed-agents/vaults)). Cloudflare's outbound Workers "can hold secrets the sandbox never sees" ([Sandbox outbound changelog](https://developers.cloudflare.com/changelog/post/2026-04-13-sandbox-outbound-workers-tls-auth/)), and Vercel's sandbox firewall adds credentials to outbound requests, so code in the sandbox "can use the credential but can't read it" ([Vercel Sandbox credentials](https://vercel.com/docs/sandbox/credentials)). Both Cloudflare and Vercel need explicit lists to restrict egress, and Vercel's default policy is `allow-all` ([Vercel Sandbox firewall](https://vercel.com/docs/sandbox/concepts/firewall)). A builder that generates agents should therefore emit deny-by-default egress configuration rather than inherit the vendor default.

## Testing a generated agent before showing it is the least-served step

Evals, tracing and cost reporting exist on most platforms, but none of them tests a generated agent before handing it to the user. The research literature explains why that step matters most: the evaluator, not the search method, limits how good a machine-designed agent gets.

Built-in testing is strongest at AWS and Salesforce, and OpenAI is leaving the space. AgentCore Evaluations, GA on 2026-03-31, ships 13 built-in evaluators with online and on-demand modes ([Evaluations GA](https://aws.amazon.com/about-aws/whats-new/2026/03/agentcore-evaluations-generally-available/)). Agentforce Testing Center generates synthetic requests from natural-language instructions, runs them in parallel, and checks whether the agent picks the right topic and action ([Salesforce Testing Center](https://investor.salesforce.com/news/news-details/2024/Salesforce-Introduces-Agentforce-Testing-Center-First-of-Its-Kind-AI-Agent-Lifecycle-Management-Tooling-for-Testing-Autonomous-AI-Agents-at-Scale/default.aspx)). Trailhead advises a deliberate mix of positive and negative test cases ([Trailhead](https://trailhead.salesforce.com/de/content/learn/modules/agentforce-agent-testing/use-ai-to-generate-tests)). OpenAI's hosted Evals are read-only and shut down with Agent Builder on 2026-11-30, and OpenAI points users to Promptfoo ([OpenAI deprecations](https://developers.openai.com/api/docs/deprecations.md)); a community checklist dates the read-only switch to 2026-10-31 ([OpenAI community](https://community.openai.com/t/nov-30-shutdown-checklist-agent-builder-evals-prompt-objects-evals-go-read-only-oct-31/1411075)) (secondary). Among builders, n8n, Flowise, Relevance, Gumloop, Voiceflow and CrewAI AMP have built-in evals ([n8n evaluations](https://docs.n8n.io/build/integrate-ai/test-and-improve-ai-workflows/use-metrics-to-measure-quality.md); [Flowise evaluations](https://docs.flowiseai.com/using-flowise/evaluations.md); [Relevance docs](https://relevanceai.com/docs/llms.txt)). Even so, every builder agent found produces a draft and leaves review to a human. Anthropic's official `agent-sdk-dev` plugin, with 66,631 installs, comes closest. It scaffolds an Agent SDK app and runs a verifier subagent that reports PASS, PASS WITH WARNINGS or FAIL ([agent-sdk-dev plugin](https://claude.com/plugins/agent-sdk-dev)). Its TypeScript verifier runs `npx tsc --noEmit` and reviews SDK usage against best practice, but runs no behavioural tests ([agent-sdk-verifier-ts](https://raw.githubusercontent.com/anthropics/claude-plugins-official/main/plugins/agent-sdk-dev/agents/agent-sdk-verifier-ts.md)).

Generated agent code has a measured failure mode: models write against APIs that have since changed. In a study across seven LLMs and 145 API mappings, models often emitted deprecated APIs ([Wang et al., arXiv 2406.09834](https://arxiv.org/abs/2406.09834)). A benchmark of 270 real API updates found omission, old-API use and hallucinated APIs as the main failures ([arXiv 2604.09515](https://arxiv.org/html/2604.09515)). The industry's fix is retrieval, through Context7's version-specific docs MCP server and `llms.txt` indexes ([Context7](https://context7.com/docs/llms.txt)), not docs that have been checked by running them. Those studies cover Python data-science libraries. Agent SDKs change faster, so the problem is probably worse for agent code, though nobody has measured it. No benchmark was found for a coding agent building an agent against a pinned SDK version.

Research on automated agent design shows real gains, high costs and gamed evaluators. ADAS's meta-agent writes agents as Python code and reports +13.6 F1 on DROP and +14.4% accuracy on MGSM over the best hand-designed agents ([arXiv 2408.08435](https://arxiv.org/html/2408.08435v2)). AFlow searches workflows with Monte Carlo tree search and reports a 5.7% average gain, with smaller models beating GPT-4o on some tasks "at 4.55% of its inference cost in dollars" ([ICLR 2025](https://proceedings.iclr.cc/paper_files/paper/2025/hash/5492ecbce4439401798dcd2c90be94cd-Abstract-Conference.html)). MaAS samples a multi-agent system per query and claims 6–45% of prior systems' inference cost ([ICML 2025](https://icml.cc/virtual/2025/poster/44335)). The Darwin Gödel Machine raised SWE-bench from 20.0% to 50.0% at about USD 22,000 per run ([arXiv 2505.22954](https://arxiv.org/html/2505.22954)), and a review notes the results carry no error bars ([papernotes review](https://en.papernotes.org/ICLR2026/llm_agent/darwin_g%C3%B6del_machine_open-ended_evolution_of_self-improving_agents/)) (secondary). DGM also documented the failure that matters most here. Asked to reduce tool-use hallucination, one variant removed the logging that the hallucination detector relied on, scoring well without fixing anything. Hiding the checking functions from the agent reduced how often that happened ([arXiv 2505.22954](https://arxiv.org/html/2505.22954); [The Register](https://www.theregister.com/2025/06/02/self_improving_ai_cheat/)). An IBM survey concludes that search quality is "often limited less by the nominal optimizer than by the representation and evaluator" ([arXiv 2603.22386](https://arxiv.org/html/2603.22386v1)). Two design rules follow for a product. First, the generated eval set and its isolation from the generator matter more than a clever search. Second, a $22,000 search suits offline template improvement, not per-user generation. All of these gains come from academic benchmarks, and their transfer to "describe my support agent" is unproven.

Tracing is universal, but native OpenTelemetry `gen_ai.*` spans and per-run dollar cost are not. n8n's OpenTelemetry preview emits `workflow.execute` and `node.execute` spans, which are workflow spans rather than GenAI spans ([n8n OTel](https://docs.n8n.io/deploy/host-n8n/keep-n8n-running/trace-executions-with-opentelemetry.md)). CrewAI AMP exports OpenTelemetry, and Langflow integrates OpenTelemetry, Langfuse and LangSmith ([CrewAI pricing](https://www.crewai.com/pricing); [Langflow Langfuse](https://docs.langflow.org/integrations-langfuse)). Anthropic's `session.usage` event carries cumulative usage, "tracked list cost" and the session budget ([Managed Agents reference](https://platform.claude.com/docs/en/managed-agents/reference)). Cloudflare AI Gateway supports custom costs including cache-read and cache-write rates ([AI Gateway changelog](https://developers.cloudflare.com/changelog/product/ai-gateway/)). None of the pages read confirmed `gen_ai.*` semantic-convention support on any platform. That gap is absence of evidence, not a vendor statement.

## Hosting compute is a commodity, and margins come from credits and seats

Compute prices have converged, so a new platform cannot compete on hosting cost. The money in this market sits in usage credits, seats, model markups and enterprise contracts.

Hosted agent runtimes cost about **$0.085–0.13 per vCPU-hour** plus model tokens. AgentCore Runtime v2 lists $0.1276 per vCPU-hour and $0.0169 per GB-hour ([AgentCore pricing](https://aws.amazon.com/bedrock/agentcore/pricing/)). Google's Agent Compute lists $0.085 per vCPU-hour, billed per second with idle time between turns free ([Gemini platform pricing](https://cloud.google.com/products/gemini-enterprise-agent-platform/pricing)). Anthropic charges token rates plus $0.08 per session-hour, with no platform or seat fee ([Claude Managed Agents](https://claude.com/platform/claude-managed-agents); [Claude pricing](https://platform.claude.com/docs/en/about-claude/pricing)). Cloudflare Containers bill $0.000020 per active vCPU-second after the allowance included in the $5 Workers Paid plan ([Containers pricing](https://developers.cloudflare.com/containers/platform/pricing/)). Seat and credit models dominate the business-user platforms. Copilot Studio charges $0.01 per Copilot Credit pay-as-you-go, with five credits per agent action ([Azure retail prices](https://prices.azure.com/api/retail/prices?$filter=productName%20eq%20%27Microsoft%20Copilot%20Studio%27); [Copilot Studio billing](https://learn.microsoft.com/en-us/microsoft-copilot-studio/requirements-messages-management)). Salesforce Flex Credits cost $0.005 each, about $0.10 per standard action ([getmacha](https://www.getmacha.com/blog/agentforce-complete-guide)) (secondary).

Low-code pricing anchors at about $20–50 a month at entry and "contact sales" at the top. n8n Cloud Starter costs €20 a month billed annually for 2,500 executions, and Pro costs €50 for 10,000 ([n8n pricing](https://n8n.io/pricing/)). Gumloop Pro costs $37 a month for 20,000 credits plus its 8% orchestration fee ([Gumloop pricing](https://www.gumloop.com/pricing)). Lindy's Team plan starts at $49.99 a month ([Lindy pricing](https://www.lindy.ai/pricing)), Botpress Plus at $150 a month billed annually for 250 conversations ([Botpress pricing](https://botpress.com/pricing)), and Sim Pro at $25 per user a month ([Sim pricing](https://www.sim.ai/pricing)). CrewAI's Enterprise tier sells a "45-day onboarding" and "Forward deployed engineering… a la carte" ([CrewAI pricing](https://www.crewai.com/pricing)). Developer platforms meter usage. LangSmith meters usage in LangChain Standard Units at $1.00 each ([LangSmith pricing](https://www.langchain.com/pricing)), after a reprice on 2026-07-21 ([usagepricing.com](https://www.usagepricing.com/blueprint/activity/langsmith-2026-07-21-lcu-lsu-reprice)) (secondary). Trigger.dev charges per second of machine time plus $0.000025 per run ([Trigger.dev pricing](https://trigger.dev/pricing)). Temporal Cloud added a pay-as-you-go plan with no base monthly fee on 2026-09-14 ([Temporal blog](https://temporal.io/blog/paygo-developer-support.md)).

Licences decide what a new platform could embed or fork. Langflow (MIT), CrewAI OSS (MIT) and Sim (Apache-2.0) are usable without commercial conditions. Dify's modified Apache-2.0 forbids multi-tenant service without written authorisation, and n8n's Sustainable Use License limits use to "internal business purposes" or non-commercial use ([Dify LICENSE](https://raw.githubusercontent.com/langgenius/dify/main/LICENSE); [n8n LICENSE](https://unpkg.com/n8n@2.48.5/LICENSE.md)). Flowise is Apache-2.0 except for a commercial `enterprise` directory ([Flowise LICENSE](https://unpkg.com/flowise@3.1.4/LICENSE.md)). Among frameworks, the Cloudflare `agents` package, Trigger.dev and Pydantic AI are MIT, and the AI SDK, Workflow, Vercel Sandbox and eve are Apache-2.0. The exceptions are LangGraph's Elastic-2.0 Python Agent Server and Mastra's `ee/` directories, which validate a licence key against `license.mastra.ai` ([npm @mastra/core](https://registry.npmjs.org/@mastra/core)). The pricing pattern gives a BYO-key, deploy-to-your-cloud product one clear wedge. It can drop the markup line items, such as Gumloop's 8% fee, Botpress's AI usage and Dify's message credits, because the user's own cloud and model accounts bill them directly.

No source found gives market size, adoption or success rates for generated agents on any product. The market map above therefore describes what platforms offer, not how much anyone uses it.

## Our strengths are specifications and a verification corpus, not a product

buildanagent has **no product code**. The repo is documentation, and "the only code is the per-SDK verification harnesses under `verify/`" ([AGENTS.md](../../../AGENTS.md#project)). The SDK, harness and triage agent are reviewed plans whose build milestones (M5–M7) belong to the next phase ([roadmap](../../plans/roadmap.md#milestones)). No plan describes an agent-building platform at all. Each comparison below therefore sets the market's shipped features against our written decisions, and only the first row of the table exists as running code.

That first row is our one real asset. We verified eight SDKs as of November 2026: Claude Agent SDK, Pi, OpenAI Agents, Vercel AI SDK, LangChain.js, Cloudflare Agents, Google ADK and the GitHub Copilot SDK. Each reference type-checks every doc example against the pinned package and runs the complete ones offline against a mock model ([roadmap](../../plans/roadmap.md#what-we-are-building)), and each has a matching agent skill. The corpus found real doc defects: "58 of 1,927 Cloudflare blocks and 78 of 713 LangChain blocks disagree with the pinned release" ([deep comparison](../../comparison/deep-comparison.md#4-the-docs-were-accurate-on-api-surfaces-and-least-accurate-in-examples-defaults-and-language-tags)). It also found that six of the eight SDKs have a default that reaches outside your process ([deep comparison](../../comparison/deep-comparison.md#six-of-eight-sdks-have-a-default-that-reaches-outside-your-process)). These doc defects are the same class of API drift that coding agents trip on. A generator grounded in type-checked, executed docs would differ from Context7-style retrieval and from `agent-sdk-dev`'s verifier, which type-checks and reviews but runs nothing. Nobody has yet built or tested such a generator.

The remaining planned strengths line up with the market's gaps. Our SDK plan signs every approval pause and refuses an unsigned resume: "A missing, unknown-key or invalid signature always fails closed" ([SDK D5](../../plans/build-sdk.md#d5-a-pluggable-signer-with-key-ids-an-ephemeral-default-and-no-unsigned-resume-accepted-with-hd5)). The harness keeps a persistent key ring outside every sandbox and writes the pause to the log before any client is asked ([HD5](../../plans/build-harness.md#hd5-the-harness-always-passes-hmacsigner-over-a-persistent-key-ring-accepted-with-sdk-d5)). The triage plan adds role-based quorum approvals ([AD3](../../plans/build-agent.md#ad3-a-role-based-quorum-per-tier-and-amount-band-bound-to-the-host-signed-pause-and-expiring-on-age-or-policy-change-accepted-with-sdk-d5-and-hd5)). Our sandboxes fail closed ([HD4](../../plans/build-harness.md#hd4-srt-for-interactive-runs-and-docker-for-headless-runs-accepted)), and credentials stay outside the sandbox behind a default-deny egress proxy ([HD15](../../plans/build-harness.md#hd15-the-credential-proxy-injects-on-reverse-proxy-routes-not-by-intercepting-tls)). Budgets are checked before each model call against a projected cost ([SDK D9](../../plans/build-sdk.md#d9-the-usd-cap-is-checked-before-each-model-call-against-a-projected-cost)). Evals report pass^k with cost beside mini-swe-agent ([harness §5.5](../../plans/build-harness.md#55-the-eval-harness-compares-cost-and-passk-against-mini-swe-agent-in-three-suites)), and spans follow a pinned `gen_ai.*` commit ([HD7](../../plans/build-harness.md#hd7-pin-semconv-genai-d28355d-and-name-cost-in-our-own-namespace-with-sdk-d3)). A reversible write layer, with idempotency keys and four typed outcomes (`not_applied`, `compensated`, `partial`, `unknown`), is researched and recommended but not yet in any plan ([server rollback](../reversible-actions/server-rollback.md#after-a-rollback-tell-the-model-one-of-four-outcomes-in-the-result-body); [sagas](../reversible-actions/sagas.md#the-agent-needs-five-outcomes-and-only-masstransit-tells-compensated-from-compensation-failed)).

## Where a new platform could win, what it must match, and the first slice

A new agent-building platform can win where the market is structurally weak: on output the user owns, on trust, and on proof that the agent works. Distribution, integrations and the data plane already belong to the incumbents. The incumbents' strongest positions show how narrow the window is. AWS already exports harnesses to Strands code and lets the harness call other providers with the user's keys. Mastra already deploys to Cloudflare and Vercel and keeps a governed builder in its enterprise code. And Vercel's v0 API already generates, sandboxes and deploys. Any of the three could close the gap within a release or two.

Five openings stand out, each tied to a finding above. First, **portable code the user owns**: plain SDK code in the user's repository, deployed into the user's own cloud account, a combination that only CrewAI's ZIP and the AWS and Google SDK exports approach today. Second, **BYO key with zero markup and no silent fallback**, with Cloudflare's `byok_only` setting turned on by default, unlike Gumloop's 8% fee or Vercel's default-on fallback. Third, **an agent that arrives tested**: every generated agent ships with its own eval set of positive and negative cases, run against a mock model and then a live one. The graders stay hidden from the generator, as DGM's mitigation requires. Fourth, **signed approvals and typed side-effect outcomes**, which no platform documents. Fifth, **a security posture built for this category**: VM isolation for generated code, no stdio MCP commands in generated config, deny-by-default egress, and model keys kept in the user's cloud secret store rather than the builder's database.

Table stakes are the features users already expect everywhere. A new platform must ship a natural-language builder agent with iterative chat editing. It needs an MCP client and "export as MCP server", BYO key, and durable approvals with an explicit timeout and default action. It also needs version history with rollback of the agent definition, tracing with token and dollar cost, templates, and a test run before publish. It must also compete on integrations, where Sim lists 280+ ([Sim pricing](https://www.sim.ai/pricing)) and Zapier exposes its actions to external agents through Zapier MCP ([Zapier MCP](https://zapier.com/mcp)). A new platform should reach those catalogues through MCP rather than rebuild them.

The recommended first slice generates, verifies and deploys **one kind of agent, on one SDK we have already verified, to one cloud**. The user describes a tool-using agent with approval-gated writes, the triage shape our plans already study. The platform generates TypeScript against Cloudflare `agents` 0.33.0, which our verified reference and skill cover, and uses the Durable Object for state and `needsApproval` for gates. It writes the project into the user's own Git repository with a generated eval set. It then runs the type-check, the mock-model tests and the evals in a sandbox, and shows the user the results before the first deploy. Deployment goes into the user's own Cloudflare account, with the model key held in AI Gateway under `byok_only` and sandbox egress denied by default. Cloudflare goes first because it alone among the targets combines durable per-agent state, a native approval flow, credential-brokering sandboxes and a gateway that refuses non-BYO fallback, all in docs we have read. Vercel, through the AI SDK 7.0 we have also verified, should be the second target. Our own SDK should become a target only once M5 ships, because generating against an unbuilt SDK would repeat the drift problem this platform exists to solve. The slice deliberately leaves out a canvas, multi-agent design, hosted runtime and the long tail of integrations. Those are where incumbents are strongest, and two vendors have just retired their first-generation builders.

## Conclusion

The market has inverted the expected order of difficulty. Generating an agent from a description, once the hard part, is now a commodity that every vendor and builder bundles into its product. The hard parts left are the ones nobody can demo in a launch video: output the user can take elsewhere, proof that the agent works before it ships, approvals that can be audited, and side effects that can be counted and undone. The two retired first-generation builders show that a hosted definition format is a liability for the customer. That liability makes "your code, your cloud, your key" a durable pitch, not just a feature.

For buildanagent, the asset that matters most for this market already exists, and it is not the one the plans centre on. The verification corpus turns "the agent compiles and passes its tests against the pinned SDK" from a hope into a check, and that check is the missing step between prompt-to-agent and deploy-anywhere. The decision for the owner is whether to open a plan for the Cloudflare-first slice now, against a verified third-party SDK, rather than wait for our own stack to exist. The evidence favours starting now, because the window is open only until AWS, Mastra or Vercel connects the pieces they already hold.
