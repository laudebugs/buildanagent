# Fact-check log: voice and realtime agents report

The voice and realtime report holds up, and its thesis stands: a voice agent runs the same tool loop as a text agent inside a live session paced by a listener, so it must predict when the person has finished, forget what the person never heard and keep its tools from silencing it. Of the 151 rows below, 103 are confirmed (✅), 41 needed a correction (✏️) and 7 rest on inference or absence (⚠️). Twelve of the confirmed rows carry a ⚠️ note on one part, because that part was read in compiled JavaScript, is an absence claim or is our inference (rows 26, 42, 58, 78, 86, 87, 88, 89, 94, 96, 98 and 107). Each section was checked as soon as it was drafted, before the next was written, and the rows come in nine blocks, one per section, plus the re-checks of the writing review's fixes (rows 117–123), of the first code review's labelling fixes (rows 124–133), of the second review's URL fixes (rows 134–141) and of the owner's decisions (rows 142–151).

None of the corrections changes a finding. Eight fixed a number's meaning or scope against its source: τ-Voice's latency and its text baseline (rows 4 and 5), the robot study's 2.6 s peak (row 24), FDB v1.5's pairing of systems and scenarios (row 45), τ-Voice's responsiveness and selectivity (row 47), FDB-v3's filler definition (row 56), the date of a 2026 study (row 65) and the text-to-audio price ratio (row 79). Seven narrowed wording the source does not support: "only when" for `response.create` (row 9), "most systems" for pseudo-full-duplex (row 15), "each SDK" for predictive detectors (row 25), an "untuned" cascade (row 33), "counts" for a cited overlap figure (row 102), a turn the client "never" asks for (row 117) and echo control "built in" to WebRTC (row 121). Five fixed a citation, a source's name or our own description of code (rows 31, 43, 70, 85 and 90). Ten came from the pull request's first code review, which found that the report stated some of our own inferences, judgements and untested proposals as plain fact; each now reads as ours or as untested (rows 124–133). Eight more came from its second review, which found cited URLs that redirect; rows 134–141 replace each with its final address. The last three followed the owner's decisions: two fixed wording in this report's conclusion and in the SDK plan's audio non-goal (rows 144 and 148), and one restored a search label on an absence claim in the TypeScript gap report (row 151).

The ⚠️ rows fall into two groups. Three are absence claims or untested behaviour: no peer-reviewed per-stage latency budget (row 30), a proposed example whose checks have not run (row 112) and no planned agent that speaks (row 114); the report now marks each as untested or as a search result (rows 30, 132 and 133). Four are our own inference or design, and the report labels each as ours (see rows 124, 125 and 128 for the labels added after the code review): the read-back rule for spoken arguments (row 66), the consequence of Cloudflare's text-only history (row 93), the scope judgement and teaching points (row 100) and the new break-note wording (row 104).

## Link check

Every relative link and anchor in the report, this log and the notes resolves. The repository's link checker extracts each Markdown link target that is not `http(s):` or `mailto:`, resolves it against the file's folder and matches each `#anchor` against GitHub-style slugs of the target's headings; it reported no problems on 2026-11-19. All 45 distinct external URLs in the report return HTTP 200 without a redirect. The first check, on 2026-11-19, followed redirects and so missed that eight of them redirected; the pull request's second review found them, and rows 134–141 record the final URLs, each re-fetched and re-checked for its quoted text. One source failed during research and is handled in the rows: PNAS returned HTTP 403 for Stivers et al., so the report cites the PubMed Central copy (row 3).
