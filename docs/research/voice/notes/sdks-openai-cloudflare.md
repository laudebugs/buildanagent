"Voice agent" here means an agent that takes audio in and produces audio out within one conversation. "Realtime" means a long-lived, bidirectional session (WebRTC, WebSocket or SIP) instead of one request per turn. The two SDKs pick opposite architectures. OpenAI wraps a speech-to-speech model. Cloudflare chains speech-to-text, your own LLM code and text-to-speech.

## 1. OpenAI Agents SDK (`@openai/agents-realtime` 0.21.0, `@openai/agents-extensions` 0.21.0)

### Takeaway

The voice loop is a `RealtimeSession` around a `RealtimeAgent`, not `run()`. The session holds a long-lived connection to OpenAI's speech-to-speech Realtime API and handles multiple turns itself. It produces no `RunResult`: you get a stream of events (`history_updated`, `audio`, `audio_interrupted`, `tool_approval_requested`, `guardrail_tripped`, `agent_handoff` and more) and a mutable `session.history`. Transports are pluggable through the `RealtimeTransportLayer` interface. The package ships `OpenAIRealtimeWebRTC` (the browser default, which handles mic and playback), `OpenAIRealtimeWebSocket` (the server default, where you handle audio) and `OpenAIRealtimeSIP`; extensions add Twilio and Cloudflare Workers transports, both marked beta.

Turn detection is the API's own VAD. The default is `semantic_vad`, and `server_vad`, eagerness, silence and padding settings, `createResponse`/`interruptResponse`, or `null` for manual commits are all surfaced. Interruption is automatic under VAD; `session.interrupt()` gives you a stop button. On WebSocket the SDK truncates the assistant audio to what was heard and emits `audio_interrupted`, but stopping local playback is your job. WebRTC clears buffered audio for you.

Tools use the same `tool()` helper, with `needsApproval` surfaced as an event plus `approve()`/`reject()`. Handoffs swap the agent's config in place on the same session; the model cannot change, and input filters are not applied. To use a different model (for example a text reasoning model), you delegate through a tool that calls `run()` on a text `Agent` (the "backend agent" pattern). Output guardrails run on transcript text every `debounceTextLength` characters (100 by default).

Lock-in: the session is model-agnostic only in principle. The transport interface lets you plug in "a different speech-to-speech API", but the only shipped transports speak the OpenAI Realtime protocol (Azure OpenAI works with the GA protocol). There is no chained STT→LLM→TTS `VoicePipeline` in TypeScript; that exists only in Python.

Offline testing is first-class: `@openai/agents/realtime/testing` ships `ScriptedRealtimeTransport`, an in-memory transport with `runScenario()`/`expectCall()`/`emit()`. Our harness currently skips anything that imports realtime.

## 2. Cloudflare Agents (`agents` 0.33.0, `agents/voice` and sub-exports)

### Takeaway

Cloudflare's voice agent is a chained pipeline inside a Durable Object, not a speech-to-speech model. `withVoice(Agent)` is a mixin. You set a `transcriber` (continuous STT) and a `tts` provider as class fields, then implement `onTurn(transcript, context)`, which returns text or a text stream from whatever LLM code you write (usually AI SDK `streamText`). The mixin sentence-chunks the stream and synthesizes each sentence as it completes, so TTS overlaps generation. Browser audio arrives as 16 kHz PCM binary frames over the Agent's ordinary WebSocket; no SFU is needed. `withVoiceInput(Agent)` is the STT-only variant for dictation.

Compared with the text loop (`AIChatAgent.onChatMessage` or Think), there is no runner or tool loop of its own. `onTurn` is the turn boundary, and you run the model and tools inside it. The mixin persists plain `{ role, content }` text messages to SQLite.

Turn detection is model-driven. The STT model decides end of turn: Workers AI Flux has an end-of-turn threshold and an optional eager end-of-turn, and Nova 3 uses endpointing. Interim transcripts stream to the client. Interruption (barge-in) has two paths. The client's RMS detector sends `interrupt`, or the transcriber's `onSpeechStart` triggers a server-side barge-in. Either way the server aborts `context.signal`, clears queued audio and tells the client `playback_interrupt`.

Tools are whatever `streamText` gets in `onTurn`. The voice layer has no tool, approval or handoff API of its own. Providers are pluggable through two tiny interfaces (`Transcriber`, `TTSProvider`). Workers AI Deepgram models (Flux, Nova 3, Aura) are built in, and AssemblyAI, Deepgram, ElevenLabs, Telnyx, Twilio and Plivo arrive as separate `@cloudflare/voice-*` packages, so lock-in is low. The `./voice/sfu` export holds Realtime SFU helpers that the mirrored docs do not document.

Status: the repo doc says "Experimental... will break between releases", and the developers.cloudflare.com pages show a beta badge. Offline testing has no shipped fake, but the interfaces are small enough that a fake transcriber and TTS would let our workerd harness drive a full call offline.

## Synthesis (mine)

The two SDKs answer "what is a voice agent" differently, and that choice decides everything else. OpenAI hands the turn to a speech-to-speech model behind one live connection. Turn detection, interruption and transcription happen in the API, and the SDK's job is to mirror state (history, the active agent, approvals) and run tools locally. That gives the lowest-latency path and real truncation-to-heard-audio. The costs: the loop becomes an event emitter with no result object, handoffs cannot change the model, structured output and input guardrails are gone, and the only shipped backend is OpenAI's protocol. The "backend agent" tool is the bridge back to the text world, and the docs name it as the way to use a reasoning model.

Cloudflare keeps the text loop and wraps it. STT ends the turn, `onTurn` is an ordinary AI SDK call with ordinary tools, and TTS starts on the first sentence. That makes every stage swappable and measurable (`VoiceTurnMetrics` is the richest latency instrumentation in either SDK). But barge-in is RMS- or STT-event-driven rather than model-aware, history is text-only, and nothing voice-specific exists for approvals or handoffs. Both are pre-1.0, and Cloudflare labels its API experimental.

For our harnesses, OpenAI is the easier one to test offline, because its scripted transport is official and documented. Our runner simply refuses to run it yet. Cloudflare needs about 20 lines of fakes, and its harness already supports the WebSocket plumbing.
