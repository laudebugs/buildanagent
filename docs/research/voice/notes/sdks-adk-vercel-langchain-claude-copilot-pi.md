## Google ADK (`@google/adk` 2.5.0, `@google/genai` 2.32.0)

### Takeaway
ADK TypeScript has a real bidirectional live loop, and it is further along than its docs say:
- **What ships.** `Runner.runLive()` takes a `LiveRequestQueue` and yields the same `Event` type as `runAsync`. The live keys on `RunConfig` (`responseModalities`, `speechConfig`, input and output transcription, `realtimeInputConfig`, `contextWindowCompression`, `proactivity`, `enableAffectiveDialog`) are copied into the Gemini Live `liveConnectConfig`. The live flow also covers session resumption with transparent reconnects (up to 5), the `interrupted` flag, and streaming tools written as async generators, with `stop_streaming` to cancel them. All of it is marked **experimental**.
- **Same agent, different loop.** The same `LlmAgent`, tools, callbacks and session service work in live mode. The loop is not the same: `LlmAgent` has a separate `runLiveFlow` with a send loop running in parallel to the receive loop. Tool calls go through `handleFunctionCallsLive`, not `handleFunctionCalls`.
- **Python-only parts.** Every page under `adk-docs/docs/live/` is tagged Python (and some Java), never TypeScript. `CascadeLive` (STT, then a text LLM, then TTS), `LiveKitRunner`, and the `response_scheduling`/`behavior` options for non-blocking tools exist only in Python. None of them appears in the 2.5.0 typings.
- **Gaps in the TypeScript loop.** The live flow never handles `toolCallCancellation`. `ParallelAgent`, `LangGraphAgent` and `A2ARemoteAgent` throw in live mode.
- **The vendor layer.** `@google/genai` `ai.live.connect()` exposes the raw protocol, also marked `@experimental`. It types barge-in (`ActivityHandling.START_OF_ACTIVITY_INTERRUPTS`, the default), `interrupted`, `toolCall` and `toolCallCancellation`, `goAway`, session resumption, and `Behavior.NON_BLOCKING` with `FunctionResponseScheduling` (`SILENT`, `WHEN_IDLE`, `INTERRUPT`).
- **Offline testing.** It is feasible, but nothing in the package does it. `BaseLlm.connect()` and the `BaseLlmConnection` interface are the seam. Our harness's scripted model currently throws from `connect()`.

### Cited findings
- **`runLive` declaration.** `runLive(params: { userId; sessionId; liveRequestQueue: LiveRequestQueue; runConfig?; abortSignal?; liveSessionResumptionHandle?: string }): AsyncGenerator<Event, void, undefined>`. The doc comment says "Runs the agent in the live (bidirectional streaming) mode" and "This feature is **experimental** and its API may change". It also says raw inline audio, video and image events "are yielded but not appended to the session", while "transcriptions, tool calls, usage" are persisted — [d.ts] `verify/google-adk/node_modules/@google/adk/dist/types/runner/runner.d.ts:244–272`.
- **`LiveRequestQueue`.** It carries `LiveRequest { content?; blob?; activityStart?; activityEnd?; close? }` (line 10). Its methods are `send`, `get(abortSignal?)`, `close()`, `sendContent(content)`, `sendRealtime(blob)` ("Sends a blob to the model in realtime mode"), `sendActivityStart()`, `sendActivityEnd()` and `[Symbol.asyncIterator]` — [d.ts] `.../@google/adk/dist/types/agents/live_request_queue.d.ts:10–72`. It is exported from the package root (`common.d.ts:17–18`).
- **`StreamingMode.BIDI` is a dead value.** The doc comment reads "Reserved. Bidirectional streaming is reached through `Runner.runLive()`, not through this value: `runLive` itself calls `createRunConfig`, which rejects `BIDI`" — [d.ts] `.../agents/run_config.d.ts:19–24`. The adk-js changelog for 2.0.0 records the earlier bug: "StreamingMode.BIDI is accepted but has no effect — silently degrades to NONE" — [docs] `docs/reference/google-adk/source/adk-js/core/CHANGELOG.md:325`.
- **Live fields on `RunConfig`.** `speechConfig?: SpeechConfig` (33), `responseModalities?: Modality[]` ("If not set, it's default to AUDIO", 35–37), `outputAudioTranscription` (62), `inputAudioTranscription` (66), `enableAffectiveDialog` (71), `proactivity` (76), `realtimeInputConfig` (80) and `contextWindowCompression` (85). All of these types are imported from `@google/genai` (line 6) — [d.ts] `.../agents/run_config.d.ts`. `supportCfc` (50) is "experimental" and switches to the Live API. `RunConfig` has no `sessionResumption` field, because resumption goes through `runLive`'s `liveSessionResumptionHandle`.
- **How those fields reach Gemini.** `const LIVE_KEYS = ["responseModalities","speechConfig","outputAudioTranscription","inputAudioTranscription","realtimeInputConfig","contextWindowCompression","proactivity","enableAffectiveDialog"]`, and `applyLiveRunConfig` copies each one into `llmRequest.liveConnectConfig` — [js] `.../@google/adk/dist/esm/agents/llm_agent.js:113–135`. `Gemini.connect` then calls `this.liveApiClient.live.connect({ model, config: llmRequest.liveConnectConfig, ... })` and strips `transparent` from resumption on the Gemini API backend — [js] `.../dist/esm/models/google_llm.js:210–221`.
- **The live flow, in its own words.** "Establishes a live connection to the model, drains the invocation's `liveRequestQueue` into the connection on a parallel task, and yields events derived from server messages until the queue closes, the model finishes, or an agent transfer occurs. If the live connection drops (network failure, server `goAway`) and a session resumption handle has been observed, the flow transparently reconnects using that handle up to {@link MAX_LIVE_RECONNECT_ATTEMPTS} times" — [d.ts] `.../agents/llm_agent.d.ts:415–430`. The limit is `const MAX_LIVE_RECONNECT_ATTEMPTS = 5;` — [js] `.../esm/agents/llm_agent.js:77`. On reconnect the flow sets `sessionResumption = { handle, transparent: true }` (`llm_agent.js:573–580`).
- **Model seam.** `abstract connect(llmRequest: LlmRequest): Promise<BaseLlmConnection>` — [d.ts] `.../models/base_llm.d.ts:57`. `BaseLlmConnection` declares `sendHistory`, `sendContent`, `sendRealtime(blob)` ("The model may not respond immediately ... It will do voice activity detection and decide when to respond"), optional `sendActivityStart`/`sendActivityEnd`, `receive(): AsyncGenerator<LlmResponse>` and `close()` — [d.ts] `.../models/base_llm_connection.d.ts:11–60`. It is exported as a type (`common.d.ts:106`).
- **Interruption.** `LlmResponse.interrupted?: boolean`, with the comment "Flag indicating that LLM was interrupted when generating the content. Usually it's due to user interruption during a bidi streaming", plus `liveSessionResumptionUpdate?` — [d.ts] `.../models/llm_response.d.ts:43–46, 66`. `LiveResponseAggregator` translates `serverContent.interrupted`, `turnComplete`, `toolCall`, `sessionResumptionUpdate` and `goAway` into `LlmResponse`s — [js] `.../esm/utils/live_connection_utils.js:37, 120, 167–183, 188–218`. Barge-in itself is server-side VAD. ADK only forwards the flag, and the client must flush its playback buffer. The Python docs show that client code in JavaScript: `if (adkEvent.interrupted) { stopAudioPlayback(); // user barged in; drop queued audio` — [docs] `docs/reference/google-adk/source/adk-docs/docs/live/custom-server.md:203–210`.
- **Tool calls in live mode.** `handleFunctionCallsLive` "Supports regular sync/async tools, async-generator streaming tools that push incremental results onto `invocationContext.liveRequestQueue`, and the `stop_streaming` control call that cancels an active streaming tool task" — [d.ts] `.../agents/functions.d.ts:70–76`.
  - **Streaming tools.** A `FunctionTool` whose `execute` is an async generator counts as a streaming tool (`isStreamingTool`, [js] `.../esm/agents/functions.js:531–537`). Each yielded value is fed back with `liveRequestQueue.sendContent(createUserContent(\`Function ${tool.name} returned: ...\`))`. The immediate function response is `{ status: "The function is running asynchronously and the results are pending." }` — [js] `functions.js:612–665`. `ActiveStreamingTool { task?; stream?: LiveRequestQueue }` — [d.ts] `.../agents/active_streaming_tool.d.ts:18–27`.
  - **Docs caveat.** "`runLive` does not populate `InvocationContext.activeStreamingTools`, so a streaming tool that expects its own `LiveRequestQueue` is not tracked" — [docs] `docs/reference/google-adk/source/adk-js/docs/guides/runners/index.md:337–338`. The code does register output-streaming tasks (`functions.js:657–661`), so the caveat applies to input-stream tools.

## Vercel AI SDK (`ai` 7.0.162, `@ai-sdk/openai` 4.0.108, `@ai-sdk/anthropic` 4.0.96, `@ai-sdk/provider` 4.0.35)

### Takeaway
At the pin the AI SDK has three voice layers, each at a different maturity:
- **Stable batch calls.** `transcribe()` and `generateSpeech()` graduated in v7. The `experimental_transcribe` and `experimental_generateSpeech` aliases are `@deprecated`. They are one-shot calls, not a loop.
- **Experimental streaming.** `experimental_streamTranscribe`, `experimental_streamSpeech` and `experimental_streamTranslate` stream in and out. `streamSpeech` accepts `streamText`'s `textStream` as `text`. That makes a sandwich (STT, then `streamText`/`ToolLoopAgent`, then TTS) easy to build by hand, but the SDK ships no pipeline object.
- **Experimental realtime.** `RealtimeModelV4` in `@ai-sdk/provider`, `Experimental_AbstractRealtimeSession` in `ai`, `openai.experimental_realtime(...)` (`gpt-realtime` turn-based, `gpt-live-1` continuous) and `experimental_useRealtime` in `@ai-sdk/react`, which is not installed in `verify/`. It is a **browser-side, separate loop**. It does not run through `generateText`, and its tools run client-side through `onToolCall`. In turn-based mode, barge-in stops local playback and truncates the assistant item to the audio actually played.
- **Providers in our pins.** `@ai-sdk/openai` implements transcription, speech, speech translation and realtime. The pattern returns no hit in `@ai-sdk/anthropic` 4.0.96 apart from unrelated "transcript" doc text. The shipped docs name Google, xAI and AI Gateway realtime models, but those packages are not installed.
- **Offline testing.** `ai/test` has `MockTranscriptionModelV4`, `MockSpeechModelV4`, `Experimental_MockStreamingSpeechModelV4` and `Experimental_MockSpeechTranslationModelV4`. There is **no mock realtime model**.

## Synthesis (mine)

My reading of the evidence above:
- **Only two of these six SDKs ship a bidirectional audio loop in TypeScript, and they put it in different places.** ADK's `runLive` is a server-side agent loop. It reuses `LlmAgent`, tools, callbacks and sessions, but runs a separate flow with parallel send and receive tasks, live-specific tool dispatch and reconnects. The AI SDK's realtime is a browser-side session that sits beside `generateText`/`ToolLoopAgent` and does not use them: tools are application callbacks (`onToolCall`), and the provider's VAD drives the turns. Both are experimental at the pin.
- **Interruption is mostly a client duty in both.** ADK forwards `interrupted` and leaves flushing playback to you. The TypeScript port lacks Python's `CascadeLive` logic that truncates history to the words the user heard. The AI SDK's turn-based session does the right thing itself: it stops playback and sends `conversation-item-truncate` with the played offset. Neither ADK nor the AI SDK handles Gemini's `toolCallCancellation`. ADK ignores it, and the AI SDK's normalized event union has no cancellation event.
- **Voice tool calls differ from text tool calls in two ways the SDKs expose unevenly.** One is latency: slow tools need to be non-blocking or streaming. The other is cancellation. `@google/genai` types `NON_BLOCKING` with `SILENT`/`WHEN_IDLE`/`INTERRUPT` scheduling, but ADK TypeScript gives no tool option for it. Only Python ADK documents it. ADK TypeScript does support async-generator streaming tools.
- **The sandwich (STT, then the text agent, then TTS) is the only voice option in LangChain.js, Claude, Copilot and Pi, and the best-tooled one in the AI SDK.** `streamSpeech(text: textStream)` is the cleanest TypeScript sandwich primitive I found, and it is the only one with offline mocks. In the other four, the text agent's existing abort or interrupt API is the barge-in hook, and the audio transports are user code.
- **The docs undersell ADK TypeScript and say nothing about voice for the others.** All 14 live pages carry Python or Java tags, while 2.5.0 ships most of the core live loop. For the AI SDK, the npm package's own `docs/` is the authoritative pinned source, and our mirror lacks those pages.
