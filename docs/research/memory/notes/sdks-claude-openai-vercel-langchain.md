# Retrieval and long-term memory in four SDKs (as of November 2026)

Research notes, gathered 2026-11-19 from the installed typings in this worktree, the mirrored upstream docs under `docs/reference/<sdk>/source/`, and official docs pages fetched that day (saved under the session scratchpad `u18-d/`). Versions are those pinned in `verify/<sdk>/package.json`, as of November 2026.

**Markers.** **[d.ts]** = checked in the installed typings. **[docs]** = the SDK's own docs (URL or mirrored path). **[guide]** = our `docs/reference/<sdk>/guide.md`. **[secondary]** = anything else. Nothing was executed; all claims come from reading files.

**Path convention.** Typings paths are given relative to the worktree through each harness's `node_modules` symlink (for example `verify/langchain/node_modules/@langchain/core/dist/stores.d.ts`). With pnpm, each symlink resolves to `node_modules/.pnpm/<name>@<version>_<peer-hash>/node_modules/<name>/`. Packages that a harness does not list directly (for example `@langchain/langgraph-checkpoint`) are given by that `.pnpm` path.

"Retrieval" here means search tools, embeddings, vector stores, file search and RAG helpers. "Long-term memory" means memory that outlives one task or session: stores, memory tools, memory files and cross-thread stores, plus TTL, delete and forget support.

## 1. Claude Agent SDK (`@anthropic-ai/claude-agent-sdk` 0.3.327)

### Takeaway

Retrieval uses tools only: the bundled CLI's `Grep`, `Glob`, `Read`, `WebSearch` and `WebFetch`, plus whatever you add over MCP. The SDK has no embeddings, vector store or RAG API. Long-term memory is file-based and inherited from Claude Code. `CLAUDE.md` and rules files load when `settingSources` includes `'project'`, `'user'` or `'local'`. Auto memory (`MEMORY.md` plus topic files under `~/.claude/projects/<project>/memory/`) loads regardless of `settingSources`, and the agent writes it with the ordinary `Write` and `Edit` tools. Subagents can get their own memory directory through `AgentDefinition.memory`. `SessionStore` persists transcripts, not distilled memory. Forgetting is manual: you delete files, or call `deleteSession()`, and no TTL applies to memory files. The Anthropic API memory tool (`memory_20250818`) is not exposed: the SDK accepts no raw API tool definitions.

## 2. OpenAI Agents SDK (`@openai/agents` 0.21.0, with `agents-core`, `agents-openai` and `agents-extensions` 0.21.0)

### Takeaway

Retrieval is hosted. `fileSearchTool(vectorStoreIds)` queries OpenAI-hosted vector stores, and `webSearchTool()` runs OpenAI web search. Both are `HostedTool`s that work only with the Responses API. The SDK ships no embeddings API, local vector store or retriever; locally you bring your own function tool. Long-term memory comes in two layers. `Session` holds conversation history across runs; implementations are `MemorySession`, `OpenAIConversationsSession`, the `OpenAIResponsesCompactionSession` decorator, and your own over SQLite, Redis and the like. Separately, the sandbox-agent `memory()` capability distills lessons from past runs into `memories/MEMORY.md` and `memory_summary.md`, with a pluggable `MemoryStore` (`read/write/delete?/list?`). Forgetting means `clearSession()` and `popItem()` on sessions, plus recency-based pruning of raw memories in sandbox memory (`maxRawMemoriesForConsolidation`). No TTL exists.

## 3. Vercel AI SDK (`ai` 7.0.162, `@ai-sdk/harness` 1.0.173, `@ai-sdk/provider` 4.0.35, `@ai-sdk/provider-utils` 5.0.74, `@ai-sdk/anthropic` 4.0.96, `@ai-sdk/openai` 4.0.108)

### Takeaway

The AI SDK offers the most retrieval primitives of the four: `embed`, `embedMany`, `cosineSimilarity`, `rerank` and embedding middleware, with offline `MockEmbeddingModelV4` and `MockRerankingModelV4` in `ai/test`. It ships no vector store: the RAG guide stores vectors in Postgres with pgvector through Drizzle. Hosted retrieval comes from provider tools: `openai.tools.fileSearch` (vector stores), and web search and fetch tools for both providers. Long-term memory is not built in. The docs list three paths: the Anthropic provider-defined `anthropic.tools.memory_20250818`, where you supply `execute` and the storage; third-party memory providers (Letta, Mem0, Supermemory, Hindsight); or a custom tool. Forget and TTL are whatever your `execute` or backend does; the memory tool's command set includes `delete`. `@ai-sdk/harness` adds no memory API.

## 4. LangChain (`langchain` 1.6.1, `@langchain/langgraph` 1.6.0, `@langchain/core` 1.3.4; store from `@langchain/langgraph-checkpoint` 1.2.3)

### Takeaway

LangChain is the only one of the four with a first-class, cross-thread long-term memory store in-process. LangGraph's `BaseStore` offers `get`, `put`, `search` (filter, plus semantic `query` when the store is built with `index: { dims, embeddings, fields? }`), `delete` and `listNamespaces` over hierarchical namespaces. `InMemoryStore` implements it, with cosine-similarity vector search built in. You pass it to `createAgent({ store })`, and tools reach it as `runtime.store`. The local store has no TTL: the JS `BaseStore` has no TTL parameter. TTL exists only in the remote Agent Server client (`@langchain/langgraph-sdk` `StoreClient.putItem(..., { ttl })`). For retrieval, `@langchain/core` has the abstract `Embeddings`, `VectorStore` (`similaritySearch`, `asRetriever`) and `BaseRetriever`, plus offline fakes (`SyntheticEmbeddings`, `FakeEmbeddings`, `FakeVectorStore`, `FakeRetriever`). The concrete `MemoryVectorStore` is in `@langchain/classic`, which is not installed. Two naming and typing traps: `import { InMemoryStore } from "langchain"` is core's key-value store, not LangGraph's; and the docs' `index: { embed, dims }` and `put(..., { index: [...] })` forms disagree with the installed typings.

## Gaps

- **Claude SDK has no typed control over auto-memory content.** The SDK cannot list, write or delete memories through an API: memory is files, the agent edits them with `Write` and `Edit`, and `SDKMemoryRecallMessage` only reports recalls. Whether `autoDreamEnabled` and the "memory recall supervisor" (`mode: 'synthesize'`, which mentions a Sonnet-authored paragraph) run in SDK sessions, and whether they make extra model calls, is not documented on the SDK pages we read. Verify with the mock and `MOCK_LOG`.
- **Claude SDK and the API memory tool.** Nothing documents a way to pass `memory_20250818` through `query()`. An MCP tool that mimics it is our inference, not tested.
- **Claude docs mirror missing.** `docs/reference/claude-agent-sdk/source/` is absent in this worktree, so the official pages were fetched live on 2026-11-19 and are not pinned to 0.3.327. The memory page cites a Claude Code version (v2.1.234) for one feature, which does not map cleanly to the SDK version.
- **OpenAI sandbox memory is unverified.** Our guide and harness have no behavioral test of `memory()`, `MemoryStore` or phase-1/phase-2 generation. How a non-sandbox `Agent` gets distilled memory is undocumented: the capability belongs to `SandboxAgent`.
- **OpenAI durable sessions.** No SQLite or Redis `Session` ships in the installed JS packages. The docs point to `examples/memory/` samples, which are not in our mirror (the manifest excludes non-docs example apps).
- **Vercel docs coverage.** Our mirror lacks the embeddings, reranking and RAG pages; they were fetched at tag `ai@7.0.162` but not mirrored. Whether a `MockLanguageModelV4` tool call named after a provider-defined tool (`memory_20250818`) routes to the user `execute` is unverified. The JSDoc's supported-model list for the memory tool looks stale.
- **No TTL anywhere in-process.** None of the four SDKs offers TTL on local long-term memory. LangGraph's TTL exists only on the remote Agent Server client. Python LangGraph has store TTL, but it is not part of this comparison [secondary, unverified here].
- **LangChain doc drift.** Three disagreements with the installed typings: `index: { embed, dims }` against `IndexConfig.embeddings`; `put(..., { index: [...] })` against the positional `false | string[]`; and `import { InMemoryStore } from "langchain"`, which yields core's key-value store. The docs repo has no tag for the pinned versions (`docs/reference/langchain/source/_manifest.json` note), so some drift may come from docs running ahead of the release. Check against newer `@langchain/langgraph-checkpoint` before reporting upstream.
- **LangChain vector store packaging.** The only concrete in-memory vector store on hand is the test-only `FakeVectorStore`. `MemoryVectorStore` requires `@langchain/classic`, which is not pinned here, and adding it would change the harness (out of scope for these notes).
- **Hosted retrieval cannot run offline** (OpenAI file search and web search, Anthropic web search and fetch). Any example of these needs a real API key and is out of scope for the offline harnesses.
