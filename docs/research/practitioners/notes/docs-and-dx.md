# Documentation and developer experience: what practitioners say about building with agents (HN, 2025-05-18 to 2026-11-18)

*Round H theme note 4 of 6 ([plan §4b](../../../plans/build-guides.md)). Source: the 400-thread corpus in [corpus.md](../corpus.md), 111,532 comments. Quotes are short attributed excerpts; counts are distinct HN usernames, estimated by reading keyword hits, and are approximate. Product and model names are quoted as commenters wrote them and are not checked here.*

## Summary

On Hacker News, "developer experience" for agents mostly means two things: getting current documentation in front of the model, and seeing and controlling what the harness does. The most widely shared documentation view is that models write against stale APIs from their training data, and that the fix is to feed them current docs (llms.txt, Context7, a docs MCP server, a docs index in AGENTS.md, or vendored source); about 30 authors in 25 threads say so, and about 10 doubt it helps much. The loudest complaints are about vendors rather than docs pages: Claude Code changing defaults, prompts and visible output without notice, the docs lagging the changelog, and answers arriving as HN or X replies instead of documentation. About 60 authors across seven Claude Code threads object to silent changes. About 45 authors ask to see what the agent is doing (files read, reasoning, subagents, context and quota), and they treat hiding that output as a regression. For debugging, practitioners use the harness's local JSONL transcripts, generic OpenTelemetry and home-made proxies; in 111,532 comments, nobody names a dedicated LLM-tracing product such as LangSmith or Langfuse. Over the 18 months, talk of hallucinated APIs and docs lookup fell, and talk of transcripts, hidden reasoning and churn rose. The main conclusion is that practitioners judge agent DX by transparency and stability more than by docs: they want a tool that shows its work, keeps its behaviour fixed until they opt into a change, documents every default, and lets the agent read accurate docs.

## Models write against stale APIs, and feeding them current docs is the common fix

Support: about 18 authors across 15 threads describe agents hallucinating or using outdated APIs, flags and patterns, and about 30 authors across 25 threads recommend giving the agent current documentation. The complaint is concrete: invented methods, deprecated libraries and old idioms. One commenter got an agent "stuck in a loop on a hallucinated API" and burned credits before noticing ([HN](https://news.ycombinator.com/item?id=47110921)). The Chrome team's [modern-web guidance](https://news.ycombinator.com/item?id=50443812) launch in November 2026 took the problem as its premise, and a commenter agreed that agents "default to older patterns because LLM training data contains vast amounts of legacy code" — merelydev, [HN](https://news.ycombinator.com/item?id=50451620), 2026-11-11.

The fixes vary: Context7 and other docs MCP servers, llms.txt files, a docs index inside AGENTS.md, a `_vendor` folder of dependency source, or telling the agent to search.

- "giving it access to up-to-date documentation via MCP … so it has direct access to canonical docs for authoritative grounding" — CharlesW, [HN](https://news.ycombinator.com/item?id=44770702), 2025-08-02
- "point the LLM specifically to what you're trying to use works better than just relying on its training data" — gexla, [HN](https://news.ycombinator.com/item?id=45009724), 2025-08-25
- "I'm using MCP for the LLM to lookup up-to-date documentation, and not hallucinate APIs." — addandsubtract, [HN](https://news.ycombinator.com/item?id=47716245), 2026-04-10

**Counter-views (about 10 authors).** Some doubt that docs lookup does much. "From my experience context7 just does not work, or at least does not help." — the_mitsuhiko, [HN](https://news.ycombinator.com/item?id=44939875), 2025-08-18. Another commenter generated llms.txt files for several sites "and have seen 0 impact" — iammrpayments, [HN](https://news.ycombinator.com/item?id=44960108), 2025-08-20. A third finds dependency docs "aren't that much of a game changer" and vendors the source code instead — epolanski, [HN](https://news.ycombinator.com/item?id=46826302), 2026-01-30. Others say a pointer is not enough and the docs must be pasted into context ([HN](https://news.ycombinator.com/item?id=47744517)), or that loading whole docs bloats context ([HN](https://news.ycombinator.com/item?id=46818853)). A few report never hitting version mismatches ([HN](https://news.ycombinator.com/item?id=46819065)) or say models pick up APIs newer than their cutoff without help ([HN](https://news.ycombinator.com/item?id=48433558)). One commenter graded Context7's MCP tool schema an F on quality ([HN](https://news.ycombinator.com/item?id=47423547)); that figure comes from the commenter's own leaderboard.

## Docs for agents are converging on an always-loaded index plus files to read on demand

Support: about 20 authors across 3 threads (the Vercel eval thread [AGENTS.md outperforms skills](https://news.ycombinator.com/item?id=46809708), 2026-01-29, plus [Claude Skills are awesome](https://news.ycombinator.com/item?id=45619537) and [I still prefer MCP over skills](https://news.ycombinator.com/item?id=47712718)). As commenters describe it, Vercel found that a compressed docs index placed in AGENTS.md beat a docs skill, because the agent often failed to invoke the skill. Commenters drew a design rule from that: keep a short index in context and let the agent read the referenced files when needed.

- "'compression' of doc pointers works. It's barely readable to humans, but directly and efficiently relevant to LLM's" — w10-1, [HN](https://news.ycombinator.com/item?id=46818579), 2026-01-29
- "half the time Claude Code still doesn't invoke it" — msp26, on a SKILL.md for marimo, [HN](https://news.ycombinator.com/item?id=46820656), 2026-01-30
- "Most llms.txt are very similar to the compressed docs." — seunosewa, [HN](https://news.ycombinator.com/item?id=46828362), 2026-01-30

**Counter-views.** Some said the comparison was unfair, because the skill had a one-line description while AGENTS.md held the whole index ([HN](https://news.ycombinator.com/item?id=46819693), [HN](https://news.ycombinator.com/item?id=46959424)). Others said the result will not scale: "as your project grows you won't be able to put all your documentation in there" — remify, [HN](https://news.ycombinator.com/item?id=46822336), 2026-01-30. A third group expected the next models to be post-trained to call skills proactively ([HN](https://news.ycombinator.com/item?id=46819783)). The tool-level version of the same debate is about MCP tool descriptions: about 20 authors across 10 threads say descriptions are the docs agents actually read, that they cost context on every request, and that progressive disclosure (tool search, deferred loading) is the fix ([HN](https://news.ycombinator.com/item?id=47162328), [HN](https://news.ycombinator.com/item?id=49179644)). A CLI's `--help` competes as agent docs, but only "unless it's a super well documented CLI like `gh`" — airforce1, [HN](https://news.ycombinator.com/item?id=47212346), 2026-03-02.

## Writing docs for agents improves human docs, but agent-written docs are distrusted

Support for convergence: about 14 authors across 9 threads. Several say the agent finally gives a reason to write and maintain docs, because it reliably reads them.

- "if we want them to have a proper onboarding then we're forced to be less lazy with our docs" — blinkymach12, [HN](https://news.ycombinator.com/item?id=44957838), 2025-08-20
- "With an agent I know if I write once to CLAUDE.md and it will be read by 1000's of agents in a week." — nicklo, [HN](https://news.ycombinator.com/item?id=44957711), 2025-08-20
- "these kinds of context documents resemble normal developer documentation, but actually good" — michael1999, [HN](https://news.ycombinator.com/item?id=45623067), 2025-10-17

**Counter-views.** About 6 authors say agents need a different style from humans: "they need so much more details and context to be reliable than humans" — kissgyorgy, [HN](https://news.ycombinator.com/item?id=44960539), 2025-08-20. Others note that agents are worse than juniors at noticing when docs are out of date ([HN](https://news.ycombinator.com/item?id=44963463)), and that docs go stale "the moment you write" them ([HN](https://news.ycombinator.com/item?id=45627925)). A separate group of about 15 authors across 12 threads distrusts docs, READMEs and comments that agents write: the complaints are redundant structure, "well written bullshit" ([HN](https://news.ycombinator.com/item?id=47330417)) and docs nobody reviewed. One says documentation "has gotten so very bad thanks to AI" — dawnerd, [HN](https://news.ycombinator.com/item?id=50389380), 2026-11-06. A minority report that an agent told to "update all relevant and related docs" after every commit keeps them accurate ([HN](https://news.ycombinator.com/item?id=48431038)).

## Vendor docs lag the product, so the real reference is the changelog, GitHub issues and HN replies

Support: about 25 authors across 18 threads report harness or SDK docs that are missing, stale, ambiguous or wrong, or behaviour they learned only from a changelog, an issue or a staff comment. The examples are specific. A Claude Code setting existed in the changelog while "docs are not updated yet" ([HN](https://news.ycombinator.com/item?id=47783188)). Two settings were new to a commenter until a staff member mentioned them on HN ([HN](https://news.ycombinator.com/item?id=47670748)). Agent SDK billing under a subscription was unclear enough that commenters gave contradictory first-hand reports in one thread ([HN](https://news.ycombinator.com/item?id=50277907), [HN](https://news.ycombinator.com/item?id=50279948), [HN](https://news.ycombinator.com/item?id=50281790)). Docker Sandboxes' docs on auth override were "incorrect" ([HN](https://news.ycombinator.com/item?id=49251284)). Copilot's subagent routing "doesn't work, even though the documentation makes it seem like it should" ([HN](https://news.ycombinator.com/item?id=46944756)).

- "They need to stop clarifying on HN and X … and update their damn docs" — giancarlostoro, [HN](https://news.ycombinator.com/item?id=50283687), 2026-10-29
- "I would have opted out 2 months ago if it was documented or communicated in any way publicly." — CjHuber, [HN](https://news.ycombinator.com/item?id=47670748), 2026-04-07
- "Docs on overriding auth are incorrect." — Humphrey, on Docker Sandboxes, [HN](https://news.ycombinator.com/item?id=49251284), 2026-08-10

Commenters also want worked examples rather than general pages: Claude Code's docs are "good, but … kept relatively general" — mhrmsn, [HN](https://news.ycombinator.com/item?id=44678825), 2025-07-25. Setup docs for skills were written "for the web version" only ([HN](https://news.ycombinator.com/item?id=45621040)). The MCP spec was called "a mess" and its terms confusing ([HN](https://news.ycombinator.com/item?id=44386078), [HN](https://news.ycombinator.com/item?id=44384382)).

**Counter-views (about 7 authors).** Some answer complaints with "RTFM": the behaviour is documented, press ctrl+o, or read the Output Styles page ([HN](https://news.ycombinator.com/item?id=46980473)). Others point to docs that were clear once read ([HN](https://news.ycombinator.com/item?id=48631979)), or to Claude Code consulting its own docs map when asked about itself ([HN](https://news.ycombinator.com/item?id=45797914)). The corpus's concentration on Claude Code (see Method and limits) means this finding says more about one fast-moving vendor than about SDK docs in general.

## Silent changes to harness behaviour are the top DX complaint

Support: about 60 authors whose comments I read across seven Claude Code threads: [Claude Code is being dumbed down?](https://news.ycombinator.com/item?id=46978710) (2026-02-11), [Claude Code CLI was broken](https://news.ycombinator.com/item?id=46532075) (2026-01-07), [unusable … with Feb updates](https://news.ycombinator.com/item?id=47660925) (2026-04-06), [An update on recent Claude Code quality reports](https://news.ycombinator.com/item?id=47878905) (2026-04-23), [steganographically marking requests](https://news.ycombinator.com/item?id=48734373) (2026-06-30), [Session URL appended to commit messages](https://news.ycombinator.com/item?id=49498201) (2026-08-30) and [Feature Request: Support AGENTS.md](https://news.ycombinator.com/item?id=49367350) (2026-08-19). Keyword matches suggest more. The complaint is that defaults, system prompts, reasoning effort and visible output change between releases without an announcement or an opt-out, so a working setup degrades and the user cannot tell why. A Claude Code team member's framing explains the vendor side: "the model frequently changes underneath you" — bcherny, [HN](https://news.ycombinator.com/item?id=46981968), 2026-02-11.

- "There should never be an undocumented change that reduces quality." — bshanks, [HN](https://news.ycombinator.com/item?id=47895898), 2026-04-24
- "Make new system prompt changes 'experimental' first so you can gather feedback." — 2001zhaozhao, [HN](https://news.ycombinator.com/item?id=47879358), 2026-04-23
- "After spending years trying to get reproducible builds, I now have a crazy moving target to deal with." — dgxyz, [HN](https://news.ycombinator.com/item?id=47676620), 2026-04-07
- "a change in format for a changelog markdown file causes the entire app to break" — mvdtnz, [HN](https://news.ycombinator.com/item?id=46532713), 2026-01-07

Practitioners respond in two ways. About 8 authors pin versions or disable auto-update (`DISABLE_AUTOUPDATER`, `minimumVersion`) or roll back after a regression ([HN](https://news.ycombinator.com/item?id=47586524), [HN](https://news.ycombinator.com/item?id=47740382)). About 12 authors across 10 threads reverse-engineer the harness with third-party tools: cchistory to diff system prompts between versions, claude-trace, and mitmproxy. "It is a bit weird why anthropic doesn't make that available more openly." — Stagnant, [HN](https://news.ycombinator.com/item?id=46549403), 2026-01-09. One commenter keeps a sed script that patches phrases out of the prompt after each update (same comment).

**Counter-views (about 8 authors).** Some call the outrage a normal feedback loop over "default verbosity levels in a CLI tool" — tzury, [HN](https://news.ycombinator.com/item?id=46980966), 2026-02-11. Some found the April postmortem "clear, honest and definitely plausible" ([HN](https://news.ycombinator.com/item?id=47883626)), and some think rapid change is desirable early in a product's life ([HN](https://news.ycombinator.com/item?id=47464462)). A recurring nuance is that model-side changes and harness-side changes are hard to tell apart from outside; both arrive under one product name.

## The ecosystem itself churns, and practitioners compare it to JavaScript frameworks

Support: about 25 authors across 18 threads. Beyond one vendor's releases, commenters describe the stack churning: frameworks of 2023 dropped by 2025, a new SDK every week, protocols changing transports, harnesses rebuilt repeatedly, and names that collide (three "Agent SDKs", two "ACP"s).

- "We've officially hit the JS framework churn phase of AI tooling." — gawacer, [HN](https://news.ycombinator.com/item?id=50280658), 2026-10-28
- "anything we were learning or implementing in regards to AI was going to be outdated in two weeks" — kami23, [HN](https://news.ycombinator.com/item?id=50283128), 2026-10-29
- "There's so much thrashing that if you're not interested with the SOTA, you can just wait for everything to calm down" — recursive, [HN](https://news.ycombinator.com/item?id=46533071), 2026-01-07
- "We really need some consolidation around commands, skills, subagents, and plugins." — mil22, [HN](https://news.ycombinator.com/item?id=48295884), 2026-05-27

The MCP protocol draws its own complaints: transports moved from stdio to SSE to Streamable HTTP ([HN](https://news.ycombinator.com/item?id=44413620)), "the protocol changes every month and breaks things" ([HN](https://news.ycombinator.com/item?id=44528089)), and "EVERY MCP UPDATE is almost certainly a breaking change" ([HN](https://news.ycombinator.com/item?id=49405005)); about 6 authors in 5 threads. A commenter recounts, without a source, that Manus rebuilt its harness five times in six months and LangChain re-architected Deep Research four times in a year ([HN](https://news.ycombinator.com/item?id=47991481)). Manus's own July 2025 post says "we've rebuilt our agent framework four times" ([manus.im](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)); the five-in-six-months figure and the LangChain count were not found in a primary source and stay secondary.

**Counter-views (about 5 authors).** "Why is a large number of ideas, technologies, frameworks, etc. bad?" — virgil_disgr4ce, [HN](https://news.ycombinator.com/item?id=50274600), 2026-10-28. Others attribute the churn to a field that does not yet know the right answer ([HN](https://news.ycombinator.com/item?id=50275372)), and one notes that Dagger and Google's ADK "have also stabilized their APIs on new major" versions ([HN](https://news.ycombinator.com/item?id=50294950)).

## Heavy framework abstractions are disliked; a framework's value is said to be tracing, not orchestration

Support: about 20 authors across 12 threads, overlapping with the build-versus-buy theme note. The DX complaint is that LangChain-style frameworks force their own idioms and hide a loop that is simple to write. "It seemed to force code into their way of doing things and was deeply opinionated about things that didn't matter like prompt templating." — space_fountain, [HN](https://news.ycombinator.com/item?id=47591895), 2026-03-31. Others are blunter: "LangChain is not over-engineered; it's not engineered at all." ([HN](https://news.ycombinator.com/item?id=47381164)). "The core of a coding agent is really simple, it's a loop with tool calling." — libraryofbabel, [HN](https://news.ycombinator.com/item?id=46546463), 2026-01-08.

**Counter-views (about 10 authors).** The best-argued defence says the value lies elsewhere: "it's tooling + observability" and one environment variable gives "a UI where i can nicely go through all of my traces" — fxwin, [HN](https://news.ycombinator.com/item?id=48480273), 2026-06-10. Another agrees that "most of the value I've gotten out of is has been observability" — chaos_emergent, [HN](https://news.ycombinator.com/item?id=47595162), 2026-04-01. Others say the 200-line loop is "technically true, operationally incomplete" — mirzap, [HN](https://news.ycombinator.com/item?id=46551553), 2026-01-09, or that LangGraph earns its keep for deterministic multi-step flows ([HN](https://news.ycombinator.com/item?id=47592630)).

## Practitioners want to see what the agent is doing, and treat hiding it as a regression

Support: about 45 authors across 15 threads. The clearest case is Claude Code's February 2026 change that collapsed file reads into "Read 3 files" ([thread](https://news.ycombinator.com/item?id=46978710), 2026-02-11). About 25 authors in that thread objected: seeing the files lets them interrupt early, catch wrong turns and keep trust. The same demand appears for hidden or summarised reasoning (about 15 authors; [Feb updates thread](https://news.ycombinator.com/item?id=47660925), [Extended Thinking thread](https://news.ycombinator.com/item?id=48630535)), for subagents that return only a summary (about 6 authors), for a context gauge that is always visible (about 5), and for quota or usage that is opaque (about 7).

- "The default view hiding files read is fully a regression imho. It is so helpful for sense of control" — patcon, [HN](https://news.ycombinator.com/item?id=46983864), 2026-02-12
- "This change doesn't reduce noise for me. It removes functionality." — ctoth, a screen reader user, [HN](https://news.ycombinator.com/item?id=46982469), 2026-02-11
- "I like the TUI. But I also want all the logs. And I do mean all of them." — sh34r, [HN](https://news.ycombinator.com/item?id=46984587), 2026-02-12
- "I do hate how there's no observability into subagents and you just get a summary." — gck1, [HN](https://news.ycombinator.com/item?id=47133556), 2026-02-24

Commenters also proposed concrete designs: a verbosity enum like log levels instead of an overloaded "verbose" boolean ([HN](https://news.ycombinator.com/item?id=46987638), [HN](https://news.ycombinator.com/item?id=46982736)), a separate log stream to a file descriptor while the TUI keeps quiet defaults ([HN](https://news.ycombinator.com/item?id=46984587)), and a forced choice when a default changes ([HN](https://news.ycombinator.com/item?id=47676381)). One accessibility point is worth keeping: for a screen reader user, nothing can be glanced at, so collapsed output means no information at all ([HN](https://news.ycombinator.com/item?id=46982469)).

**Counter-views (about 7 authors).** "There is almost no value in watching the stream of intermediate tokens." — perrygeo, [HN](https://news.ycombinator.com/item?id=46983251), 2026-02-12. Some would hide all generated code and read only summaries and plans ([HN](https://news.ycombinator.com/item?id=46982563)). The vendor said the change reflected "an experience that most users preferred" ([HN](https://news.ycombinator.com/item?id=46982306) quotes it), and expected to hide more as trust grows ([HN](https://news.ycombinator.com/item?id=46982317)). This split tracks the reader: engineers steering an agent mid-task want the stream, while those who review only the artifact do not.

## Debugging runs means reading local transcripts and OTel data, not using LLM-ops products

Support: about 25 authors across 20 threads use the harness's local session logs (Claude Code's `~/.claude/projects/*.jsonl`, Codex's equivalents) to debug, search, audit or measure past runs. About 11 authors across 9 threads use OpenTelemetry from the harness, usually with an existing backend such as Datadog. Not one of the 111,532 comments names LangSmith, Langfuse, Braintrust, Helicone, Logfire or Arize as a tool. Practitioners describe the JSONL files as the system of record and build small tools on them: TUIs to browse them, full-text search, commit attribution and regression analysis.

- "For Claude Code, this is literally a JSONL file in .claude/projects/… You can trivially have Claude Code write a commit hook" — vidarh, [HN](https://news.ycombinator.com/item?id=46973388), 2026-02-11
- "the only way to really make sense of using LLMs in any context is to have good observability data you can analyze later" — phillipcarter, [HN](https://news.ycombinator.com/item?id=44407945), 2025-06-28
- "I checked the session logs to see how often the agents were actually invoking the LSP tools." — mil22, [HN](https://news.ycombinator.com/item?id=48295884), 2026-05-27

The limits they name are retention ("jsonl files seem to get recycled after 30 days" — tstrimple, [HN](https://news.ycombinator.com/item?id=48446947), 2026-06-08), content the OTel export leaves out (prompts but not responses, [HN](https://news.ycombinator.com/item?id=44324621)), and logs the vendor controls: "the evidence is whatever the vendor chose to log" — felix9527, [HN](https://news.ycombinator.com/item?id=47348742), 2026-03-12. Two late-2026 threads show the logs becoming material for disputes: one measured background-agent summary calls from OTel traces ([HN](https://news.ycombinator.com/item?id=50284256)), and another argued over session URLs added to commits ([thread](https://news.ycombinator.com/item?id=49498201)).

**Counter-views.** "Session logs can absolutely be useful, but not when building further." — trjordan, [HN](https://news.ycombinator.com/item?id=48777538), 2026-07-03, who sees them as useful during validation only. The absence of LLM-ops products almost certainly reflects the corpus (individual developers running coding agents) more than production practice.

## Onboarding is hard because the configuration surface is large and overlapping

Support: about 10 authors across 8 threads; a single-anecdote tier compared with the findings above. Newcomers ask how to build their own loop ([HN](https://news.ycombinator.com/item?id=44398524)), why `/init` does not already do the setup experts describe ([HN](https://news.ycombinator.com/item?id=46530178)), or what a product is at all after reading its docs ([HN](https://news.ycombinator.com/item?id=47108659)). Experienced users report that overlapping concepts (commands, skills, subagents, plugins, hooks, output styles, environment variables) are hard to keep straight: "There are so many config options. Most I still need to truly deeply understand." — sdoering, [HN](https://news.ycombinator.com/item?id=46982104), 2026-02-11. One frames the shift as going "from 'RTFM' to 'here's 30 tips to babysit your AI assistant'" — rncode, [HN](https://news.ycombinator.com/item?id=46069162), 2025-11-27.

## Single anecdotes worth keeping

These come from one or two commenters each, so they are leads to test rather than consensus.

- **Changelogs parsed as data break things.** A date added to a CHANGELOG.md header crashed Claude Code 2.1.0 at startup, because the CLI parsed the file as structured data ([HN](https://news.ycombinator.com/item?id=46532252), [thread](https://news.ycombinator.com/item?id=46532075)).
- **Verbose-mode semantics are an API.** One user's scripts read the Agent SDK's verbose output for logging and broke when its meaning changed: "Please don't change what these modes do!" — adastra22, [HN](https://news.ycombinator.com/item?id=46989030), 2026-02-12.
- **Logging is now an interface.** A library warned in its release notes that its stdout "may confuse AI-based agents", which prompted "logging is now an undocumented API" — liampulles, [HN](https://news.ycombinator.com/item?id=48320713), 2026-05-29.
- **llms.txt can carry instructions.** A GitBook-generated llms.txt included an "agentic ask interface" section that agents follow, and one commenter suggested stripping it with hooks ([HN](https://news.ycombinator.com/item?id=50389933)); another asked what a hostile llms.txt could do ([HN](https://news.ycombinator.com/item?id=50386206)).
- **Eval-measured docs.** Google said it used eval infrastructure to decide when knowledge is common enough to prune from its agent guides ([HN](https://news.ycombinator.com/item?id=50447679) quotes it); one user found the skill cost about $5 per use on their codebase ([HN](https://news.ycombinator.com/item?id=50450822)).

## Shifts over time

I compared keyword-hit rates per 10,000 comments in three periods: mid-2025 (to 2025-11-30, 23,171 comments), early 2026 (2025-12-01 to 2026-05-31, 53,136) and late 2026 (2026-06-01 onward, 35,225). The keywords are noisy and the thread mix changes between periods, so these show direction, not size.

- **Docs lookup and stale-API complaints fell.** Docs-lookup mentions (Context7, llms.txt, "point it at the docs") fell from 14.2 to 6.0 to 2.0 per 10,000 comments; llms.txt and Context7 alone fell from 9.5 to 4.9 to 1.4. Hallucinated and outdated API mentions fell from 12.5 to 7.2 to 4.5. Mid-2025 threads treat docs MCP servers as a must-have ([HN](https://news.ycombinator.com/item?id=44773228)). By 2026, commenters treat them as optional or redundant with web search ([HN](https://news.ycombinator.com/item?id=46546799)). Vendors moved the other way: in November 2026 Google shipped eval-tested docs-as-skills for agents ([thread](https://news.ycombinator.com/item?id=50443812)), so docs for agents became a vendor product as interest in DIY lookup declined.
- **Churn complaints peaked in early 2026.** Churn phrases rose from 5.2 to 10.2 and fell back to 4.8. The early-2026 peak matches the Claude Code release-quality threads (January to April 2026). In October 2026 the complaint shifted from one tool's releases to the ecosystem ("JS framework churn phase").
- **Visibility complaints moved from output to reasoning and logs.** Complaints about hidden or summarised reasoning rose from 1.7 to 4.3 to 7.7, and transcript or session-log mentions rose from 1.7 to 4.3 to 7.1. In mid-2025, visibility meant cost and quota (the usage-monitor thread). In early 2026 it meant file paths and thinking in the TUI. By late 2026 it meant transcripts as evidence in disputes about what the harness sent and to whom.
- **Undocumented-behaviour complaints stayed flat** at about 5 to 6.5 per 10,000 comments across all three periods. The docs gap did not close.

## Design implications for our SDK, harness and agent

1. **Ship docs for agents as a first-class artifact, from the pinned release.** Practitioners say agents write against stale APIs and that an always-loaded index plus on-demand files works best. Publish an `llms.txt` and a compact docs index generated from the same release tag as the npm package, and keep the guide's examples runnable. Our docs-drift finding ("Docs drift wherever docs build from a branch instead of a release", [SDK research §4](../../agent-sdk/agent-sdk-research.md#4-callers-need-six-typed-interceptors-a-layered-event-union-and-an-explicit-deprecation-pipeline)) already points this way; the HN evidence adds that agents, not only humans, read these docs.
2. **Make behaviour changes opt-in and announced.** Practitioners' top complaint is defaults that change between releases. SDK decision 13's versioning policy (`experimental_` prefixes, renames as aliases, [SDK research §6](../../agent-sdk/agent-sdk-research.md#6-fourteen-design-decisions-follow-from-the-evidence)) should cover defaults and built-in prompts as well as types. Every change to a default, prompt or tool description gets a changelog entry and a setting to keep the old value. Agent decision 11 (stamp a bundle hash on every session, [agent research §6](../../agent/agent-research.md#6-seventeen-design-decisions-for-our-agent)) is what lets a user prove that a regression came from a version change.
3. **Publish the system prompt and tool descriptions, and diff them per release.** Users built cchistory and mitmproxy setups to see these. Shipping them as readable files, with a diff in each release note, costs us nothing and removes a reverse-engineering chore.
4. **Default to showing what the agent does, with levels.** Show tool calls and file paths by default, use a verbosity enum (quiet, normal, verbose, trace) instead of a boolean, and write a full event stream to a file or descriptor whatever the TUI shows. This fits harness decision 18 (telemetry as a projection of the log, [harness research §6](../../agent-harness/agent-harness-research.md#6-eighteen-design-decisions-follow-from-the-evidence)); the screen-reader point argues for a plain-text event stream as a supported interface.
5. **Treat the JSONL session log as the debugging product.** Practitioners already debug from transcripts. Harness decision 1 (the JSONL tree is the only source of truth) should come with a documented, stable entry schema, configurable retention (not a silent 30-day purge), subagent sidechains linked to their parent, and a CLI to search and replay sessions (harness decision 7). An LLM-ops vendor integration can stay optional; OTel export to the user's own backend (harness decision 18) covers what practitioners say they use.
6. **Keep reasoning and subagent output inspectable when the provider allows it.** Where reasoning arrives summarised or encrypted, record what we received and label it as a summary. Never drop subagent transcripts: store them as entries linked by the spawning id.
7. **Keep the abstraction thin, and keep the loop visible.** The dislike of heavy frameworks supports SDK decision 6 (one pure loop function) and the AGENTS.md rule that each component be removable. Most framework users name tracing as the value they get, so the built-in OTel observer should work with one setting.
8. **Hold the concept count down and document each concept once.** The complaints about overlapping commands, skills, subagents and plugins argue for a small extension model (harness decision 17's three tiers) with one page per concept, and for not adding a new mechanism when an existing one covers the case.
9. **Answer in the docs, not in threads.** When a question gets answered in an issue or a chat, the answer should land in the docs in the same release.

## Method and limits

**Extraction.** Throwaway Python scripts in the session scratchpad flattened all 400 thread trees into 111,532 comments with story id, comment id, author, date and HTML-stripped text. I skipped the handful of off-topic threads (for example the Mac Studio review) by not citing them. Filters were regular expressions for: llms.txt, Context7 and docs MCP; "docs for agents" and pointing agents at docs; hallucinated or outdated APIs and training cutoffs; docs that are undocumented, out of date or wrong; churn phrases ("moving target", "keeps changing", "framework churn"); breaking changes and deprecation; LangChain-family frameworks with abstraction terms; observability products and OTel; transcripts and JSONL session logs; hidden or summarised reasoning; visibility phrases ("see what it is doing", "black box", "visibility into"); context and quota gauges; version pinning and auto-update; MCP spec churn; tool descriptions; RTFM; and configuration overload. I also read whole or keyword-filtered comment lists from 13 threads central to the theme, including the Claude Code SDK launch, The Agent SDK, Claude Code is being dumbed down?, the Feb-updates and quality-report threads, Claude Code CLI was broken, AGENTS.md outperforms skills, the agent-readiness scanner and the modern-web-guidance launch.

**Reading.** I read about 2,000 comment excerpts (the first 220 to 520 characters of each, more for quoted comments), spread across all three periods and well over 150 threads. Support counts come from reading the hits and judging which were on-claim; regex totals were not used as counts, because the visibility and churn filters matched many off-topic comments (for example "black box" used about models in general). Counts are therefore approximate, with an uncertainty of perhaps ±30%, and authors who made the same point twice count once.

**Biases.** The corpus is HN stories above 50 points that matched agent-related queries, so it over-represents coding agents, Claude Code in particular (many of the DX threads are Claude Code GitHub issues or announcements), senior engineers, individual developers rather than platform teams, and strong opinions. Complaint threads attract more comments than quiet satisfaction, so the silent-change and visibility findings are probably over-weighted relative to the user base. The absence of LLM-ops products says little about production teams who do not post in these threads. Few comments discuss SDK reference docs (Vercel AI SDK, OpenAI Agents SDK, Pi) at all: only about 8 authors mention any SDK's docs or quickstart, so this note says more about harness DX than about SDK docs. Several quoted claims (Vercel's eval result, the Manus and LangChain rebuild counts, the MCP schema grades) come from commenters summarising other work and are marked as secondary.
