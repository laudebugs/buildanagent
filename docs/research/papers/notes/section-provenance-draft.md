## Trustworthy agent provenance needs a replayable transaction log, per-criterion verifiers the generator cannot see, and a staged gate before any demo-based score counts

Six papers from November 2026 converge on the same design for provenance and verification: record what the agent actually did as a structured, append-only trace; grade that trace against many narrow criteria instead of one holistic judgment; and gate every release behind that grading before a demo or a leaderboard number ever counts. A global bank's evaluation of ten agentic AI platforms found that demo-based scores mostly measure presentation, not capability, so it proposes scoring platforms only after a hidden technical gate runs (Ali, Siddiqui and Zahid, arXiv:2611.24039, 18 Nov 2026). That finding, together with five companion papers on governed ML harnesses, runtime transaction schemas, shadow-mode deployment, and natural-language-criterion verifiers, matches the design we already committed to: an append-only, tree-shaped session log (N2), a check-and-deploy gate the generator cannot bypass or read ([ADR 0039](../../../decisions/0039-check-and-deploy-gate.md)), and a shadow stage before any real rollout (A22). The agreement is not coincidental. Both our plan and these papers start from the same failure mode: an agent that looks capable in a demo because nothing recorded what it actually tried, retried, or silently skipped.

Ali, Siddiqui and Zahid name that failure mode the halo effect: when a cross-functional panel scored ten platforms across nine capability dimensions on three financial-services workloads, the scores moved together almost perfectly, which means the panel was rating one overall impression rather than nine separate capabilities (arXiv:2611.24039). Their fix is a four-layer, gate-then-score protocol, where a technical layer runs first and the human panel sees only what passes it, plus trace-level reliability metrics and an autonomy-readiness scale. This is the same order ADR 0039 already enforces for the agent platform: the gate type-checks, runs mock-model tests, and scores hidden evals before any deploy request is accepted, and the graders live in the platform rather than the generated project, so the system being judged never shapes its own score. The paper gives that design a name and a documented failure case for skipping it.

Wong's governed harness for LLM-driven ML experimentation shows what the gate needs to read from at runtime. A control plane, not the LLM, manages each trial's lifecycle, checks whether an edit stays in scope, decides to keep or discard it, and writes every trial to an append-only ledger; governance metrics such as invalid-action rate, repeated-bad rate, and provenance completeness are then computed from that ledger across six ML tasks and 1,445 trials, with the ledgers released for reproduction (arXiv:2611.23678, 18 Nov 2026). N2's `SessionEntry` union already separates `permission_decision` and namespaced `product_record` entries from the core transcript for exactly this reason: a dashboard or a gate report should compute metrics like Wong's from the log without re-deriving them from free text. Hou et al. push the same point further for coding agents specifically. Their survey of agent-output datasets found that patches, commits, and benchmark results omit the failed retries, fallback strategies, routing decisions, and abandoned sessions that actually drive cost and reliability, so they propose recording those as structured runtime transaction records and ship a local-first prototype, Atm, that reconciles gateway records with transcript evidence without sending prompt content to an external collector (Hou, Li, Chen and Chen, arXiv:2611.23234). That is the gap our tree-shaped, append-only log is built to close, and it is also the gap that makes an agent's partial failures hard to roll back cleanly, which is why a multistep action still needs the saga-style compensation our own reversible-actions research describes rather than a single commit-or-fail transaction.

Masoero's deployed documentation-maintenance system shows what grading that log should look like once an agent runs on real work instead of a benchmark. Over 43 days of shadow-mode operation, "TriAgent" triaged 499 tickets and surfaced 92 documentation gaps, and an LLM judge panel found 81.1% of its verifiable assertions correct; human and agent replies turned out to be complementary rather than redundant (arXiv:2611.23142, 17 Nov 2026). That is close to the shape A22 already specifies: a shadow wrapper that records proposed writes without executing them, a join of those proposals against human labels, and a `sampledJudgeScore` that stays null until a judge is calibrated. Masoero's 43-day, 499-ticket run is a concrete data point for how long and how large our own shadow stage should be before we trust its labels, once the triage round resumes under [ADR 0032](../../../decisions/0032-personal-coding-agent-first.md).

The last two papers answer the halo-effect problem directly, at the level of the verifier itself rather than the harness around it. Pitis et al. built VFM, a tree-attention verifier that checks one agent output against many natural-language criteria at once and returns a separate satisfied, violated, or not-applicable verdict for each one, pretrained on a roughly 394,000-example corpus called CriteriaBank; a fine-tuned 4B-parameter version beats a much larger model on a synthetic governance benchmark and checks 1,000 criteria against a 4,000-token context in under two seconds on a single H100 (Pitis, Alamdari, Tang, Klassen and McIlraith, arXiv:2611.23074, 17 Nov 2026). Dücker et al. reach the same conclusion from a different industry: their 2,464-criterion, human-judged benchmark across 24 investment-banking tasks shows that a verifier scoring many separate rubric criteria, distilled into an open-source tool called Gandalf, matches or beats existing verifiers at lower cost (Dücker, Kumar, Liu, Chaudhary, Plesner, Guzmán and Athalye, arXiv:2611.22841, 17 Nov 2026). Both papers replace the single holistic score that produces Ali et al.'s halo effect with many independent, auditable verdicts, which is exactly the shape ADR 0039's hidden graders should take: not one pass/fail judgment on a generated agent, but a set of narrow, separately scored criteria the generator never sees.

Taken together, these six papers confirm rather than revise our current design: the session log stays append-only and tree-shaped under N2 ([ADR 0013](../../../decisions/0013-log-entry-per-content-block.md), [ADR 0018](../../../decisions/0018-retention-and-transcript-schema.md)); the check-and-deploy gate keeps its hidden, many-criterion graders under ADR 0039; and shadow-mode evaluation, deferred under ADR 0032 but already specified in A22, is the right stage to put between a passing gate and a real deploy. The one addition worth carrying into A22 and ADR 0039 is explicit: grade the log on several narrow, auditable criteria, the way VFM and Gandalf do, rather than trust a single score that Ali et al.'s panel has now shown can move as one undifferentiated halo.
