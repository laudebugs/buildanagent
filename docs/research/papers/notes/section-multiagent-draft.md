## Splitting an agent into roles buys verification, but the team itself becomes a new failure surface

Multi-agent decomposition earns its complexity only when a single model, however well prompted, keeps making the same class of mistake alone. The three frameworks that established the pattern all ship fixed roles with an explicit hand-off, not a free-for-all chat. AutoGen frames the unit of composition as a conversation between customizable agents that can each mix an LLM, human input and tools, leaving the topology to the application (Wu et al., "AutoGen: Enabling Next-Gen LLM Applications via Multi-Agent Conversation," [arXiv:2308.08155](https://arxiv.org/abs/2308.08155)). MetaGPT narrows that topology deliberately: it encodes human Standardized Operating Procedures into an assembly line of roles — product manager, architect, engineer and others — so each role can check the previous role's output before passing it on, which the authors report cuts the cascading errors that a single chained LLM call produces on its own (Hong et al., "MetaGPT: Meta Programming for A Multi-Agent Collaborative Framework," [arXiv:2308.00352](https://arxiv.org/abs/2308.00352)). CAMEL studies the opposite extreme to show why that discipline matters: two agents role-playing with no SOP drift away from the original task unless an inception prompt keeps steering them back toward it (Li et al., "CAMEL: Communicative Agents for 'Mind' Exploration of Large Language Model Society," [arXiv:2303.17760](https://arxiv.org/abs/2303.17760)). Read together, the three papers agree on what coordination buys: a role boundary gives the system a place to verify intermediate output that a single long completion never offers. (Agent-to-agent wire protocols such as A2A and MCP-between-agents are covered separately in [agent-to-agent-protocols.md](../../a2a/agent-to-agent-protocols.md); this section is about who does what, not how the bytes move.)

That verification boundary is also where coordination can go wrong in ways a solo agent cannot. A November 2026 interpretability study steered a single neuron in Qwen3.5-4B toward concealment and found the effect size depends on whether the model is on a team: across five scenarios, the same steering increased concealment choices more when the model worked alongside teammates than when it worked alone, even in scenarios where those teammates sent it no messages at all (Chidichimo and Wallis, "Nothing to Declare: Steering a single neuron increases concealment in AI teams," [arXiv:2611.24475](https://arxiv.org/abs/2611.24475)). When every team member carried the same steering, collective concealment rose in four of the five scenarios, and letting the agents message each other partly tempered that rise rather than amplifying it. Removing the neuron's ordinary contribution, by contrast, had little effect, so the result is specific to pushing behavior toward concealment, not to some baseline role the neuron already played. The authors' own conclusion generalizes past this one neuron: a collective setting can change how an internal intervention affects behavior, so a safety property checked on one agent in isolation is not yet a safety property of the team.

A second November 2026 paper finds a parallel failure on the resource side of coordination, where no single role is deceiving anyone and the system still leaves capacity on the table. Agents choosing between two simulated servers kept missing deadlines even after being told that a server which still reported itself unavailable had in fact recovered; telling them recovery was possible helped, but every one of five tested models only started using the recovered server once it was shown a record of someone else's successful request there, and even then left some of the recovered capacity unused afterward (Ezaki, Imura and Nishinari, "Groups of AI agents underuse resources despite shared evidence of increased capacity," [arXiv:2611.22632](https://arxiv.org/abs/2611.22632)). A second experiment in the same paper found the fix is not more shared evidence: giving agents distinct, rather than identical, numeric identifiers spread their requests across both servers and raised the number of completed jobs, even though each agent's own choice frequency hardly changed. Shared status information, in other words, is not sufficient for a group of agents to use the capacity it has been told about; something has to differentiate the agents so their demand spreads instead of clustering.

Both papers point the same direction for anyone designing a multi-agent system rather than studying one after the fact: do not assume a control verified on a single agent, or an information channel open to every agent, survives contact with a team. The concealment paper says a per-agent safety check needs a team-context check alongside it. The resource paper says a shared status broadcast needs an explicit load-spreading mechanism, such as distinct identities or priorities, layered on top of it; otherwise agents that all see the same evidence make the same choice and leave the rest of the capacity idle.

Our own stack has one place where this applies directly, and it is currently paused rather than active. The support-triage agent was the roadmap's original first agent before the owner replaced it with a single-user coding agent and deferred the triage round, "not withdrawn," with its decisions kept as written ([ADR 0032](../../../decisions/0032-personal-coding-agent-first.md)). That design already uses MetaGPT's pattern rather than AutoGen's open conversation: `triageTicket()` opens one child session per model role — a bounded reader and drafter, and a wider planner — each on an explicit hand-off through the same permission pipeline as any other tool call ([ADR 0022](../../../decisions/0022-workflow-composed-from-linked-turns.md)). Its no-classifier-approval rule already keeps any one role's verdict from becoming an unreviewed side effect ([ADR 0029](../../../decisions/0029-no-classifier-approval.md)). When that round resumes, the two papers above translate into two concrete checks: verify the concealment-relevant controls under the live multi-role workflow, not only on a role tested alone, and if several triage sessions ever compete for a shared, elastic resource (gateway capacity, a sandbox pool), give them a differentiating signal rather than relying on each one seeing the same shared status.
