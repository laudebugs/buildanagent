## Our loop already is a ReAct loop; later papers add layers around it, not a rival architecture

Every agent loop in production today, ours included, descends from one 2022 idea: let the model interleave reasoning and acting in a single text stream instead of planning once and executing blind. ReAct has the model emit a thought, an action and an observation in a repeating trace, so "reasoning traces help the model induce, track, and update action plans... while actions allow it to interface with and gather additional information from external sources" (Yao et al., [arXiv 2210.03629](https://arxiv.org/abs/2210.03629)). On the interactive benchmarks ALFWorld and WebShop, ReAct beat imitation-learning and reinforcement-learning baselines by 34 and 10 absolute points using only one or two in-context examples; on HotpotQA and FEVER it cut the hallucination that chain-of-thought alone produces by letting the model query a Wikipedia API mid-trace (same source). That one design choice, reason and act in the same loop rather than in separate phases, is the ancestor of every tool-calling model API and every harness loop, ours included, that feeds a tool result back as the next turn's context.

Reflexion kept ReAct's loop and added a second one around it: a model that talks to itself across attempts instead of within a single attempt. Agents "verbally reflect on task feedback signals" and store that reflection "in an episodic memory buffer to induce better decision-making in subsequent trials," with no gradient update at all (Shinn et al., [arXiv 2303.11366](https://arxiv.org/abs/2303.11366)). The headline result makes the mechanism concrete: Reflexion raised HumanEval pass@1 to 91%, against GPT-4's 80% (same source). Nothing about the agent's weights changed between attempts; only the text carried forward did. That is the same trick our architecture's point 5, layered context policy, is built to generalize: carrying forward a compacted, selective summary of what went wrong, not the whole failed transcript, between turns.

Toolformer sits one layer lower, inside the model rather than around it, and the difference matters for where tool use should live. Schick et al. trained a model via self-supervised fine-tuning to "decide which APIs to call, when to call them, what arguments to pass, and how to best incorporate the results into future token prediction," needing only a handful of demonstrations per API (Toolformer, [arXiv 2302.04761](https://arxiv.org/abs/2302.04761)). The APIs it learned were a calculator, two search engines, a Q&A system, a translator and a calendar (same source), a narrower set than any current agent's tool registry. Toolformer proved tool calls could be baked into generation itself; the industry instead kept tool use at the harness boundary, as structured function calls a loop like ReAct's interprets, because a harness-level tool registry is swappable and auditable in a way a fine-tuned API habit is not. Our own point 4, a small set of well-designed tools plus an MCP client, follows that harness-boundary choice rather than Toolformer's fine-tuning one.

Voyager pushed the same ReAct-shaped loop toward long-horizon autonomy by giving it durable, reusable output instead of disposable text. Its three parts are "an automatic curriculum that maximizes exploration," "a skill library for storing and retrieving complex behaviors," and "an iterative prompting mechanism... that generates executable code for embodied control," all driven through black-box GPT-4 calls with no fine-tuning (Wang et al., [arXiv 2305.16291](https://arxiv.org/abs/2305.16291)). Against prior Minecraft agents, Voyager obtained 3.3 times more unique items, traveled 2.3 times farther and unlocked tech-tree milestones up to 15.3 times faster, and its skill library transferred to a fresh world where other methods could not generalize (same source). The AutoGPT and BabyAGI projects popularized the same shape, a loop that writes its own sub-goals, at the same time, but without Voyager's benchmark or its persistent, composable skill files. The lesson for a harness is Voyager's, not AutoGPT's: skills belong on disk as inspectable, reusable code, which is why our point 6, file-based memory first, and the `.agents/skills/` layout already treat a skill as a file an agent can read, write and reuse rather than as text re-derived every run.

A loop can still be architected two ways, and recent work treats that choice, not the reason-act interleaving itself, as the open design question. Plan-then-execute agents separate a planner that produces a full task graph from an executor that carries it out, trading ReAct's turn-by-turn adaptability for a plan a harness can inspect, scope tools against and resume after a failure; a 2025 guide to the pattern argues it gives "predictability, cost-efficiency, and reasoning quality" over reactive loops and resists prompt injection by fixing the control flow before any tool runs (Del Rosario et al., [arXiv 2509.08646](https://arxiv.org/abs/2509.08646)). A broader 2025 review of agent architectures, drawn only from A*/A-rank conferences and Q1 journals published in 2023–2025, confirms that single-agent design still splits along this same planning-versus-reasoning axis, with memory and tool integration as separate, orthogonal concerns (Chowa et al., "From Language to Action," [arXiv 2508.17281](https://arxiv.org/abs/2508.17281); see [retrieval-and-memory.md](../../memory/retrieval-and-memory.md) for the memory side). Our own stateless harness loop with explicit stop conditions and hooks sits closer to ReAct than to plan-then-execute: the model reasons and acts in one interleaved stream, and a fixed upfront plan is not required. But the hooks around that loop, before/after model step, before/after tool call, context transform, do the job a separate planner would otherwise do, letting us impose plan-then-execute-style structure (re-planning, scoped tool access, injection resistance) selectively, without giving up ReAct's turn-by-turn adaptability.

This lineage says our harness loop (point 2 in `AGENTS.md`'s planned architecture) needs no new architecture to add reflection, tool-use discipline or skill persistence: Reflexion's self-critique and Voyager's skill library are both expressible as hooks and file-based memory around the ReAct loop we already plan to build, and the plan-then-execute question is a hook-level policy decision, not a rewrite.
