# Security of browser-using AI agents (as of November 2026)

Research notes, gathered 2026-11-18. Each figure has the date its source gives. "Secondary" marks a claim taken from a search summary or third-party write-up and not checked against the primary page. Two primary pages could not be fetched: OpenAI's Atlas hardening post (HTTP 403, Cloudflare JS challenge) and the full OWASP Agentic Top 10 PDF. Their claims below come from secondary coverage.

## Indirect prompt injection from web content: attacks, measured rates, benchmarks and mitigations

### Takeaway
Every vendor that has shipped a browser agent reports prompt injection as unsolved. Layered defenses cut attack success sharply on vendor-internal adaptive tests: from roughly 8–14% to 1.4–2.4% (Anthropic, Nov 2025), and below 0.08% for Claude Opus 4.8 per Anthropic's current support page (undated). Independent and adaptive tests still find much higher rates: up to 86% partial success on WASP, up to 100% on VPI-Bench for browser-use agents, 81% for attacks tailored to a model in NIST CAISI's tests, and 95.41% for feedback-adapted attacks in BrowseSafe++. Treat any low vendor number as a floor that depends on the attacker, not as a guarantee.

### Cited Findings

**Vendor measurements (Anthropic)**
- 2025-08-25, Claude for Chrome pilot: 123 adversarial test cases across 29 attack scenarios. Autonomous-mode attack success was 23.6% without mitigations and 11.2% with them. On a challenge set of four browser-specific attack types (hidden malicious form fields in the DOM, injections in URL text and in tab titles), success fell from 35.7% to 0% — [Claude blog, Claude for Chrome](https://claude.com/blog/claude-for-chrome)
- Mitigations at the pilot: per-site permissions the user can grant or revoke, confirmations before publishing, purchasing or sharing personal data, revised system prompts, blocked site categories (financial services, adult, pirated content) and classifiers for suspicious instruction patterns, which were still in development at the time — [Claude blog](https://claude.com/blog/claude-for-chrome)
- 2025-11-24, internal adaptive Best-of-N attacker, 100 attempts per environment. Model alone / old safeguards / improved safeguards: Sonnet 4 13.8% / 10.7% / 2.0%; Sonnet 4.5 13.8% / 10.8% / 1.9%; Haiku 4.5 12.0% / 11.1% / 2.4%; Opus 4.5 8.0% / 7.6% / 1.4% — [Anthropic, prompt injection defenses](https://www.anthropic.com/research/prompt-injection-defenses)
- Anthropic's defense layers: RL training on simulated pages carrying injected instructions; classifiers that scan all untrusted content entering the context for hidden text, manipulated images and deceptive UI, and trigger a behavioral intervention; continuous human red teaming plus external arena-style challenges. The post says even 1% "still represents meaningful risk" — [Anthropic](https://www.anthropic.com/research/prompt-injection-defenses)
- Current support page (undated, read 2026-11-18): "Claude Opus 4.8 demonstrates significantly stronger prompt injection robustness than previous models"; the current configuration reduces attack success to "less than 0.08%" in internal testing that combines known effective techniques; risk "still non-zero" — [Claude Help Center, Use Claude in Chrome safely](https://support.claude.com/en/articles/12902428-use-claude-in-chrome-safely)
- Secondary: a write-up of the Claude in Chrome GA launch reports a three-layer defense holding attacks at 0–0.3%, against an unguarded 17.6% for Opus 4.5 and 3.8% for Opus 5. Not checked against an Anthropic page; model names conflict with the support page's Opus 4.8 — [kdpisda.in (secondary)](https://kdpisda.in/claude-in-chrome-general-availability/)

**Vendor measurements and statements (OpenAI, Google, Perplexity)**
- 2025-10-22, OpenAI CISO Dane Stuckey on Atlas, as quoted by Simon Willison: prompt injection is "a frontier, unsolved security problem"; OpenAI cites "extensive red-teaming", "novel model training techniques", overlapping guardrails and rapid response — [Simon Willison](https://simonwillison.net/2025/Oct/22/openai-ciso-on-atlas/)
- 2025-12-22, OpenAI "hardening Atlas against prompt injection" (secondary; primary returned 403). OpenAI trained an automated attacker end to end with reinforcement learning. The attacker tests candidate injections in a simulator ("counterfactual rollout"), and the attacks it finds feed adversarial training of new agent models in a "rapid response loop". Demo: a planted email made the agent send a resignation letter while drafting an out-of-office reply. OpenAI says prompt injection, like scams and social engineering, "is unlikely to ever be fully 'solved'" — [OpenAI (primary, not fetched)](https://openai.com/index/hardening-atlas-against-prompt-injection); [TechInformed (secondary)](https://techinformed.com/openai-hardens-chatgpt-atlas-against-prompt-injection-with-auto-attacker-red-team/); [eWeek (secondary)](https://www.eweek.com/news/openai-chatgpt-atlas-security/)
- 2025-12-08, Google Chrome agentic security architecture. A prompt-injection classifier checks each page and "runs in parallel to the planning model's inference". Automated red-teaming systems generate malicious sandboxed sites and track attack success to catch regressions. Google's VRP pays up to $20,000 for breaches of the agentic boundaries (bounty figure from [9to5Google (secondary)](https://9to5google.com/2025/12/08/gemini-chrome-agentic-security/)) — [Google blog](https://blog.google/security/architecting-security-for-agentic/)
- 2025-11-25 (v2 2026-08-12), BrowseSafe by Perplexity, Rutgers and Purdue authors. BrowseSafe-Bench: 14,719 samples (11,039 train / 3,680 test), 11 attack types, 9 injection strategies, 5 domains. Detection F1: BrowseSafe (fine-tuned Qwen3-30B-A3B) 0.904 at under 1 s; Sonnet 4.5 0.863 at 23–36 s with 669 refusals; GPT-5 (medium) 0.855; gpt-oss-safeguard-120B 0.741; PromptGuard-2 (86M) 0.360. Architecture: treat all browser-tool output as untrusted, strip AI-generated fields before classifying, chunk large pages and flag the page if any chunk is flagged, run detection in parallel with planning, and replace flagged tool output with a placeholder — [arXiv 2511.20597](https://arxiv.org/html/2511.20597)
- 2026-10-12, BrowseSafe++: 38,675 attack/control page pairs, 12 website types, 24 attack types, 18 injection locations, text and screenshot views. Two 0.8B detectors (text, screenshot) reportedly beat a frontier-model detector on F1. Attacks that "succeed on only a few percent of tasks" when replayed reach up to 95.41% after BrowseSafe-Adapt revises them using agent feedback — [arXiv 2610.17457](https://arxiv.org/abs/2610.17457)

**Documented attacks on shipped products**
- 2025-08 (Brave): Perplexity Comet's "Summarize the current webpage" acted on instructions hidden behind a Reddit spoiler tag. It extracted the user's email address and a one-time passcode and exfiltrated them. Root cause: Comet fed page content to the LLM without separating it from user instructions — [Brave](https://brave.com/blog/comet-prompt-injection/); fix completeness disputed — [The Register](https://www.theregister.com/2025/08/20/perplexity_comet_browser_prompt_injection/)
- 2025-10-21 (Brave): "unseeable" injections in screenshots (faint text that the model reads through OCR) against Comet's screenshot feature, plus attacks on Fellou. Brave calls it "a systemic challenge facing the entire category of AI-powered browsers" and recommends isolating agentic browsing from regular browsing and starting agentic actions only on explicit user invocation. Timeline: found 2025-10-01, notice to Perplexity 2025-10-02, disclosed 2025-10-21 — [Brave](https://brave.com/blog/unseeable-prompt-injections/); [Simon Willison](https://simonwillison.net/2025/Oct/21/unseeable-prompt-injections/)
- 2025-10 (secondary): NeuralTrust showed that a string disguised as a URL pasted into the Atlas omnibox was treated as high-trust user intent. LayerX showed a CSRF that writes instructions into ChatGPT's persistent memory, abusing the default logged-in state. LayerX also claimed Atlas blocked only 5.8% of 103 malicious pages, against 47% for Chrome and 53% for Edge. That is a vendor test of phishing protection, not of injection — [The Hacker News (secondary)](https://thehackernews.com/2025/10/new-chatgpt-atlas-browser-exploit-lets.html); [ITPro (secondary)](https://www.itpro.com/security/cyber-researchers-have-already-identified-several-big-security-vulnerabilities-on-openais-atlas-browser)

**Academic and government benchmarks**
- WASP (2025-04-22, v3 2025-05-16; code under facebookresearch): 21 injection tasks on simulated GitLab and Reddit (VisualWebArena). Attacks "partially succeed in up to 86%" of cases, but agents often fail to finish the attacker's goal, which the authors call "security by incompetence" — [arXiv 2504.18575](https://arxiv.org/abs/2504.18575)
- VPI-Bench (2025-06-03; v2 2026-03-01, ICLR 2026): 306 visual prompt injection cases across five platforms. Computer-use agents deceived at up to 51%, browser-use agents at up to 100% on some platforms. System-prompt defenses gave "limited improvements" — [arXiv 2506.02456](https://arxiv.org/abs/2506.02456)
- Agent Security Bench (2024-10, ICLR 2025): 10 scenarios, more than 400 tools, 27 attack and defense methods, 13 LLM backbones. Highest average attack success 84.30%; defenses show "limited effectiveness". Not browser-specific — [arXiv 2410.02644](https://arxiv.org/abs/2410.02644)
- NIST CAISI on AgentDojo: the strongest baseline attack reached 11%; novel attacks built for the model reached 81%. Repeated attempts raise measured success, so CAISI recommends multi-attempt evaluation. Improvements open-sourced as agentdojo-inspect — [NIST CAISI blog](https://www.nist.gov/blogs/caisi-research-blog/insights-ai-agent-security-large-scale-red-teaming-competition); single- versus multi-attempt detail from [CSA research note (secondary)](https://labs.cloudsecurityalliance.org/research/csa-research-note-nist-caisi-ai-agent-security-agenda-2026-2/)
- 2026-03-16, Gray Swan / CAISI / UK AISI public competition: 464 participants, 272,000 attempts, 13 frontier models, 41 scenarios (tool calling, coding, computer use), 8,648 successful attacks. Per-model success ranged from 0.5% (Claude Opus 4.5) to 8.5% (Gemini 2.5 Pro). "All models proved vulnerable." Universal attacks transferred across 21 of 41 behaviors. Capability correlated only weakly with robustness — [arXiv 2603.15714](https://arxiv.org/abs/2603.15714)
- 2026-06-12, SOPGuard (Wang, Song, Gong et al.): enforces a same-origin policy on agent-triggered cross-origin data flows, implemented in the open-source BrowserOS, with a SOPBench benchmark. The abstract claims small overhead and preserved utility but gives no numbers — [arXiv 2606.14027](https://arxiv.org/abs/2606.14027)
- Search surfaced PRUDENTIA (claims to block all WASP attacks) and MMA-SafetyBench (visual task hijacking, 2026-10); neither was read — [arXiv 2602.11416](https://arxiv.org/pdf/2602.11416); [arXiv 2610.19384](https://arxiv.org/pdf/2610.19384)

### Inferences
- The figures are not comparable across sources. Vendor numbers use internal adaptive attackers with fixed budgets; BrowseSafe++ and CAISI show that adaptive, model-specific attacks multiply success by roughly 7× (CAISI, 11%→81%) or more (BrowseSafe++, a few percent→95%). Plan for the adaptive number.
- Detection classifiers help, but none is close to complete: the best BrowseSafe recall is 0.841. A classifier is one layer, not a boundary. BrowseSafe's "replace flagged output with a placeholder" is a cheap pattern to copy into our harness's after-tool-call hook.
- Visual and screenshot channels (VPI-Bench, Brave's "unseeable" injections) mean text sanitising alone does not cover a screenshot-driven agent.
- For the coding agent, browsing docs and issues is the common case. The WASP setting (GitLab issues carrying injections) maps directly onto a coding agent that reads issue trackers.

### Gaps
- OpenAI published no Atlas attack-success figures that I could find; the hardening post could not be fetched (403).
- No primary source found for the 0–0.3% / Opus 5 Claude in Chrome GA figures; treat them as unverified.
- Full per-model tables for VPI-Bench, SOPGuard and BrowseSafe++ were not read (abstracts only).
- A search summary claimed OpenAI's Atlas launch page now says Atlas is deprecated. This was not checked and needs a primary check before anyone relies on it.

## Design patterns: trifecta, Rule of Two, CaMeL, confirmation, allowlists, read-only, logged-out mode, profiles

### Takeaway
The architectural patterns converge on one rule: an agent that reads untrusted web content must not hold private data and an exfiltration channel at the same time, unless a deterministic, non-LLM gate decides each consequential action. Vendors carry this out with origin sets and allowlists, logged-out or credential-free modes, separate profiles, and confirmations for sensitive steps. CaMeL shows the provable version costs about 7 points of utility on AgentDojo.

### Cited Findings
- Lethal trifecta (2025-06-16): "Access to your private data", "Exposure to untrusted content" and "The ability to externally communicate in a way that could be used to steal your data". Any tool that can make an HTTP request, including image loads and links the user clicks, is an exfiltration channel. There is "no way to reliably prevent" the attack; "95%" guardrail claims are "very much a failing grade". Advice: constrain the agent once it has seen untrusted input — [Simon Willison](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/)
- Meta's Agents Rule of Two (2025-10-31): within a session, an agent "must satisfy no more than two" of [A] "process untrustworthy inputs", [B] "access to sensitive systems or private data" and [C] "change state or communicate externally". Meta's browsing research assistant is [AC]; to avoid [B] it runs "in a tightly restricted sandbox with no pre-loaded session data" — [Meta AI](https://ai.meta.com/blog/practical-ai-agent-security/)
- CaMeL (2025-03-24, Google DeepMind and ETH authors including Debenedetti, Carlini and Tramèr): separates control flow from data flow, so untrusted data cannot change the program. It solves 77% of AgentDojo tasks with provable security against 84% undefended — [arXiv 2503.18813](https://arxiv.org/abs/2503.18813)
- Google Chrome (2025-12-08): a "User Alignment Critic" is "a separate model built with Gemini that acts as a high-trust system component". It is "architected to see only metadata about the proposed action", vets each action after planning, and sends repeated rejections back to the user. "Origin Sets" split read-only origins, from which "Gemini is permitted to consume content" (an iframe from an unlisted origin is hidden from the model), from read-writable origins where the agent "is allowed to actuate". New origins are checked for relevance by a variant of the critic. A deterministic list triggers confirmation before banking and medical sites; payments and sending messages pause for the user — [Google blog](https://blog.google/security/architecting-security-for-agentic/); gating functions "not exposed to untrusted web content" per [9to5Google (secondary)](https://9to5google.com/2025/12/08/gemini-chrome-agentic-security/)
- OpenAI Atlas (2025-10-22): "logged out mode" lets the agent act "without access to your credentials"; "logged in mode" is "most appropriate for well-scoped actions on very trusted sites". "Watch mode" on sensitive sites "requires you have the tab active". Willison found that neither GitHub nor a bank triggered watch mode — [Simon Willison](https://simonwillison.net/2025/Oct/22/openai-ciso-on-atlas/). At launch the agent could not run code, download files or access the user's system — [Campus Technology (secondary)](https://campustechnology.com/articles/2025/10/27/openai-launches-ai-powered-web-browser-built-around-user-context.aspx)
- Claude in Chrome (current, undated): blocks adult and pirated sites; asks before financial sites; confirms downloads and entry of sensitive information; offers a "Manually approve" mode, though Cowork defaults to "Automatically approve" with per-action risk screening. Claude cannot trade stocks, bypass CAPTCHAs, input sensitive data or scrape faces. Team and Enterprise admins can set allowlists and blocklists; the extension is off by default for HIPAA organizations. Users are advised to run it in "a separate browser profile without access to banking, healthcare, or government accounts" and not to open the side panel on sensitive pages, because sessions are saved — [Claude Help Center](https://support.claude.com/en/articles/12902428-use-claude-in-chrome-safely)
- Brave (2025-10-21): isolate agentic browsing from regular browsing and start agent actions only on explicit user invocation — [Brave](https://brave.com/blog/unseeable-prompt-injections/)
- OWASP LLM01:2025 mitigations: constrain behavior; validate output formats with deterministic code; filter input and output; least privilege (the app holds its own tokens, and extended functions are handled in code, not by the model); human approval for high-risk actions; segregate and label external content; adversarial testing. Scenario #2 is a webpage summary that inserts an exfiltrating image URL — [OWASP GenAI LLM01](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)

### Inferences
- Cheapest structure for our coding agent: run research browsing as [AC], with a fresh, empty, credential-free browser context per task and read-only origins. A separate, narrowly scoped [BC] path takes no untrusted input, for example pushing a PR through the GitHub API instead of the browser. This matches ADR 0036 (loop outside the sandbox, PR approval as the confirmation step).
- Google's split (a critic that sees only action metadata, plus origin sets computed outside the model's reach) is the most concrete published browser-specific design. Origin sets map naturally onto a per-task egress allowlist enforced in the network layer.
- Confirmation prompts suffer approval fatigue, and auto-approve defaults (Cowork) show vendors trading them away. Reserve confirmations for a deterministic list of action classes: submit, purchase, send, download, credential use.

### Gaps
- No public numbers on how much the Rule of Two, origin sets or the User Alignment Critic each reduce attack success.
- No independent evaluation of CaMeL-style planners on live browser tasks (as opposed to AgentDojo) was found in this pass.

## Credentials and authentication

### Takeaway
The consensus pattern is that the model never sees secrets. The harness or a password-manager extension injects credentials into the page after human approval, and persisted cookies live in an encrypted, per-site browser context held by the browser host. Web Bot Auth signs requests to say who the agent operator is, but it does not authorise anything. As of November 2026 it is an IETF working-group draft (`draft-ietf-webbotauth-httpsig-protocol-01`), not an RFC.

### Cited Findings
- 1Password Secure Agentic Autofill (2025-10-08): the 1Password extension fills credentials in a Browserbase session "without ever being able to see or handle the credentials themselves", and injects them "if, and only if, the human approves". Credentials are not shared with the LLM or written to Browserbase logs, and Browserbase has no vault access — [1Password blog](https://1password.com/blog/closing-the-credential-risk-gap-for-browser-use-ai-agents); [1Password press](https://1password.com/press/2025/oct/browserbase-ai-security-partnership). Availability at launch was early access or open beta for Enterprise; the sources differ — [SiliconANGLE (secondary)](https://siliconangle.com/?p=715038)
- Google Chrome (2025-12-08): "the model does not have direct access to stored passwords"; sign-in goes through Google Password Manager after the user confirms — [Google blog](https://blog.google/security/architecting-security-for-agentic/)
- OpenAI Operator (2025-01): "takeover mode" hands control to the user to enter logins or payment details, and Operator does not collect or screenshot what the user types there — [OpenAI, Introducing Operator](https://openai.com/blog/introducing-operator) (via secondary summary; not fetched)
- Claude in Chrome refuses to input sensitive data or bypass CAPTCHAs — [Claude Help Center](https://support.claude.com/en/articles/12902428-use-claude-in-chrome-safely)
- Browserbase Contexts persist the Chromium user data directory (cookies, localStorage, IndexedDB, service workers, autofill Web Data, permissions); they do not persist sessionStorage or the HTTP cache. "Contexts are uniquely encrypted at rest", with no method given. Docs advise one context per site and login, no concurrent sessions on one context, treating contexts as sensitive, and `persist: false` for read-only reuse. Contexts last until deleted — [Browserbase docs](https://docs.browserbase.com/features/contexts)
- Web Bot Auth: Cloudflare's signed-agents class (2025-08-28) covers user-directed agents whose platform signs HTTP requests with Web Bot Auth. First cohort: ChatGPT agent, Goose, Browserbase, Anchor Browser — [Cloudflare blog](https://blog.cloudflare.com/signed-agents/). It builds on RFC 9421 HTTP Message Signatures, with keys published at `/.well-known/http-message-signatures-directory` — [Cloudflare, Web Bot Auth](https://blog.cloudflare.com/web-bot-auth); OpenAI's cloud browser signs with RFC 9421 and sends `Signature`, `Signature-Input` and `Signature-Agent` headers — [OpenAI Help](https://help.openai.com/en/articles/11845367-chatgpt-works-cloud-browser-allowlisting)
- IETF webbotauth WG documents as of 2026-11-18. WG document: `draft-ietf-webbotauth-httpsig-protocol-01` (2026-10-29). Individual drafts include `draft-meunier-webbotauth-registry-04` (signature agent card, 2026-10-27), `draft-rescorla-anonymous-webbotauth-01` (2026-07-19), `draft-vilgalys-webbotauth-signed-agent-metadata-00` (2026-11-02), `draft-meunier-webbotauth-capacity-management-00` (PACE, 2026-11-15) and `draft-singh-webbotauth-hosted-directories-00`. The datatracker lists no RFCs — [IETF datatracker](https://datatracker.ietf.org/wg/webbotauth/documents/)
- AWS AgentCore Browser: Web Bot Auth is in preview and is "a mechanism for signing requests and identifying the sender", not a blocking layer. It and session replay depend on extensions that run only in the default browser context — [AWS docs](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/browser-tool.html); detail from [hidekazu-konishi.com (secondary)](https://hidekazu-konishi.com/entry/what_agentcore_browser_keeps_and_where_its_traffic_goes.html)
- OWASP LLM01: give the application its own API tokens and handle extended functions in code, not through the model — [OWASP GenAI](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)

### Inferences
- Order of preference for our agents: (1) an OAuth or API token held by the harness outside the sandbox, which fits ADR 0036's no-credentials-in-sandbox rule; (2) a harness-side credential injection step (CDP fill or a password-manager extension) gated by human approval, with the injected field values redacted from screenshots and DOM before the model sees them; (3) a human takeover for login, 2FA and CAPTCHA.
- A persisted cookie jar is a credential. If a hosted browser keeps it (Browserbase context), a prompt-injected agent in that context can use the session even though it never saw a password. Scope contexts per site and per tenant, and default to `persist: false`.
- Web Bot Auth helps sites admit our agent past bot walls. It does not protect us. For the platform, each tenant's agents would sign as the platform unless the drafts' per-agent metadata matures.

### Gaps
- Current (Nov 2026) general availability and pricing of 1Password Agentic Autofill outside Browserbase not checked.
- How 1Password or Browserbase keep injected values out of later screenshots and DOM reads is not documented in the sources read.

## Egress and isolation

### Takeaway
A browser that renders attacker pages is an SSRF and exfiltration primitive. The controls that hold regardless of model behavior are network-level: deny private ranges, link-local addresses and the cloud metadata endpoint, allowlist by resolved IP, and give each task a fresh isolated browser. Exfiltration needs only a URL, so per-task egress allowlists (origin sets) matter more than content filters.

### Cited Findings
- Image loads and links are exfiltration vectors; vendors have fixed instances by closing the channel — [Simon Willison](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/); OWASP scenario of an injected image URL leaking a conversation — [OWASP GenAI](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)
- Comet exfiltrated an email address and OTP through an attacker-controlled destination — [Brave](https://brave.com/blog/comet-prompt-injection/)
- Anthropic's browser-specific attacks included hidden form fields and injections in URL text — [Claude blog](https://claude.com/blog/claude-for-chrome); Anthropic names form submission, downloads and data forwarding as the high-impact actions — [Anthropic](https://www.anthropic.com/research/prompt-injection-defenses)
- SOPGuard argues agents break the browser's same-origin assumptions by carrying data between origins, and enforces SOP on agent data flows — [arXiv 2606.14027](https://arxiv.org/abs/2606.14027)
- Secondary: rendering untrusted pages server-side is an SSRF primitive. The metadata endpoint `169.254.169.254` returns temporary IAM credentials. Hostname denylists fall to DNS rebinding and TOCTOU, so pin to the resolved IP or fetch out of process. Network isolation is the strongest control — [modpagespeed blog (secondary)](https://modpagespeed.com/blog/air-gapped-headless-fetch-ssrf-pinning/); [decryptiondigest (secondary)](https://www.decryptiondigest.com/blog/ai-agent-egress-proxy-ssrf-prevention-default-deny)
- Secondary: CVE-2026-5607, an SSRF in `mcp-browser-agent` up to 0.8.0 that reaches internal services and cloud metadata — [SentinelOne (secondary, not checked on NVD)](https://www.sentinelone.com/vulnerability-database/cve-2026-5607/)
- AWS AgentCore Browser runs each session in its own container. The managed `aws.browser.v1` runs only in PUBLIC network mode; VPC mode and S3 session recording need a custom browser with its own IAM role — [AWS docs](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/browser-tool.html); [AWS session docs](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/browser-session-characteristics.html); PUBLIC-only detail from [hidekazu-konishi.com (secondary)](https://hidekazu-konishi.com/entry/what_agentcore_browser_keeps_and_where_its_traffic_goes.html)
- Meta: run browsing agents "in a tightly restricted sandbox with no pre-loaded session data" — [Meta AI](https://ai.meta.com/blog/practical-ai-agent-security/)
- Downloads: Claude in Chrome confirms downloads — [Claude Help Center](https://support.claude.com/en/articles/12902428-use-claude-in-chrome-safely); the Atlas agent could not download files at launch — [Campus Technology (secondary)](https://campustechnology.com/articles/2025/10/27/openai-launches-ai-powered-web-browser-built-around-user-context.aspx)

### Inferences
- For the platform, per-tenant isolation means one browser per tenant task, never a shared browser pool with shared contexts. Browser egress should go through a per-tenant proxy that denies RFC 1918, link-local, loopback and metadata addresses, with an allowlist derived from the task. This applies ADR 0042's rule that generated code runs only in a fresh sandbox.
- Run the browser in the sandbox (no credentials) or in a hosted browser, and keep the loop outside. Our harness should treat navigation as a tool call whose URL passes a deterministic allowlist check in a before-tool-call hook, enforced again at the proxy.
- Quarantine downloads: store them as inert blobs and do not open or execute them without a separate approval.

### Gaps
- No primary vendor documentation found on how Browserbase, Steel or Cloudflare Browser Rendering block private and metadata ranges; this needs a targeted follow-up.
- No measured data on exfiltration through form GETs or DNS from browser agents.

## Data handling: screenshots, PII, logs, retention

### Takeaway
Browser agents capture screenshots and DOM text full of PII and session data. Vendors keep them longer than chat logs: OpenAI keeps deleted Operator and ChatGPT agent screenshots up to 90 days, against 30 for ChatGPT. Our traces must treat page captures as sensitive tenant data, with redaction and short, explicit retention.

### Cited Findings
- OpenAI may keep deleted Operator chats and screenshots up to 90 days, against 30 days for ChatGPT, citing abuse review (Jan 2025) — [TechCrunch via aggregator (secondary)](https://techcrunch.com/?p=2952436); ChatGPT agent help: deleted chats and screenshots removed "within 90 days" — [OpenAI Help, ChatGPT agent](https://help.openai.com/articles/11752874)
- Operator does not screenshot what the user types in takeover mode — [OpenAI (via secondary summary)](https://openai.com/blog/introducing-operator)
- Claude in Chrome: sessions are saved to history, so do not open the side panel on sensitive pages; not covered by a BAA for HIPAA organizations — [Claude Help Center](https://support.claude.com/en/articles/12902428-use-claude-in-chrome-safely)
- 1Password: credentials are not exposed in Browserbase logs — [1Password blog](https://1password.com/blog/closing-the-credential-risk-gap-for-browser-use-ai-agents)
- AWS AgentCore session replay writes recordings to customer S3 under a customer IAM role; CloudTrail logs API calls — [AWS docs](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/browser-tool.html)
- Browserbase contexts hold autofill data and cookies indefinitely until deleted — [Browserbase docs](https://docs.browserbase.com/features/contexts)

### Inferences
- OTel `gen_ai.*` spans should carry references to screenshot and DOM blobs, not inline content. Blobs go in per-tenant encrypted storage with a TTL. Fields the harness injected (passwords, OTPs) are masked before capture.
- Session recordings and the "replay for debugging" feature conflict with minimal retention. Make recording opt-in per tenant.

### Gaps
- No official guidance found (vendor or standards) on PII redaction in agent screenshots specifically.

## Standards and official guidance (OWASP, NIST, vendors)

### Takeaway
OWASP's LLM01:2025 and the Agentic Top 10 (2025-12-09; ASI01 Agent Goal Hijack) give the checklist. NIST CAISI contributes evaluation methods (adaptive, multi-attempt, AgentDojo-based) rather than controls. Vendor guidance converges on separate profiles, logged-out or credential-free modes, origin allowlists and confirmations.

### Cited Findings
- OWASP Top 10 for LLM Applications 2025, LLM01 Prompt Injection, with its seven mitigations (listed above) — [OWASP GenAI](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)
- OWASP Top 10 for Agentic Applications 2026, published 2025-12-09 by the GenAI Security Project with 100+ contributors. Risks ASI01–ASI10; ASI01 is Agent Goal Hijack. It supplements the LLM Top 10 — [TechRepublic (secondary)](https://www.techrepublic.com/article/news-owasp-ai-agent-risk-list/); [Giskard (secondary)](https://www.giskard.ai/knowledge/owasp-top-10-for-agentic-application-2026)
- NIST CAISI: adaptive, model-specific attacks (11%→81%) and multi-attempt testing for realistic hijacking estimates — [NIST CAISI](https://www.nist.gov/blogs/caisi-research-blog/insights-ai-agent-security-large-scale-red-teaming-competition); large-scale competition with UK AISI and Gray Swan — [arXiv 2603.15714](https://arxiv.org/abs/2603.15714)
- Vendor user guidance: Anthropic (separate profile, trusted sites, manual approve, avoid financial, legal and medical accounts) — [Claude Help Center](https://support.claude.com/en/articles/12902428-use-claude-in-chrome-safely); OpenAI (logged-out mode unless account access is needed; logged-in only for well-scoped tasks on trusted sites) — [Simon Willison quoting OpenAI CISO](https://simonwillison.net/2025/Oct/22/openai-ciso-on-atlas/); Google (origin sets, critic, confirmations, password manager) — [Google blog](https://blog.google/security/architecting-security-for-agentic/); Brave (isolate agentic from regular browsing) — [Brave](https://brave.com/blog/unseeable-prompt-injections/)

### Inferences
- Map our design review onto OWASP ASI01 plus LLM01's mitigations 4–6 (least privilege, human approval, segregating external content). For evaluation, adopt CAISI's method: adaptive attacks with multiple attempts, reporting success at k attempts. Candidate harness suites are AgentDojo (agentdojo-inspect), WASP and BrowseSafe-Bench.

### Gaps
- The full OWASP Agentic Top 10 document (ASI02–ASI10 wording and browser-specific mitigations) was not read from the primary source.
- No NIST control-level publication (for example an SP 800 overlay for agents) was found in this pass; CAISI output found was evaluation-focused.
