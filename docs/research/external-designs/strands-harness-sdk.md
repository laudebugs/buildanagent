# Strands assembles a harness, not a runtime

- **Status:** research report for todo U10 ("Round U" research), 2026-11-18. It compares the Strands Agents harness-sdk with our [harness guide](../../guides/agent-harness.md), our [harness plan](../../plans/build-harness.md) (HD1–HD15) and our eight verified SDK references.
- **Versions checked (as of November 2026):** the `strands-agents/harness-sdk` repo at commit [`84d814b`](https://github.com/strands-agents/harness-sdk/tree/84d814b31810acc8d9f452f6cdd7333d2ed8c223) on `main` (2026-11-18), and the release tag `harness-typescript/v0.4.0` (also `harness-python/v0.4.0`) at commit [`ad1ae00`](https://github.com/strands-agents/harness-sdk/tree/ad1ae00f35a560e492cb061b0103d10771f48cb6) (2026-11-12). Packages: `@strands-agents/harness` and `strands-harness` 0.4.0 (2026-11-12), `@strands-agents/sdk` 1.25.0 and `strands-agents` 1.65.0 (2026-11-13), and `@strands-agents/cli` 0.3.0 (2026-11-10), from the npm and PyPI registries.
- **Evidence:** two research notes, [harness-sdk in depth](notes/harness-sdk-in-depth.md) and [harness-sdk compared with our design](notes/harness-sdk-vs-our-design.md). They cite the repo at `84d814b`, strandsagents.com pages and the registries, all fetched on 2026-11-18. Corrections are logged in [the fact-check log](fact-check-strands-harness-sdk.md).
- **Read, not run:** every Strands claim was re-read against the source at `84d814b`, and against `ad1ae00` wherever 0.4.0 matters. Nothing was installed or run, so every behaviour below comes from source and docs, and the benchmark figures are the vendor's own. Repo content and site pages were read as data, and the instructions they contain were not followed.
- **Recommendation:** add Strands as a ninth verified reference, pinned to `@strands-agents/sdk@1.25.0` and `@strands-agents/harness@0.4.0` from 2026-11-20. Copy its declarative compaction strategies, its `guide` gate outcome and its Cedar policy backend; avoid its defaults.

The Strands Agents "harness-sdk" ([github.com/strands-agents/harness-sdk](https://github.com/strands-agents/harness-sdk)) is the whole Strands **monorepo**, not a separate harness library. It holds the Python and TypeScript SDKs, two thin harness packages (`strands-harness` on PyPI and `@strands-agents/harness` on npm, both 0.4.0, Apache-2.0 and marked Beta on PyPI), the `strands` CLI, an MCP docs server, the docs site and design docs. `create_harness()` and `createHarness()` are factory functions that wire a plain SDK `Agent` with tuned defaults. Those defaults include a Bedrock-hosted Claude model, eight built-in tools with a host shell and file edits, automatic context offloading, and file-backed sessions and memory. The factories add no loop, runtime or protocol of their own, so **Strands is a library plus an assembled harness**.

Measured against our harness guide and plan, Strands shares the SDK-level shapes we chose: one streamed event union, a pluggable sandbox seam, `@modelcontextprotocol/client` 2.x and declarative compaction layers. Its defaults, though, run every tool call on the host with no gate and with the full inherited environment, and its session record is a snapshot overwritten on every message. Six of our earlier Strands claims also needed fact-check rows, which the main fact-check log now holds. In this report, I trace the harness from its factory to its defaults, compare it component by component with our design, and show that **Strands is worth a ninth verified reference for its interfaces, and a warning for its defaults**.

## A 5,900-line factory sits on top of the real SDK

The repository README lays out the monorepo as `harness-py/` ("fully assembled agent via `create_harness()`"), `harness-ts/` (`createHarness()`), `strands-cli/`, `strands-py/`, `strands-ts/`, `strands-mcp/`, `site/` (strandsagents.com), `team/` (governance and design docs) and `test-infra/` ([README.md:52-62](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/README.md#L52-L62)). Design 0009, dated 2026-05-05 and still marked "Proposed", argued for the consolidation because Strands was "spread across 12 repos" ([0009-mono-repository.md:5, 13](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/team/designs/0009-mono-repository.md)). The old `strands-agents/sdk-python` URL now serves the monorepo: on 2026-11-18, `git ls-remote` returned the same HEAD for it as for harness-sdk, while `sdk-typescript` returned a different commit. The likeliest explanation is that `sdk-python` was renamed to `harness-sdk` and `sdk-typescript` was merged in as `strands-ts/`. That explanation is an inference, because the GitHub API and HTML were blocked, so the rename date, star counts and contributor counts remain unknown.

The branding invites confusion, so this report keeps two names apart. The docs call the core SDK itself the "Strands Harness SDK" and the factory output the "Strands harness" ("Strands harness is built on the Strands Harness SDK") ([docs: harness index](https://strandsagents.com/docs/user-guide/harness/index.md)). Here, **the Strands SDK** means `@strands-agents/sdk` 1.25.0 and `strands-agents` 1.65.0, and **the Strands harness** means `@strands-agents/harness` 0.4.0. The harness is a 0.x product, versioned separately, where "Minor (0.X.0)" releases carry "breaking changes" and patches carry features. Python and TypeScript are "versioned and released independently", although both 0.4.0 tags point at commit `ad1ae00` ([docs: versioning](https://strandsagents.com/docs/user-guide/harness/versioning/)). The harness is also young. Its PyPI history starts with a 0.0.0 placeholder and 0.1.0 on 2026-09-21, and it has 11 releases in all ([PyPI](https://pypi.org/pypi/strands-harness/json)).

The factory is thin. `create_harness(*, model, effort, instructions, tools, plugins, mcp_servers, builtin_tools, background_tasks, caching, context_manager, session, skills, memory, builtin_plugins, interventions, **agent_kwargs) -> Agent` ends by constructing `Agent(...)` and returning it ([agent.py:243-261, 535-546](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/harness-py/src/strands_harness/agent.py#L243-L261)). The TypeScript `createHarness(options)` is **async** because it awaits six setup steps: telemetry, the model, MCP servers, built-in tools, memory and interventions. Its `HarnessAgentOptions` extends the SDK's `AgentConfig`, so any field it does not name passes straight through ([agent.ts:75-78, 349-530](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/harness-ts/src/agent.ts#L349-L530)). The Python docstring states the override rule: "an explicit SDK value there (`session_manager`, `memory_manager`, `system_prompt`, ...) always beats the harness sugar". The whole TypeScript harness is **5,890 lines across 25 files** at `84d814b` (5,666 lines across 24 files at 0.4.0), mostly config, model resolution, the subagent tool and the code-execution tool. Almost every capability lives in the SDK: the context manager, interventions, sandbox, sessions, memory, MCP, telemetry and background tasks.

The defaults define what users actually get ([defaults.py](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/harness-py/src/strands_harness/defaults.py#L5-L40); [harness-ts/README.md:58-77](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/harness-ts/README.md#L58-L77)):

| Option | Default |
|---|---|
| `model` | `bedrock/global.anthropic.claude-opus-5` (Opus 5) in 0.4.0 ([tag](https://github.com/strands-agents/harness-sdk/blob/ad1ae00f35a560e492cb061b0103d10771f48cb6/harness-py/src/strands_harness/defaults.py#L5)); `…claude-opus-5-5` (Opus 5.5) on `main`; `effort: "auto"` |
| Built-in tools | `shell, read, write, edit, web_fetch, web_search, programmatic_tool_caller, subagent` (subagent depth 2) |
| `contextManager` / `caching` | `"auto"` / `"auto"` |

| `memory` / `skills` | on: `./.agent/memory`, `./.agent/skills` |
| `builtinPlugins` | `environment` (platform, date, cwd, `AGENTS.md`); `todos` opt-in |

Around the tools, the harness adds a system prompt and a model resolver. Its model-neutral system prompt (`HARNESS_CONTRACT`) covers acting, tools, safety and context management. It tells the model, for example, that "A denied or failed tool call is information" and that `<system-reminder>` tags come from the harness ([prompt.py:3, 27-28](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/harness-py/src/strands_harness/prompt.py)). The model layer resolves seven `"provider/model"` aliases: bedrock, bedrock-mantle, anthropic, openai, google, ollama and litellm. It maps one `effort` knob (`auto` through `max`) onto each family's reasoning settings, and it picks a small model per provider for fetch summaries and memory extraction ([models.py:71-77, 376-393](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/harness-py/src/strands_harness/models.py#L376-L393)). The docs index names only Bedrock, Anthropic, OpenAI, Google and Ollama, but the model page lists all seven aliases ([model.mdx:21-22](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/site/src/content/docs/user-guide/harness/configure/model.mdx#L21-L22)).

AWS coupling sits in the defaults and dependencies, not in the architecture, and it grew after 0.4.0. On `main`, boto3, Anthropic's Bedrock client and AgentCore `InvokeWebSearch` are hard dependencies of the Python harness, and AgentCore backs `web_search` on Bedrock ([harness-py/pyproject.toml:29-42](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/harness-py/pyproject.toml#L29-L42)). In 0.4.0, the Python harness depends only on `strands-agents[otel]>=1.64.0`, `pydantic-monty` and `pydantic`, and `web_search` stays off on the default Bedrock model unless Exa is chosen ([pyproject.toml at `ad1ae00`](https://github.com/strands-agents/harness-sdk/blob/ad1ae00f35a560e492cb061b0103d10771f48cb6/harness-py/pyproject.toml#L32-L36); [harness-ts/README.md:326-327 at `ad1ae00`](https://github.com/strands-agents/harness-sdk/blob/ad1ae00f35a560e492cb061b0103d10771f48cb6/harness-ts/README.md#L326-L327)). Deployment is the SDK's story (Lambda, Fargate, EKS, AgentCore), and the docs say to build the agent "with `create_harness()` where the guide builds one with `Agent()`" ([production.mdx:24, 42](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/site/src/content/docs/user-guide/harness/production.mdx)).

Interfaces live outside the harness packages. The `strands` CLI wraps the same agent with an Ink TUI, plain mode, print mode and an **ACP server** over newline-delimited stdin/stdout, built on `@agentclientprotocol/sdk` 1.3.0 ([strands-cli/README.md:120-128](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/strands-cli/README.md#L120-L128); [strands-cli/package.json:64](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/strands-cli/package.json#L64)). The SDK also speaks A2A through a peer dependency on `@a2a-js/sdk`. Evals live in a separate, Python-only `strands-agents-evals` package ([evals-sdk index](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/site/src/content/docs/user-guide/evals-sdk/index.mdx); [PyPI](https://pypi.org/pypi/strands-agents-evals/json)). The harness is therefore a set of choices over an SDK that already does the work.

## Component by component, Strands matches our SDK and misses our safety floor

The table maps Strands onto the components of our [harness guide](../../guides/agent-harness.md) and [harness plan](../../plans/build-harness.md). Its verdicts summarise the four sections that follow.

| Component | Strands (SDK + harness) | Ours | Verdict |
|---|---|---|---|
| Loop | SDK `Agent`; harness only assembles | Stateless loop, explicit stop conditions | Aligned |
| Session | Mutable `snapshot_latest.json` plus optional UUIDv7 immutable checkpoints; file or S3; single writer, no cross-process lock | Append-only typed JSONL tree, HEAD, lease lock (HD1, HD2) | Ours fits our goals better |
| Context | `Offload.truncate/summarize/drop(...).when({...})` pipeline; removed messages go to a stash behind a retrieval tool and leave a placeholder | Five removable layers; every compaction an appended entry (HD3) | Copy the shape, not the mechanics |
| Approvals | Ordered intervention handlers: `proceed/deny/guide/confirm/transform`; `ask`, `smart` classifier, rubric, Cedar; off by default; unsigned interrupts | Deny-first, fail-closed, HMAC-signed approvals (HD5); no classifier allow outside the host callback (HD12, ADR 0029) | Ours safer; copy `guide` and Cedar |
| Sandbox | Six-operation `Sandbox` (local, Docker, SSH); default is the host with `...process.env` | Separate sandbox and approval policies; srt/Docker default (HD4); credential proxy (HD15) | Copy the interface, not the default |
| MCP | `@modelcontextprotocol/client` 2.x, `<server>_<tool>` names, non-fatal failures, elicitation, tasks extension | Same client base behind `McpConnection` (HD14), canonical-name registry, exposure modes | Aligned; our registry closes their collision gap |
| Hooks | 17 hook events, plus interventions, plus middleware | Six interceptors plus observers (ADR 0006) | Theirs has more surface than we want |
| Streaming | One `AgentStreamEvent` union of 16 classes | One closed, layered union with authoritative end events | Aligned |
| Telemetry | `invoke_agent`/`chat`/`execute_tool` spans with `gen_ai.*` attributes; content recorded once on | Projection of the log, content off, cost attributes (HD7) | Copy "unset means off"; avoid content-on |
| Evals | Separate Python SDK; vendor benchmark on Harbor | Inspect plus a mini-swe-agent baseline (HD8) | Complementary |
| Test model | `MockMessageModel` only in internal fixtures | Public strict `ScriptedModel` | Strands lacks one |
| Protocol | None; the CLI speaks ACP and the SDK speaks A2A | One typed JSON-RPC 2.0 protocol (HD6) | Different; ACP as an adapter |

### Sessions and compaction trade history for simplicity

Strands' `SessionManager` keeps "A single mutable snapshot that is overwritten on each save" plus "Append-only snapshots with unique IDs (UUID v7), created only when `snapshotTrigger` fires" ([session-manager.ts:28-37](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/strands-ts/src/session/session-manager.ts#L28-L37)). Writes go through a temp file and a rename ([file-storage.ts:165-175](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/strands-ts/src/session/file-storage.ts#L165-L175)). The docs are candid about concurrency: "Concurrency is single-writer … The built-in managers take no distributed lock, and the in-process guard cannot see a writer running elsewhere" ([checkpoints-and-memory.mdx:118-125](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/site/src/content/docs/user-guide/harness/configure/checkpoints-and-memory.mdx#L118-L125)). The harness saves per message, so "Text still streaming and unfinished tool calls are not yet saved" ([harness-ts/README.md:392-393](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/harness-ts/README.md#L392-L393)). Strands has therefore chosen the run-state-blob design that [our harness guide's §2](../../guides/agent-harness.md#2-the-session-log-should-be-one-append-only-tree-of-typed-entries-with-head-a-writer-lock-and-pauses-as-entries) rejects, which places it closest to OpenAI's `RunState` among our eight.

Compaction is where the snapshot design costs most. The `"auto"` preset truncates tool results over **1,500 tokens** and summarizes at **85% utilization, preserving 4 recent messages**. The `"agentic"` preset gives the model context-management tools, truncates at 8,000 tokens and summarizes only when the window is full ([context-manager.ts:45-54](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/strands-ts/src/context-manager/context-manager.ts#L45-L54)). Trimming calls `messages.splice(...)`, writes the removed messages to a stash and inserts a placeholder that carries the stash reference ([message-trimming.ts:175-207](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/strands-ts/src/context-manager/message-trimming.ts#L175-L207)). The agent can read stashed originals back through a retrieval tool ([stash.ts](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/strands-ts/src/context-manager/stash.ts#L1-L8)), and the harness keeps the stash as files in the session's folder ([harness-ts agent.ts:457-459](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/harness-ts/src/agent.ts#L457-L459)). The next snapshot then overwrites the old one, so **the session record keeps only the placeholder**, and the original survives only in a side store. Strands also warns that its named strategy presets "are internal defaults and may change between releases" ([presets.ts:1-9](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/strands-ts/src/context-manager/presets.ts#L1-L9)).

The Strands strategies map closely onto our layers. Truncate plus stash is our layer 1, dropping stale results is a destructive version of layer 2 masking, summarize is layer 3, and `overflowProtection` is a drop-based layer 5. No explicit mid-turn layer 4 was found.

### Approvals and sandbox pair good interfaces with permissive defaults

The SDK's interventions are well designed. Handlers run in registration order "with short-circuiting on Deny (and denied Confirms) and accumulation for Guide" ([registry.ts:21-28](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/strands-ts/src/interventions/registry.ts#L21-L28)). A `Guide` after a model call discards the response, and "the model retries with the feedback injected as a user message" ([actions.ts:58-78](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/strands-ts/src/interventions/actions.ts#L58-L78)). A handler that throws blocks execution by default, because `onError` defaults to `'throw'` ([handler.ts:15, 47-48](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/strands-ts/src/interventions/handler.ts#L15)).

The harness defaults, however, reverse our principles at four points. First, no gate is installed. Second, the `smart` preset lets an LLM classifier decide: "low-risk calls run on their own and risky ones are escalated to the human" ([hitl.ts:195-196](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/strands-ts/src/vended-interventions/hitl/hitl.ts#L195-L196)). A handler built with `enableTrust: true` goes further, because a "trust" reply "disables argument-level risk classification for that tool name" for the session, so a trusted `shell` would cover every command ([hitl.ts:90-101](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/strands-ts/src/vended-interventions/hitl/hitl.ts#L90-L101)). Trust is off by default and the presets leave it off. Third, pending approvals resume as `interruptResponse` content blocks ([interrupt.ts:1-10](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/strands-ts/src/interrupt.ts#L1-L10)), and a grep of the whole TypeScript SDK source found no HMAC or signing code, though a grep cannot prove absence. Fourth, the CLI gates only its Ink mode. Its plain, print and ACP-server modes "have no permission UI and therefore use stock harness tool behavior", so they run every call ungated ([strands-cli/README.md:424-428](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/strands-cli/README.md#L424-L428)). [Our guide's §5](../../guides/agent-harness.md#5-the-permission-pipeline-should-be-ordered-deny-first-and-fail-closed-and-its-approvals-should-be-signed-entries) makes a call with no matching rule an `ask` interactively and a `deny` headless.

The sandbox follows the same pattern: a good interface over a weak default. `abstract class Sandbox` exposes `executeStreaming`, `executeCodeStreaming`, `readFile`, `writeFile`, `removeFile` and `listFiles` ([base.ts:42-120](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/strands-ts/src/sandbox/base.ts#L42-L120)). Every harness tool routes through it, including `web_fetch`, which runs `curl` inside the sandbox by default "so the sandbox's network controls apply" ([harness-ts types/agent.ts:23-40](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/harness-ts/src/types/agent.ts#L23-L40)). The Node default is `NotASandboxLocalEnvironment`, which "Runs on the host with no isolation" and builds each child environment from `{ ...process.env }` ([not-a-sandbox-local-environment.ts:31-53](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/strands-ts/src/sandbox/not-a-sandbox-local-environment.ts#L31-L53)). Strands has no credential boundary, no egress proxy and no split between a sandbox policy and an approval policy. Its own CLI README says the approval layer "is not an operating-system sandbox" ([strands-cli/README.md:424](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/strands-cli/README.md#L424)). Strands therefore belongs in our deep comparison's [list of SDKs whose defaults reach outside the process](../../comparison/deep-comparison.md#six-of-eight-sdks-have-a-default-that-reaches-outside-your-process), beside the Claude and Copilot runtimes that inherit the parent environment. Its Bedrock default also picks up ambient AWS credentials, much as Pi picks up ambient cloud credentials.

### Telemetry, MCP and streaming already agree with our plan

The harness's telemetry rule matches ours: "Unset means off — the harness does not honor OTEL's spec default of `otlp`", and setup runs once per process ([harness-ts telemetry.ts:1-15](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/harness-ts/src/telemetry.ts#L1-L15)). The Python harness also leaves an existing tracer provider, such as ADOT on AgentCore Runtime, untouched ([telemetry.py:12-17](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/harness-py/src/strands_harness/telemetry.py#L12-L17)). Once telemetry is on, though, the SDK writes tool arguments and messages as span events or attributes, with no content gate in that code path ([tracer.ts:452-478](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/strands-ts/src/telemetry/tracer.ts#L452-L478)). Its own comment tells users to "suppress span content at the exporter or processor" when content is a concern ([tracer.ts:658-660](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/strands-ts/src/telemetry/tracer.ts#L658-L660)).

MCP confirms our HD14 choice of client, because both designs build on `@modelcontextprotocol/client` 2.x ([strands-ts/package.json:370](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/strands-ts/package.json#L370)). Strands makes a failed server non-fatal by default. It admits, however, that MCP names are "only known once a client connects", so a server can still clash with a built-in ([harness-ts agent.ts:498-500](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/harness-ts/src/agent.ts#L498-L500)). Our single registry closes that gap by design. Streaming agrees too. The 16-class `AgentStreamEvent` union mirrors our closed event union, with `ContentBlockEvent` and `ModelMessageEvent` in the role of our end events ([types/agent.ts:699-715](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/strands-ts/src/types/agent.ts#L699-L715)).

### Among our eight, Strands has Pi's shape and OpenAI's state model

Our eight verified references are the Claude Agent SDK, Pi, OpenAI Agents, the Vercel AI SDK, LangChain, Cloudflare Agents, Google ADK and the Copilot SDK ([feature table](../../comparison/feature-table.md)). Strands resembles **Pi** in architecture: an in-process library loop with an assembled coding agent, a CLI, a skills format and a sandbox seam on top. It resembles **OpenAI Agents** in state: a run-state snapshot, per-call interrupts that resume as data, and a home cloud. Its policy breadth is Claude-like, with Cedar, a classifier and ordered gates. Its default safety posture, though, sits at Pi's end of our [deep comparison](../../comparison/deep-comparison.md#safety-defaults-range-from-six-permission-steps-to-none): host shell and file tools that run with no gate and no isolation, plus an inherited environment.

## Seven ideas to copy, seven defaults to avoid

The ideas worth copying are specific, and each fits a slot our plan already has:
1. **The declarative strategy shape**, `Offload.summarize("*").when({contextUtilization: "85%", preserveRecent: 4})`, turns each compaction layer into a removable, ablatable value, which is what [our guide's §11](../../guides/agent-harness.md#11-every-component-should-be-removable-because-the-value-of-harness-scaffolding-decays-as-models-improve) asks for. The stash-plus-retrieval-tool pattern fits our layer 1 spill-to-file.
2. **`guide` as a first-class gate outcome**, including after the model call. Our `afterModelCall` interceptor can replace a response, but it cannot discard one and retry with feedback.
3. **Cedar as a declarative policy backend** behind our rule step.
4. **Bypass mode only from user-level config.** The CLI reads `~/.strands/cli.toml` and "does not load a project config file that could silently enable bypass mode" ([strands-cli/README.md:407-418](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/strands-cli/README.md#L407-L418)), which matches our project-trust gate.
5. **The six-operation `Sandbox` interface**, with code execution as an operation and honest naming of the no-isolation tier: `NotASandboxLocalEnvironment` warns in its own name.
6. **Telemetry where unset means off.**
7. **Per-server non-fatal MCP failure**, combined with collisions between consumer tools and built-ins that throw, so that nothing "is silently shadowed" ([harness-ts/README.md:212-214](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/harness-ts/README.md#L212-L214)).

The seven defaults to avoid are the mirror image:
1. an overwritten snapshot as the session record;
2. compacted originals kept only in a side stash;
3. no gate by default, and CLI modes that run ungated;
4. classifier allows, and tool-wide trust that can widen to `shell`;
5. pauses resumed from unsigned state;
6. an unconfined default sandbox that inherits `process.env`;
7. content recorded in telemetry once it is on.

One documented hole also deserves a test in our plan. Calls made from inside `programmatic_tool_caller` are gated by interventions, but "those inner calls fire the agent's hooks but not tool middleware or guards" ([harness-ts/README.md:505-513](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/harness-ts/README.md#L505-L513)). Our plan routes code-initiated calls through the same pipeline (N40), so a test should prove that every gate fires for them.

Several more features are worth noting rather than copying now, because our staged path defers memory, subagents and code mode until an eval justifies them ([harness guide §11](../../guides/agent-harness.md#11-every-component-should-be-removable-because-the-value-of-harness-scaffolding-decays-as-models-improve)). Long-term memory extracts facts "every few turns on a small, cheap model" into markdown, with a `search_memory` tool ([harness-ts/README.md:395-421](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/harness-ts/README.md#L395-L421)). `programmatic_tool_caller` runs model-written Python in Monty, "a language-level sandbox, not an OS-level one", with 60-second and 256 MB limits ([programmatic_tool_caller.py:1-58](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/harness-py/src/strands_harness/tools/programmatic_tool_caller.py#L1-L58)). The delegation rule is one we could adopt if subagents arrive: a child "can never gain a capability the parent lacks", inherits interventions and runs at bounded depth ([harness-ts/README.md:229-236](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/harness-ts/README.md#L229-L236)). Skills load through a `skills` tool rather than a file read, which is easier to gate and log.

Two outside pieces are worth watching as well. ACP is a credible editor transport, but as an adapter over our HD6 protocol, because ACP has no operations for session trees or signed approvals (an inference, not checked against the ACP spec). Harbor is a second cross-harness eval runner beside Inspect. The Strands team's 94,000-trial Harbor benchmark claims the lowest estimated cost (~$0.20 per trial) and the highest accuracy (71.02%) on OpenAI models ([blog:93](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/site/src/content/blog/we-ran-94000-trials-to-measure-the-cost-of-harness-choice.mdx#L93)). That claim is self-reported, it uses estimated rather than billed costs, and it omits a mini-swe-agent baseline ([blog:39-45](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/site/src/content/blog/we-ran-94000-trials-to-measure-the-cost-of-harness-choice.mdx#L39-L45)).

## A ninth verified reference is feasible from 2026-11-20

Strands clears every structural bar our eight-step process sets. The licence is Apache-2.0, so the docs mirror can be committed. The TypeScript SDK is first-class on Node 22 ESM. The docs live in the repo under `site/`, with `sourceLinks` front matter that ties pages to code. Releases arrive about weekly: SDK 1.23.0, 1.24.0 and 1.25.0 shipped on 2026-10-30, 2026-11-04 and 2026-11-13 ([npm](https://registry.npmjs.org/@strands-agents/sdk)). The reference would also fill a real gap. It would be our only AWS-home SDK and our second "library plus assembled agent" case after Pi. It would also be a sharp contrast case for our claim that the sandbox and the credential boundary are separate components, because Strands has the seam but no boundary.

Four constraints shape the work:
1. **The age rule.** `@strands-agents/harness` 0.4.0 (2026-11-12T22:36Z) and `@strands-agents/sdk` 1.25.0 (2026-11-13T16:59Z) clear the one-week minimum on **2026-11-19 and 2026-11-20**. A pin taken before then must fall back to harness 0.3.4 and SDK 1.24.0, both published on 2026-11-04 ([npm](https://registry.npmjs.org/@strands-agents/harness)).
2. **Version skew.** The docs site renders `main`, which already carries a breaking `feat(context)!` change to the Python SDK and the Opus 5.5 default, both made after 0.4.0. The mirror must come from tag `harness-typescript/v0.4.0` (`ad1ae00`), and pages where the live site runs ahead must be recorded. The SDK's own tag, `typescript/v1.25.0` (`b48c73c`), is 26 minutes older than `ad1ae00`.
3. **No public test model.** `MockMessageModel` sits in internal `__fixtures__`, and the package exports no testing subpath ([mock-message-model.ts:32](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/strands-ts/src/__fixtures__/mock-message-model.ts#L32)). We would subclass `Model`, as we did for ADK, or mock the Anthropic API through `ANTHROPIC_BASE_URL`. A `Model` instance makes the harness ignore `effort` and `caching` with a logged warning ([harness-py/README.md:150-152](https://github.com/strands-agents/harness-sdk/blob/84d814b31810acc8d9f452f6cdd7333d2ed8c223/harness-py/README.md#L150-L152)).
4. **Hazardous defaults.** The verify harness must scrub AWS credentials, pass an explicit sandbox, and deny `shell`, `write`, `edit`, `web_fetch`, `web_search`, `programmatic_tool_caller` and `subagent` by name. AGENTS.md's inherited-credentials rule was written for exactly this case.

## Conclusion: copy Strands' interfaces and keep our defaults

Strands confirms that the industry is converging on our SDK-level shapes: a single streamed union, ordered gates over lifecycle points, a sandbox interface and MCP client 2.x. It also shows where an assembled harness is tempted to cut corners: a mutable snapshot for a durable log, a classifier for a human, the host for a sandbox. Its most useful lesson for us is the declarative `.when({...})` strategy value, which makes compaction both tunable and ablatable. Its most useful warning is that "every default is overridable" does not make a product safe when the defaults themselves are permissive. Our plan's fail-closed, signed and credential-free defaults are therefore the differentiator, not redundant caution.

The recommendation is to open a todo for a Strands verified reference pinned to `@strands-agents/sdk@1.25.0` and `@strands-agents/harness@0.4.0` from 2026-11-20. Its first examples should test the claims this report could not run: that a pending approval survives a restart, that every gate fires for calls made inside `programmatic_tool_caller`, and that an MCP tool can clash with a built-in name. Strands should also join the deep comparison's list of defaults that reach outside your process.
