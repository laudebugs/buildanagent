# Context management and compaction in mature harnesses

Status: working note, 2026-11-18. Versions are as of November 2026. Code claims cite pinned packages under `verify/` or shallow clones at the commits listed below. Web claims cite URLs, and "(secondary)" marks claims from search summaries or third-party write-ups.

**Thesis.** Mature harnesses have converged on a layered policy. The first layer cuts bulky tool output cheaply: truncation at write time, then clearing or masking at read time. The second summarizes on a threshold, always keeping a verbatim recent tail. The third compacts mid-turn before a step overflows, and the fourth compacts once and retries when the provider rejects the request anyway. They differ mainly in three things: who writes the summary (the client model or a server), whether the originals survive, and how much each layer costs in prompt-cache misses. The evidence says the cheap layers carry most of the value. Masking old observations matches LLM summarization at lower cost. The benefit of context management shrinks as windows grow, and compaction alone does not carry long tasks across windows without external progress files.

## Every summarizer keeps a verbatim recent tail, but the tail units differ

- **Pi.** Walks back until about `keepRecentTokens` = 20,000 accumulate (`PI/compaction/compaction.js:334-373`). It never cuts at a tool result, so calls and results stay paired (`:253-266`; `PIDOC:136`). When a single user-message span exceeds the budget, Pi writes two summaries, history plus a "turn prefix", and merges them (`compaction.js:666-711`; `PIDOC:100-126`). Repeated compaction re-summarizes from the previous `firstKeptEntryId` and passes the old summary as `<previous-summary>` (`compaction.js:411-449,616-626`; `PIDOC:81`). Read and modified file lists accumulate across compactions and are appended to the summary (`compaction.js:16-35,712-714`).
- **Codex.** Keeps no assistant or tool tail in local compaction. It keeps the summary plus *user messages*, newest first, up to `COMPACT_USER_MESSAGE_MAX_TOKENS` = 20,000. Oversized or non-text messages are emptied rather than split (`CX/core/src/compact.rs:69,733-800`). It re-renders the initial context (instructions, environment "world state") into the new window instead of summarizing it (`compact.rs:90-121`). "Retained tool outputs" flagged `retain_across_windows` survive (`CX/core/src/compact_retained_tool_outputs.rs:6-18`). Remote v2 compaction selects retained items newest-first under a token and image budget (`CX/core/src/compact_remote_v2.rs:700-760`).
- **Claude Agent SDK.** The `compact_boundary` records `preserved_segment` or `preserved_messages` UUIDs, "unset when compaction summarizes everything" (`CSDK:4053-4066`). So a verbatim tail is optional, not guaranteed. The SDK docs say compaction keeps "your most recent exchanges and key decisions" and "specific instructions from early in the conversation may not be preserved". They tell you to put persistent rules in CLAUDE.md, which is re-injected on every request (`CDOC/agent-loop.md:268-270`). Anthropic says Claude Code continues with the summary "plus the five most recently accessed files" ([Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)).
- **LangChain.** `keep` defaults to 20 messages, or `{tokens}` / `{fraction}` (`LC/summarization.js:43,354-378`), with a safe cutoff that never orphans tool pairs (`:444-480`). Pitfall: the summarizer is fed only the **last 4,000 tokens** of the span being discarded (`DEFAULT_TRIM_TOKEN_LIMIT = 4e3`, `trimMessages` with `strategy: "last"`, falling back to the last 15 messages; `:44,250,566-580`). A long history is therefore summarized from its tail only, unless you raise `trimTokensToSummarize`.
- **OpenHands.** Keeps the first `keep_first` = 2 events and roughly the back half. It "replaces the first half of all events with a single summary event" (`OH/context/condenser/README.md:5-9`; `llm_summarizing_condenser.py:300-325`).
- **Cloudflare Sessions.** `findTailCutByTokens` keeps a 20,000-token tail (`CF/packages/agents/src/sessions/compaction-helpers.ts:135-148`; `createCompactFunction` `keepRecentTokens ?? 20_000`, `:312-313`).
- **System prompt.** No harness summarizes it. Pi and LangChain split it out and prepend it unchanged (`PIDOC:71-76`; `LC/summarization.js:258-260`). Codex re-renders it (`compact.rs:90-121`). The Claude CLI *records* the system prompt and changes it only at compaction (`CSDK:2570-2596`; `CDOC/modifying-system-prompts.md:368`).

Twenty thousand recent tokens is the de facto default across Pi, Codex (for user text) and Cloudflare, an independent convergence.

## Tool-result clearing and summarization solve different problems, and clearing is the safer default

- **Clearing (masking).** Anthropic calls tool-result clearing "one of the safest lightest touch forms of compaction" ([Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)). The API strategy `clear_tool_uses_20250919` defaults to trigger 100,000 input tokens, keep 3 tool uses, `clear_tool_inputs: false`, plus optional `clear_at_least` and `exclude_tools`. Cleared results become a placeholder ([Context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing)). LangChain's `ClearToolUsesEdit` copies these defaults exactly: `[cleared]`, 1e5 and 3 (`LC/contextEditing.js:6-8`). Vercel exposes the same edits plus `clear_thinking_20251015` and `compact_20260112` as Anthropic provider options (`AI/@ai-sdk/anthropic/dist/index.d.ts:664-700`).
- **Truncation at read time.** Cloudflare `truncateOlderMessages` keeps 4 recent messages intact and cuts older tool outputs to 500 characters and older text to 10,000. It "does NOT mutate stored messages" (`CF/packages/agents/src/chat/truncate-older-messages.ts:1-5,16-21`). Think wires it in by default (`CF/packages/think/src/think.ts:276,302`).
- **Truncation inside the summarizer input.** Pi serializes tool results at 2,000 characters for the summary request (`PI/compaction/utils.js:83-92,137`; `PIDOC:291`). Cloudflare slices tool input and output to 500 characters (`compaction-helpers.ts:203-207`). Summaries therefore never see full tool outputs, and anything in a tool output that the agent needs later must be re-read from the environment.
- **Truncation at write time.** Codex truncates exec and tool output to a token budget with a "Warning: truncated output" header (`codex-rs/utils/output-truncation/src/lib.rs:39-42`, git HEAD). Claude Code caps tool responses at 25,000 tokens (main report, `docs/research/agent-sdks-and-harness-design.md:103`).
- **Pi has no automatic tool-result clearing.** It has `context_edit` entries, which omit or replace a target entry in the projection without deleting it, and are used for failed overflow attempts (`PI/agent-session.js:924`; `PIDOC:85-98`).

## Every compaction costs one prompt-cache rebuild, so harnesses ration how often the prefix changes

- Providers cache a byte-identical prefix. Think steps its read-time truncation cutoff every 8 messages (`truncationStep`) because "a cutoff that moved every turn rewrote a message near the end of that prefix on every turn" (`CF/packages/think/src/think.ts:304-313,6206-6219`). Think tests this as "rewrites the prefix once per compaction" (`think/src/tests/prompt-cache.test.ts:143`).
- Anthropic: clearing "invalidates cached prompt prefixes", and `clear_at_least` exists so each clear is worth the cache write ([Context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing)). For threshold compaction, the guidance is to put a `cache_control` breakpoint at the end of the system prompt so it stays cached across compactions, and to cache the compaction block ([Compaction at a token threshold](https://platform.claude.com/docs/en/build-with-claude/compaction-threshold)).
- OpenHands: "condensation destroys the prompt cache, but doing so regularly keeps the cost of rebuilding the prompt cache low" (`OH/context/condenser/README.md:7`).
- Pi disables cache writes on summary requests (`cacheRetention: "none"`, `PI/compaction/compaction.js:478-482`; `PIDOC:23`).
- Codex trims from the start when the compaction request itself overflows, "to preserve cache (prefix-based)" (`CX/core/src/compact.rs:359-366`).
- The Claude CLI freezes the system prompt until compaction to keep the cache prefix stable (`CSDK:2570-2577`).

## Token counting is mostly provider usage plus a chars/4 estimate for the tail

- **Pi** uses the last valid assistant `usage` (`totalTokens`, or input + output + cache read + cache write) and adds a chars/4 estimate for messages after it. It ignores usage from before the latest compaction or a context edit so that stale counts do not re-trigger compaction (`PI/compaction/compaction.js:62-134,198-249`; `PI/agent-session.js:2570-2600`).
- **Codex** takes `get_total_token_usage()` from responses (`CX/core/src/session/context_window.rs:58`). Its estimate is bytes/4 (`codex-rs/utils/string/src/lib.rs:6,94-97`, git HEAD). A model's catalog `effective_context_window_percent` (95 in tests) reserves headroom (`CX/protocol/src/openai_models.rs:576-580`).
- **Think** uses provider-reported `usage.inputTokens`, falling back to `totalTokens` (`think.ts:3061-3070`). Sessions estimates the larger of chars/4 and words × 1.3, because "real tokenizers cost ~100 MB of heap" (`CF/packages/agents/src/sessions/tokens.ts:4-17`).
- **LangChain** defaults to `countTokensApproximately` (chars/4 plus tool schemas; `LC/utils.js:16-26`). A real count is available only where the model has `getNumTokensFromMessages`, "currently only OpenAI models" (`LC/contextEditing.js:508-515`). Fractional triggers need a model `profile.maxInputTokens` (`LC/summarization.js:137-141,245-247`).
- **OpenHands** counts with LiteLLM's tokenizer for the agent model (`OH/context/condenser/utils.py:8-26`).
- **Claude Agent SDK** `getContextUsage()` returns categories (system prompt, tools, MCP, memory files, messages, `autocompact_buffer`), the `autoCompactThreshold` and a tool-call/result breakdown (`CSDK:3362-3364,4080-4110,4253-4264,4355-4356`). The window may be a policy window smaller than the hard limit, "e.g. the 200K boundary on 1M-window models" (`CSDK:4089`).
- Per-model overrides exist because one reserve does not fit all window sizes: Pi `compaction.modelOverrides` (`PIDOC:439-457`), Claude `autoCompactWindow` per model (`CSDK:9814-9816`).

## Measured payoffs are real but modest, and they shrink as windows grow

- Anthropic internal agentic-search eval (as of September 2025): memory tool plus context editing "improved performance by 39% over baseline", context editing alone by 29%, and context editing cut token use by 84% in a 100-turn web-search eval ([Managing context on the Claude Developer Platform](https://claude.com/blog/context-management)). This is a vendor eval with no public task set.
- Masking old observations "halves cost relative to the raw agent while matching, and sometimes slightly exceeding, the solve rate of LLM summarization" (SWE-agent on SWE-bench Verified). A hybrid cuts cost a further 7% and 11% against masking alone and summarization alone. Lindenbauer et al., "The Complexity Trap", arXiv 2508.21433, NeurIPS 2025 workshop (secondary: search summary; arxiv.org was unreachable from this session). One write-up gives 53.8% → 54.8% for Qwen3-Coder 480B (secondary).
- Decay with window size: the context-management payoff on SWE-bench fell from 35.7 to 2.7 points as the window grew from 32K to 128K ("An Empirical Study of Harness Design for Coding Agents", arXiv 2609.20804, secondary summary via [hyper.ai](https://hyper.ai/en/papers/2609.20804), as cited in `docs/research/agent-sdks-and-harness-design.md:9`). The same report notes that harness gains in general shrink as models improve (ibid.).
- Reasons to manage context below the hard limit: "as the number of tokens in the context window increases, the model's ability to accurately recall information from that context decreases", a "performance gradient rather than a hard cliff" ([Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)). Chroma's "Context Rot" report (Hong, Troynikov, Huber, July 2025, 18 models) found that reliability falls with input length even on simple tasks ([research.trychroma.com/context-rot](https://research.trychroma.com/context-rot); details secondary). This is why the Claude CLI may compact at a 200K policy window on 1M models (`CSDK:4089`), and why Codex starts async compaction at 65% (`CX/core/src/config/mod.rs:248`).
- OpenHands says its half-summarization "performs well in benchmarks" without numbers (`OH/context/condenser/README.md:5`). Neither Pi nor Codex publishes compaction ablations.

## Compaction alone does not carry long tasks across windows; external progress files do

- Anthropic: "compaction isn't sufficient". In a loop across windows, Opus 4.5 still tried to one-shot the app, ran out of context mid-feature, or declared the job done early, because compaction "doesn't always pass perfectly clear instructions to the next agent". The fix is an initializer agent that writes `init.sh`, `claude-progress.txt`, a JSON feature list (200+ features, each starting with `passes: false`, chosen over Markdown because the model is less likely to rewrite JSON) and an initial git commit. Each later session reads `pwd`, the git log, the progress file and the feature list, then runs a smoke test before starting new work. The post reports no quantitative results ([Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)).
- Structured note-taking (to-do lists, `NOTES.md`, the Pokémon agent's objective counters) lets an agent resume after a context reset ([Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)). Subagents return condensed summaries, "often 1,000-2,000 tokens", from tens of thousands of explored tokens (ibid.).
- Context editing pairs with the memory tool. Near the clearing threshold, Claude is warned to save to memory files first ([Context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing)).
- Harness equivalents: Pi appends file read and modify lists to every summary (`PI/compaction/compaction.js:712-714`). OpenHands keeps task IDs (`summarizing_system.j2`). Codex re-injects AGENTS.md and environment state after compaction (`CX/core/src/compact.rs:90-121`). Claude re-injects CLAUDE.md on every request (`CDOC/agent-loop.md:270`). Think moves evicted media to workspace files and leaves a path marker (`CF/packages/think/README.md:369,860`).

## Design implications for our harness

The layers below are ordered from cheapest to most expensive. Each is a removable module, so ablations can drop it as windows grow. The decay result (35.7 → 2.7 points) says layers 3 to 5 may be worth little on 128K+ models; measure them against the mini-swe-agent baseline before keeping them.

1. **Bound output at write time.** Cap each tool result (Claude Code uses 25K tokens, Codex a token budget) and spill the full output to a file the agent can re-read by path. This is cheap, cache-neutral, and follows Anthropic's just-in-time retrieval ([Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents); Think media eviction).
2. **Mask older tool results at read time, never in the log.** Keep the last N tool results verbatim (3 as in Anthropic and LangChain, or 4 messages as in Think), replace older ones with a placeholder that names the tool, call ID and spill path, and leave call arguments intact. Move the cutoff in steps (Think: every 8 messages) and clear at least a minimum amount (`clear_at_least`) so the cache prefix is rewritten rarely. The evidence: masking matches summarization at about half the cost ("The Complexity Trap", secondary), and clearing alone gave +29% in Anthropic's eval. On Anthropic models, prefer the server-side `clear_tool_uses` edit behind the gateway's provider adapter.
3. **Summarize between turns on a threshold.** Trigger at `window − reserve` (Pi: 16,384 reserve) or at a policy window below the hard limit (Claude: 200K on 1M models; Codex: 90%), with per-model overrides. Keep a 20K-token verbatim tail cut at turn boundaries and never between a tool call and its result, and run the split-turn prefix summary when one turn exceeds the tail (Pi). Use a structured, recall-first template (Pi or OpenHands sections, with exact paths, errors and task IDs) that updates the previous summary iteratively. Feed the summarizer the whole discarded span with tool outputs truncated to about 2K characters each, not just the span's tail (avoid LangChain's 4K-token `trimTokensToSummarize` default). Append cumulative read and modified file lists. Re-render the system prompt and project instructions fresh instead of summarizing them.
4. **Compact mid-turn.** Between tool steps, check provider-reported input tokens against about 90% of the window (Think `proactive`, Pi `prepareNextTurn`, Codex `MidTurn`), at most once per step loop.
5. **Retry once on overflow.** Classify overflow errors per provider (Think's regex covers Anthropic, OpenAI, Gemini, Bedrock and Mistral), discard the partial, compact, and retry once. Then fail loudly (Pi, Think). If the compaction request itself overflows, drop the oldest items first (Codex).
6. **Make compaction an event, not a rewrite.** Append a `compaction` entry (summary, `firstKeptEntryId`, tokens before and after, model, prompt version, usage) to the tree-shaped log, and build the model context as a projection (Pi, OpenHands, Cloudflare). Never delete originals, unlike the OpenAI compaction session and LangChain summarization. Emit `before_compact` and `after_compact` hooks (Claude's `PreCompact` and `PostCompact`, Pi's `session_before_compact`) so a custom summarizer can replace ours, and record compaction tokens in cost accounting (Anthropic `usage.iterations`; Claude `modelUsage` includes compaction calls, `CSDK:6242`).
7. **Count tokens with provider usage plus an estimated tail.** Use the last response's usage and estimate later messages at chars/4. Discard usage that predates the latest compaction or edit (Pi), and expose a `getContextUsage()`-style breakdown for debugging (Claude).
8. **Keep external state as the durable memory.** For multi-window tasks, have the harness or an initializer step create a progress file, a JSON task list with pass/fail fields and git commits, and re-read them at session start. Compaction is not a substitute for them ([Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)).

**Unresolved gaps.** The Claude CLI's exact auto-compact threshold and its tool-result clearing (microcompaction) are not visible in `sdk.d.ts`. No harness publishes an ablation of mid-turn or reactive compaction. The arXiv figures (2508.21433, 2609.20804) are unverified because arxiv.org and neurips.cc were blocked. Codex's server-side remote-compaction contents are encrypted, so its retention policy cannot be audited.
