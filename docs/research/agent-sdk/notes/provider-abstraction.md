# Provider abstraction: how mature agent SDKs build the model layer

Status: research notes, November 2026. Working material for layer 1 ("model gateway") of the reference architecture in [agent-sdks-and-harness-design.md](../../agent-sdks-and-harness-design.md).

The four SDKs split into two designs. **Vercel AI SDK** and **OpenAI Agents SDK** put a thin, versioned model interface (`doGenerate`/`doStream`, `getResponse`/`getStreamedResponse`) under a loop that owns retries and usage totals. **Pi** puts a fat, normalised transcript and event stream at the boundary, and it computes cost per message from a model catalog. The **Claude Agent SDK** exposes no provider interface: the model layer lives in the CLI subprocess, and the SDK only reports what the CLI did (model, fallback, retries, cost). For our SDK, the best design is Pi's message and usage model behind a Vercel-style versioned spec, with OpenAI's replay-safety rules for retries.

Versions checked (as of November 2026): `ai@7.0.162`, `@ai-sdk/provider@4.0.35`, `@ai-sdk/provider-utils@5.0.74`, `@ai-sdk/anthropic@4.0.96`, `@ai-sdk/openai@4.0.108`; `@earendil-works/pi-ai@1.5.2`; `@openai/agents-core@0.21.0` and `agents-openai@0.21.0`; `@anthropic-ai/claude-agent-sdk@0.3.327`. All evidence comes from the installed dist `.js`/`.d.ts` files. I cloned no source repos, because the dist was readable.

**The stream vocabularies agree on start/delta/end per content block.**
- Vercel parts: `text-start/-delta/-end`, `reasoning-start/-delta/-end`, `tool-input-start/-delta/-end`, the whole-object parts `tool-call`, `tool-result`, `tool-approval-request`, `file`, `source` and `custom`, plus `stream-start` (warnings), `response-metadata`, `finish` (usage, finishReason, providerMetadata), `raw` and `error` (`VP:3351-3418`). Parts correlate by string `id`.
- Pi events: `start`, `text_*`, `thinking_*`, `toolcall_*`, and terminal `done` or `error`. Each event carries a `contentIndex` and the live `partial` message, and `toolcall_end` carries the parsed `ToolCall` (`PI/types.d.ts:577-645`). The protocol guarantees that no update arrives before `start` and that the stream ends with exactly one `done` or `error` (`PI/types.d.ts:579-590`).
- OpenAI Agents is much thinner: `response_started`, `output_text_delta`, `response_done` (with the full response and usage) and a generic `model` event that wraps the raw provider event (`OA/types/protocol.d.ts:2095-2120, 2550-2555, 3000`). Tool calls and reasoning arrive only inside `response_done.output`, so the core loop never streams tool arguments.
- Pi returns errors **in-band**: a failed call is an `AssistantMessage` with `stopReason: "error" | "aborted"` and `errorMessage` (`PI/types.d.ts:321, 382-399, 641-645`). Vercel streams an `error` part, or throws `APICallError` from `doGenerate` (`VP:2142-2162`). OpenAI Agents throws.

**Finish reasons are normalised with the raw value kept beside them.** Vercel V4 uses `{ unified: 'stop'|'length'|'content-filter'|'tool-calls'|'error'|'interrupted'|'other', raw }` (`VP:654-675`). Pi has `stopReason` plus `rawStopReason` and `endTurn` (`PI/types.d.ts:321, 399-404`).

## 2. Message normalisation: a provider-neutral transcript, plus opaque per-provider payloads

**Content parts.**
- Vercel prompt roles are `system` (string), `user` (text and file parts), `assistant` (text, file, reasoning, reasoning-file, custom, tool-call, tool-result) and `tool` (tool-result, tool-approval-response). Every message and every part carries `providerOptions` (`VP:1122-1335`). Images are generic `file` parts with an IANA `mediaType` and tagged data: `data`, `url`, provider `reference`, or `text` (`VP:1220-1257`). The model's `supportedUrls` decides which URLs are passed through and which are downloaded (`VP:3463-3478`, `convertToLanguageModelPrompt` at `VAI:1460`).
- Pi messages are `system`, `user`, `assistant` and `toolResult`. Content is `TextContent`, `ThinkingContent`, `ImageContent` (base64 plus `mimeType`) or `ToolCall` (`PI/types.d.ts:259-291, 360-450`). Opaque provider state lives in typed fields: `textSignature`, `thinkingSignature`, `redacted`, `thoughtSignature` and `namespace`. Pi system messages can arrive mid-transcript to change the prompt sections and the tool set (`toolsAdded`/`toolsRemoved`), and an adapter either sends them in place or rebuilds the leading system prompt (`PI/types.d.ts:350-376`).
- OpenAI Agents uses the OpenAI Responses item model for every provider: `message`, `function_call`, `function_call_result`, `reasoning`, `computer_call`, `shell_call`, `apply_patch_call`, `compaction` and others (item literals in `OA/types/protocol.d.ts`). Each item and part has `providerData`. Other providers come in through the `aisdk()` adapter, which wraps any Vercel V2, V3 or V4 model (`verify/openai-agents-sdk/node_modules/@openai/agents-extensions/dist/ai-sdk/index.d.ts:36-55`).

**Cross-provider replay rules (Pi has the most explicit code, `PI/api/transform-messages.js:63-213`):**
1. Thinking blocks from a different provider, API or model are **dropped**, because "signatures and encrypted reasoning are only valid for the model that produced them, and sending readable thinking as plain text makes the new model treat it as part of the visible reply" (`:91-104`). Signed or redacted thinking from the same model is kept even when its text is empty (`:97-100`).
2. Text from another model keeps its text but loses its signature, and `thoughtSignature` is stripped from foreign tool calls (`:105-119`).
3. Tool-call IDs are remapped through an adapter-supplied `normalizeToolCallId`. The code comment says OpenAI Responses IDs run to 450+ characters while Anthropic requires `^[a-zA-Z0-9_-]+$` with at most 64 characters (`:58-62, 120-126`). Tool results are rewritten through the same map (`:76-83`).
4. Images are replaced by a placeholder when the target model lacks image input (`:38-57`).
5. Errored or aborted assistant turns are skipped entirely (`:172-180`), and orphaned tool calls get a synthetic `isError` result reading "No result provided" (`:138-166, 210-211`).

Vercel reaches the same outcome by namespacing. The Anthropic adapter emits `providerMetadata: { anthropic: { signature } }` on reasoning (`VANT:4591`) and replays reasoning only when `providerOptions.anthropic.signature` or `redactedData` is present. Otherwise it drops the reasoning with an "unsupported reasoning metadata" warning (`VANT:3030-3067`). Reasoning that came from OpenAI therefore never reaches Anthropic, and the adapter reports the drop as a warning instead of throwing.

## 3. Provider-specific options pass through namespaced bags and payload hooks

- **Vercel:** `providerOptions: Record<providerName, JSONObject>` at three levels: the call, each message, and each part (`VP:127-149`; prompt types `VP:1122+`). The response direction mirrors it with `providerMetadata` (`VP:125`). Adapters validate their own slice with zod, for example Anthropic's `cacheControl: { type: 'ephemeral', ttl?: '5m'|'1h' }` (`VANT:1262-1271`). Middleware (`transformParams`, `wrapGenerate`, `wrapStream`, `VP:3503-3575`; `wrapLanguageModel` at `VAI:16354`) is the sanctioned interception point.
- **Pi:** each wire API has its own typed options interface, selected by the `api` string through `ApiOptionsMap` (`PI/types.d.ts:180-196`). The untyped fallback is `StreamOptions & Record<string, unknown>` (`:165`). Escape hatches: `onPayload` can inspect or replace the final request body, `onResponse` observes status and headers, `onProviderStreamEvent` sees raw events, `samplingParams` merges arbitrary keys into OpenAI-compatible bodies, and `headers` can set or suppress (`null`) individual headers (`PI/types.d.ts:65-127`). Per-model `compat` objects describe quirks of OpenAI-compatible servers (`PI/types.d.ts:681-682`).
- **Pi separates the wire protocol (`api`) from the vendor (`provider`).** `KnownApi` lists 10 wire protocols, and `KnownProvider` lists more than 40 vendors that reuse them (`PI/types.d.ts:20-27`). This is why one `openai-completions` adapter serves Groq, Cerebras, DeepSeek and others.
- **OpenAI Agents:** `ModelSettings.providerData` (`OA/model.d.ts:315`) plus `providerData` on every item. Cache, reasoning, `store`, `truncation` and `contextManagement` (server-side compaction) are first-class settings, because the SDK is Responses-first (`OA/model.d.ts:242-325`).

## 4. Retries: three layers, and streams need replay-safety rules

**Layer A, the HTTP request (connection or headers fail before any output).**
- *Vercel* retries in the core, not in adapters: `prepareRetries` defaults to `maxRetries = 2` (`VAI:2346-2375`), with an initial delay of 2 s and a backoff factor of 2 (`VAI:2324-2341`). It retries only `APICallError`/`GatewayError` with `isRetryable === true` (`VAI:2329`). The default `isRetryable` is status 408, 409, 429 or ≥500 (`V/@ai-sdk/provider/dist/index.js:70`). It honours `retry-after-ms` and `retry-after` when the value is under 60 s (`VAI:2302-2320`). The retry wraps the `doGenerate`/`doStream` call (`VAI:5537`).
- *Pi* disables the vendor SDKs' own retries (`maxRetries: 0`) and wraps the call in `retryProviderRequest`, because "their built-in retry timers ignore the request AbortSignal" (`PI/utils/provider-retry.js:68-75`; `PI/api/anthropic-messages.js:611-617`). The policy mirrors the OpenAI and Anthropic SDKs: `x-should-retry` first, then 408/409/429/5xx, with backoff `min(0.5·2^n, 8)` s and up to 25% jitter. A server-requested delay above `maxRetryDelayMs` (60 s by default) **fails fast** with the requested delay in the message, so a higher layer can decide what to do (`PI/utils/provider-retry.js:9-45`; option doc `PI/types.d.ts:98-105`).
- *OpenAI Agents* makes retries opt-in: "no retries occur unless `policy` returns `true`" (`OA/model.d.ts:218-232`). It ships composable policies `never`, `providerSuggested`, `networkError`, `httpStatus([...])`, `retryAfter`, `any` and `all` (`OA/runner/modelRetry.d.ts:10-18`), with default backoff of 250 ms initial, 2 s maximum, ×2 and jitter (`OA/runner/modelRetry.mjs:4-7`). When the runner manages a retry, it sets the OpenAI client's `maxRetries = 0` (`OA/runner/modelRetry.mjs:123-135`; `.../agents-openai/dist/openaiResponsesModel.mjs:1019-1021`). Models can add `getRetryAdvice()` returning `suggested`, `retryAfterMs`, `replaySafety` and `responseStarted` (`OA/model.d.ts:118-145`).

**Layer B, mid-stream failure.**
- *Vercel* has a separate `streamRetries` option, default 0 (`V/ai/dist/index.d.ts:3900`). When it is enabled, the core buffers tool parts, cancels the failed reader, closes open text and reasoning parts, and re-calls the model (`VAI:9879, 9950-9985`).
- *OpenAI Agents* refuses to replay once output has started or replay safety is `unsafe`, unless the policy returns `approveUnsafeReplay`. It treats timeouts as unsafe (`OA/model.d.ts:75-95`; `OA/runner/modelRetry.mjs:420-430`). The policy context also flags stateful requests (`previousResponseId`/`conversationId`), whose replay may duplicate server-side state (`OA/model.d.ts:146-200`). This is the most careful design of the four.

**Layer C, turn-level retry above the model.** Pi's `retryAssistantCall` reruns a whole assistant turn when `isRetryableAssistantError` matches the error text against a long regex list (overloaded, rate limit, 5xx, socket hang up, and similar). It deliberately does **not** retry quota or billing exhaustion such as `insufficient_quota` (`PI/utils/retry.js:4-112, 155-215`). Context overflow is a separate classifier (`isContextOverflow`, `PI/utils/overflow.js:139`), which the coding agent routes to compaction rather than retry (`verify/pi/node_modules/@earendil-works/pi-coding-agent/dist/core/agent-session.js:2529-2532, 3144-3146`). The Claude CLI performs retries itself and reports each one as an `SDKAPIRetryMessage` with `attempt`, `max_retries`, `retry_delay_ms` and `error_status` (`CL:3867-3885`). Model fallback on overload goes through `fallbackModel`, and the primary model is retried each user turn (`CL:1815-1822`). Refusal fallback emits `model_refusal_fallback` (`CL:5959-5973`).

## 5. Prompt caching: one portable knob plus provider-specific breakpoints

Provider facts: Anthropic allows up to 4 breakpoints. The default TTL is 5 minutes, with `ttl: "1h"` optional. Cache writes cost 1.25× base input (5 min) or 2× (1 h), reads cost 0.1× (lower on some newer models), the minimum cacheable length is 512 to 4,096 tokens depending on the model, and the prefix lookback is 20 blocks ([Anthropic prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching), fetched November 2026). OpenAI facts below come from code only, because `platform.openai.com` and `developers.openai.com` were unreachable from this session.

- **Pi** offers one portable setting, `cacheRetention: "none" | "short" | "long"` (default `"short"`), plus `sessionId` (`PI/types.d.ts:134-144`). Each adapter maps it to its provider. Anthropic gets `cache_control: {type:"ephemeral"}` with `ttl:"1h"` for `long` when the model supports it (`PI/api/anthropic-messages.js:28-47`). Breakpoints are placed automatically on the system prompt, the last tool definition and the **last user or tool-result block**, which caches the whole history so far (`PI/api/anthropic-messages.js:1077-1137, 1408-1432, 1520`). OpenAI Completions and Responses get `prompt_cache_key = sessionId`, clamped to 64 characters, and `prompt_cache_retention: "24h"` for `long` (`PI/api/openai-responses.js:263-264`; `PI/api/openai-completions.js:567-570`; `PI/api/openai-prompt-cache.js:1-9`). Models declare cache TTLs per tier in `promptCache` (`PI/types.d.ts:673-674`). Pi also ships a cache-*warming* calculator that weighs expected savings against a 5% threshold (`PI/cache-warming.d.ts:3-45`).
- **Vercel** has no portable knob. Callers set `providerOptions.anthropic.cacheControl` on messages, parts or tools, and the adapter's `CacheControlValidator` enforces at most 4 breakpoints and warns on non-cacheable blocks such as thinking (`VANT:1462-1495, 3037-3040`). OpenAI takes `promptCacheKey` and `promptCacheRetention: 'in_memory'|'24h'` (`VOAI:1443, 1463`).
- **OpenAI Agents** has `promptCacheRetention: 'in-memory'|'24h'` and `promptCacheOptions { mode: 'implicit'|'explicit', ttl?: '30m' }` (`OA/model.d.ts:40-51, 292-296`), plus a per-part `promptCacheBreakpoint: { mode: 'explicit' }` on input content (50 occurrences in `OA/types/protocol.d.ts`, first at `:38`). The `aisdk()` adapter rejects cache retention on V2 models (`.../agents-extensions/dist/ai-sdk/index.mjs:306`).
- **Claude Agent SDK:** caching is internal to the CLI and visible only in usage, as `cacheReadInputTokens`, `cacheCreationInputTokens` and the 5 m/1 h split (`CL:1561-1577`).

The SDKs define "input tokens" differently. Vercel's Anthropic adapter reports `inputTokens.total = input + cacheWrite + cacheRead` and `noCache = input` (`VANT:2232-2273`). Pi stores Anthropic's `input_tokens` as `input`, excluding cache, and adds the three classes when pricing (`PI/api/anthropic-messages.js:694-700`; `PI/models.js:681`). A normalised schema has to fix one convention and document it.

## 7. Spec evolution: tag every model and adapt old versions with Proxies

Vercel's provider spec is the only one with explicit versions. Every model carries `specificationVersion` (`'v2'`, `'v3'` or `'v4'`; `VP:1955-2007, 3457, 4564, 5356`), and `@ai-sdk/provider@4` still exports the V2 and V3 types. `resolveLanguageModel` accepts all three versions and upgrades the model through `asLanguageModelV4` (`VAI:984-998`). The adapters are `Proxy` objects that rewrite only what changed:
- V2→V3 (`VAI:714-778`): a flat `finishReason` string becomes `{unified, raw}` (`'unknown'` maps to `'other'`), and flat usage becomes nested usage, with `cachedInputTokens` moving to `cacheRead`. It also logs a compatibility warning.
- V3→V4 (`VAI:780-892`): the prompt is converted *down* (V4 tagged file data becomes V3 raw data, a URL or a file-id) and content is converted *up*, with V3 `file.data` wrapped as `{type:'data'}`.
- `asProviderV4` chains `asProviderV3` (`VAI:954-983`).

Middleware is versioned too (`LanguageModelV4Middleware.specificationVersion`, `VP:3503-3507`). The cost of this design is that a provider package stays pinned to one spec while the core moves on. Third parties lean on it as well: OpenAI's `aisdk()` adapter still compiles against V2 types and accepts V3/V4 by duck typing (`.../agents-extensions/dist/ai-sdk/modelTypes.d.ts:1-14`).

Pi has no spec version. It evolves by adding optional fields (for example `durationMs`, `thinkingLevel`, `diagnostics`, marked "absent for legacy messages", `PI/types.d.ts:390-412`) and by keeping old names in `legacy-api-aliases.js`. OpenAI Agents adds optional members to `Model` (`getRetryAdvice?`, `supportsPromptModelSelection?`, `OA/model.d.ts:533-556`).

## 8. Testing: every SDK ships a scriptable fake model

Pi's `fauxProvider`/`createFauxCore` scripts `AssistantMessage` responses or factories, simulates `tokensPerSecond` streaming, and records `callCount` (`PI/providers/faux.d.ts:3-80`). Vercel ships `MockLanguageModelV4` in `ai/test` (`V/ai/dist/test/index.d.ts:135`). OpenAI Agents ships `ScriptedModel` (`OA/testing/scriptedModel.d.ts`). The Claude Agent SDK has no in-process fake. Offline tests mock the Messages API over HTTP instead (`docs/reference/claude-agent-sdk/guide.md`).

## Design implications for our SDK

1. **Make the boundary one streaming method that returns a typed event stream, and derive non-streaming from it.** Pi needs only `stream()` and builds `complete()` on top (`PI/types.d.ts:205-210`). Vercel and OpenAI keep two methods each (§1), and every adapter then implements both. Use a `start / *_start / *_delta / *_end / done | error` protocol keyed by content index, and guarantee exactly one terminal event, as Pi's docs specify (`PI/types.d.ts:577-590`).
2. **Return failures in-band as a final message with `stopReason: "error" | "aborted"`, and do not throw.** This keeps partial content, usage and `rawStopReason` in the session log, and it lets the loop classify errors as retryable, overflow or fatal (Pi §4C; `PI/types.d.ts:321, 641-645`). Throw only for programmer errors such as missing auth.
3. **Separate `api` (wire protocol) from `provider` (vendor and catalog), and keep quirks in per-model `compat` data.** Ten Pi adapters cover more than 40 vendors this way (`PI/types.d.ts:20-27, 681-682`).
4. **Own the canonical transcript, and put every opaque provider token in a typed field tagged with the producing `provider/api/model`.** Use Pi's `thinkingSignature`, `redacted`, `textSignature` and `thoughtSignature` rather than an untyped bag, and run a single `transformMessages` pass before every request. That pass drops foreign reasoning, strips foreign signatures, remaps tool IDs, downgrades images, skips errored turns and synthesises orphan tool results (§2). Vercel's namespaced `providerOptions` approach silently drops cross-provider reasoning with only a warning (`VANT:3060-3067`), so it is easier to get wrong.
5. **Provide escape hatches: a namespaced `providerOptions` bag, an `onPayload` request rewrite, and raw-event and response observers.** Vercel (`VP:127-149`) and Pi (`PI/types.d.ts:65-127`) both found that typed options never cover new provider features fast enough.
6. **Put retries in the gateway, disable vendor-SDK retries, and make backoff abortable.** Pi found that vendor SDK sleeps ignore `AbortSignal` (`PI/utils/provider-retry.js:68-75`). Copy OpenAI's replay-safety rules: no automatic replay after the first output event, or after a timeout on a stateful request, without explicit approval (`OA/model.d.ts:75-95, 146-200`). Cap server-requested delays and fail fast above the cap (Pi, 60 s). Treat quota and billing errors as non-retryable (`PI/utils/retry.js:4-28`). Emit a retry event like Claude's `api_retry` (`CL:3867-3885`) so the UI and log can show it.
7. **Make prompt caching a portable policy (`cacheRetention` plus `sessionId`) with automatic breakpoints, and allow per-block overrides.** Pi's placement on the system prompt, the last tool and the last user or tool-result block covers the agent-loop case with no caller effort (`PI/api/anthropic-messages.js:1408-1432`). Keep Vercel's 4-breakpoint validator as a guard (`VANT:1462-1495`). Freeze the system prompt and tool order so prefixes stay stable.
8. **Attach usage and cost to every assistant message, with four input classes and an explicit convention.** Store `input` (uncached), `cacheRead`, `cacheWrite`, `cacheWrite1h`, `output`, `reasoning ⊂ output`, a `raw` snapshot, and `cost` with a `source`/`basis` flag. Combine Pi's `totalFromProvider` (`PI/types.d.ts:315-318`) with Claude's `costBasis` (`CL:1591-1594`). Price from a catalog that has tiered rates (`PI/models.js:680-700`). Count failed attempts too (`OA/runner/modelRetry.mjs:100-115, 834`). Run totals then become a fold over the append-only log, which also gives budget stops like `maxBudgetUsd` (`CL:2066-2070`).
