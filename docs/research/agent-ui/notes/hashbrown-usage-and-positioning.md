*Working material for the [hashbrown report](../hashbrown.md); the report and its [fact-check log](../fact-check.md#hashbrown-report-2026-11-18) supersede this note where they disagree.*

## 1. What problem hashbrown says it solves, and its documented feature set

### Takeaway
Hashbrown is an MIT-licensed, headless TypeScript framework for React and Angular. The model picks from components the app registers and fills their props from a schema, calls tools that run in the browser, and streams typed structured output. A server adapter keeps the provider key and translates each provider's API to AG-UI events. Around that core, by v0.8.3 the docs also cover a QuickJS sandbox for model-written JavaScript, streaming Markdown ("Magic Text", renamed "prose" in 0.9.0), typed "decisions", AG-UI activities, shared agent state, interrupt/resume, subagent display and browser-local models. The docs document no voice feature.

### Cited Findings
- **Positioning.** The README tagline is "AI chat and agents for your React or Angular app". It calls hashbrown "a headless TypeScript framework" that "ships no chat UI of its own: you keep your components and your design system" ([C/README.md](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/README.md)). `llms.txt` describes "generative user interfaces that converse with users, dynamically reorganize, and even code themselves" ([llms.txt](https://hashbrown.dev/llms.txt)).
- **Original problem statement (June 2025 launch).** The launch post lists the challenges it targets: managing LLM state, integrating with app state and services, computing structured data from natural language, exposing components to the LLM, debugging responses, and "executing LLM-generated code in the browser". It said hashbrown is "built specifically for frontend web applications" ([C/www/content/blog/2025-06-25-hashbrown-launch.md](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/www/content/blog/2025-06-25-hashbrown-launch.md)).
- **README feature table (current main):** generative UI ("The model composes your components. Bundle them into UI kits."), client-side tools, structured output via Skillet, streaming ("Strings, arrays, and objects parse as they arrive. Prose streams Markdown."), any model, and code execution ("Run model-written JavaScript in a sandbox") ([C/README.md](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/README.md)).
- **Three package kinds:** `@hashbrownai/core` (framework-agnostic primitives, the Skillet schema language and the streaming JSON parser), `@hashbrownai/<angular|react>` (resources, hooks and components), and `@hashbrownai/<provider>` (Node adapters) ([C/README.md](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/README.md)).
- **API chooser (React names; Angular uses `*Resource` equivalents).** `useUiChat` renders trusted components in a conversation. `useChat` is a text conversation, `useStructuredChat` a conversation with typed data, and `useCompletion`, `useStructuredCompletion` and `useUiCompletion` work from the current input only. `useDecision` chooses among named options, and `useUiDecision` narrows the components available to a chat ([Choosing an API](https://hashbrown.dev/docs/react/start/overview)).
- **Generative UI definition.** The model "selects a component you expose and supplies schema-shaped values for its props. It does not write the component implementation" ([React Quickstart](https://hashbrown.dev/docs/react/start/quick)). Components are registered with `exposeComponent(Component, { name, description, props, children })`. `children: false` keeps the catalogue flat, while `children: 'any'` or an explicit list allows nesting from the same trusted catalogue. A mismatched prop type "is a build error" ([Generative UI with React Components](https://hashbrown.dev/docs/react/concept/components)). Assistant messages expose `message.ui` for rendering (same page).
- **UI kits** package components with their descriptions and prop schemas for reuse across conversations ([UI Kits](https://hashbrown.dev/docs/react/recipes/ui-kits)). Since v0.7, `createUiJsonSchema()` builds the UI schema for "an agent Hashbrown doesn't run (CopilotKit, LangGraph, your own server)" ([C/CHANGELOG.md, 0.7.0](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/CHANGELOG.md); [Upgrade to v0.7](https://hashbrown.dev/docs/react/migrations/v0-7)).
- **v0.8 removed few-shot UI examples:** "the `prompt` tagged template and its `<ui>` blocks" and every `examples` option, replaced by component descriptions and rules ([C/CHANGELOG.md, 0.8.0](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/CHANGELOG.md); [v0.8 release post](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/www/content/blog/2026-10-22-hashbrown-v-0-8-0.md)).
- **Skillet schemas.** Skillet is exported as `s` from core and infers TypeScript types ([Skillet schemas](https://hashbrown.dev/docs/react/concept/schema)). "Standard JSON Schema inputs are normalized to Skillet (draft-07)… Unsupported keywords throw at runtime" ([Tool Calling](https://hashbrown.dev/docs/react/concept/functions)).
- **Streaming.** `s.streaming.array` and streaming strings and objects resolve values while the response arrives. The docs warn that a visible field "can still belong to a run that later fails… rendering it must not commit a business action" ([Streaming](https://hashbrown.dev/docs/react/concept/streaming)). A standalone streaming JSON parser recipe needs no model or endpoint ([Choosing an API](https://hashbrown.dev/docs/react/start/overview); [Streaming JSON Parser](https://hashbrown.dev/docs/react/recipes/json-parser)).
- **Magic Text, renamed prose.** In 0.9.0 (unreleased), `MagicTextRenderer` becomes `ProseRenderer` and `createMagicTextNodeRenderers` becomes `createProseNodeRenderers`, a "breaking rename with no deprecated exports"; "Rendering, streaming, parser completion and citation behavior stay the same" ([Rename Markdown Rendering to Prose](https://hashbrown.dev/docs/react/migrations/prose)). Prose renders "headings, lists, links, and citations" as the text grows ([Prose in React](https://hashbrown.dev/docs/react/recipes/prose)). The React and Angular packages depend on `@cacheplane/partial-markdown` 0.5.12 and `@cacheplane/partial-json` 0.3.1 ([npm @hashbrownai/react](https://registry.npmjs.org/@hashbrownai/react)).
- **Tool calling.** `useTool({ name, description, schema, handler })` defines a browser tool. "Hashbrown runs the browser handler" and "sends that result in a continuation request" ([Tool Calling](https://hashbrown.dev/docs/react/concept/functions)). Agent servers can also run server tools, which the client displays as `serverToolCalls` with labels, outcomes, timing and sources ([C/CHANGELOG.md, 0.8.0](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/CHANGELOG.md)).
- **JavaScript runtime.** `useRuntime({ timeout, functions })` "evaluates a script in a separate QuickJS context", with "no browser `window`, `document`, or `fetch`". Host functions are explicit capabilities (`useRuntimeFunction`). "Each call creates a fresh QuickJS context". A deadline "does not roll back a host side effect or impose a memory limit", and the function schema "does not automatically validate arguments". `useToolJavaScript` wraps a runtime as a chat tool so a model can submit code ([JS Runtime](https://hashbrown.dev/docs/react/concept/runtime)).
- **Decisions (new in v0.8).** These are typed decision models whose answer includes "the model's confidence", for routing, classification or choosing which components a chat can render. "TypeSafe's Jev" is the first decision adapter ([v0.8 release post](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/www/content/blog/2026-10-22-hashbrown-v-0-8-0.md)). `HashbrownTypeSafe.decide()` returns JSON from `/api/decide`. "TypeSafe is a decision service, so it does not replace the streaming chat endpoint" ([TypeSafe](https://hashbrown.dev/docs/react/platform/typesafe); [Platforms](https://hashbrown.dev/docs/react/start/platforms)).
- **Activities.** These are "structured, display-only messages" that stay "out of the outgoing model conversation". `groupTurns` groups the transcript, and the agent must emit real AG-UI activity events ([Activities](https://hashbrown.dev/docs/react/concept/activities)). v0.8 added the `ActivityMessage` variant (`role: 'activity'`) ([C/CHANGELOG.md, 0.8.0](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/CHANGELOG.md)).
- **Other v0.8 and 0.9 features:** normalized `lastRunFinishReason` and `lastRunUsage` across all six adapters; `lastRunResult`; OpenAI/Azure `builtInTools.webSearch` with citations ([C/CHANGELOG.md, 0.8.0](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/CHANGELOG.md)). In 0.9.0 (unreleased): readonly `subagents` records for AG-UI child runs, headless tool-step display helpers, opt-in HTTP retry, and OpenAI/Azure `builtInTools.codeExecution` (same file, 0.9.0).
- **Debugging and workbench.** The docs ship a "Conversation Workbench" that replays recorded runs with Requests, JSON, UI and State tabs; "playback makes no provider requests" ([Generative UI with React Components](https://hashbrown.dev/docs/react/concept/components); [Conversation Workbench](https://hashbrown.dev/docs/react/start/workbench)). There is a dedicated Debugging page ([llms.txt](https://hashbrown.dev/llms.txt)).
- **MCP: the README and the docs disagree.** The README says of client-side tools, "Connect MCP servers too" ([C/README.md](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/README.md)). A search of `llms-full.txt` found no MCP page or mention, and the current `packages/` tree has no `.ts` file mentioning MCP (own grep). MCP work appears only in older changelog entries (`remote mcp with react`, `samples/spotify: align mcp tool types`) ([C/CHANGELOG.md, 0.5.0-beta](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/CHANGELOG.md)). The v0.3 AG Grid post's description mentions "MCP server integration" ([C/www/content/blog/2025-10-22-ag-grid-ai-toolkit.md](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/www/content/blog/2025-10-22-ag-grid-ai-toolkit.md)).
- **Voice and audio.** No voice or speech feature is documented. Audio appears only as *input* to Chrome's built-in Prompt API under `experimental_chrome` media configuration ("Chrome image/audio input requires an explicit `experimental_chrome` media configuration"), and "WebLLM audio is not implemented or qualified" ([Local Models](https://hashbrown.dev/docs/react/recipes/local-models)).

### Inferences
- The project has moved from a frontend LLM toolkit with its own frame protocol and thread storage (2025) to a headless AG-UI client with typed generative UI and adapters (v0.6 and later). Its scope now reaches agent concerns: approvals, subagents, activities and durable recovery through partners. This reading rests on the changelog breaking-change lists for 0.6, 0.7 and 0.8.
- The MCP claim in the README looks stale relative to the current docs and packages. The report should not list MCP client support as a current documented feature without a caveat.

### Gaps
- Whether MCP still works through some undocumented path in 0.8.3 is left to the source-internals researcher.
- GitHub star count and contributor count were not collected, because the GitHub REST API is blocked from this session.

## 2. Model providers and adapters

### Takeaway
As of 0.8.3 there are six streaming server adapters: OpenAI, Azure OpenAI, Anthropic, Amazon Bedrock, Google Gemini (Developer API or Vertex AI) and Ollama. There is also a TypeSafe decision adapter and browser-local transports (Chrome, Edge, WebLLM). Each adapter exposes `Hashbrown<Provider>.stream.text({ ..., input: RunAgentInput, signal })` and returns `AsyncIterable<AGUIEvent>`, which the route encodes as SSE. The Writer adapter was removed in v0.6. Per-provider limits are documented: OpenAI and Azure require the Responses API, and Ollama is only partially qualified.

### Cited Findings
- **Adapter table:** `@hashbrownai/openai`, `/azure`, `/anthropic`, `/bedrock`, `/google`, `/ollama`. "They map text, tool calls and structured-output requests… an adapter does not add a missing model capability" ([Platforms](https://hashbrown.dev/docs/react/start/platforms)).
- **Common contract.** For example, "`HashbrownAnthropic.stream.text(options)` accepts an AG-UI `RunAgentInput` and returns an `AsyncIterable<AGUIEvent>`… Encode its events as AG-UI SSE at your HTTP boundary". "The model is server configuration and is not read from the client run input" ([Anthropic](https://hashbrown.dev/docs/react/platform/anthropic)). Every adapter takes an optional `transformRequestOptions` hook to rewrite the final provider request ([Request transformation](https://hashbrown.dev/docs/react/concept/transform-request-options); adapter pages).
- **Structured-output request shape.** `input.forwardedProps.hashbrown.responseSchema` selects native structured output ([Anthropic](https://hashbrown.dev/docs/react/platform/anthropic)). v0.8 moved the extension "from a top-level `hashbrown` key to `forwardedProps.hashbrown`, AG-UI's pass-through extension point" ([C/CHANGELOG.md, 0.8.0](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/CHANGELOG.md)).
- **OpenAI and Azure** "use the Responses API. An OpenAI-compatible Chat Completions endpoint alone is not enough" ([Platforms](https://hashbrown.dev/docs/react/start/platforms)). Since v0.8: reasoning summaries, "stateless encrypted-reasoning replay", `builtInTools.webSearch`, and incomplete responses finishing with `lastRunFinishReason` instead of `RUN_ERROR` ([C/CHANGELOG.md, 0.8.0](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/CHANGELOG.md)). Peer dependency: `openai ^6.45.0` ([npm @hashbrownai/openai](https://registry.npmjs.org/@hashbrownai/openai); [npm @hashbrownai/azure](https://registry.npmjs.org/@hashbrownai/azure)).
- **Anthropic** uses "Anthropic's streaming Messages API". Options are `apiKey`, `baseURL` ("Anthropic-compatible API base URL"), `model`, `input`, `signal`, `activities`, `builtInTools` ("server-side web search, fetch, and code execution") and `transformRequestOptions`. Thinking, signatures and redacted thinking become AG-UI reasoning records, and unsupported native events are preserved as `RAW` ([Anthropic](https://hashbrown.dev/docs/react/platform/anthropic)). The npm package was first published 2025-11-14, with peer `@anthropic-ai/sdk 0.122.0 || 0.135.0` ([npm @hashbrownai/anthropic](https://registry.npmjs.org/@hashbrownai/anthropic)).
- **Bedrock** "maps AG-UI input to ConverseStream". It takes `model` (model or inference-profile ID), `clientOptions` or `client`, and `builtInTools` ("Nova web grounding with `webSearch`"), and grounding citations become answer sources ([Amazon Bedrock](https://hashbrown.dev/docs/react/platform/bedrock)). First published 2025-12-16, with peer `@aws-sdk/client-bedrock-runtime ^3.1106.0` ([npm @hashbrownai/bedrock](https://registry.npmjs.org/@hashbrownai/bedrock)).
- **Google** supports two "mutually exclusive authentication modes": a Gemini Developer API `apiKey`, or `vertexai: true` with `project` and Application Default Credentials. "Some native tool capabilities differ" between them ([Google Gemini](https://hashbrown.dev/docs/react/platform/google)). Peer: `@google/genai ^2.19.0` ([npm @hashbrownai/google](https://registry.npmjs.org/@hashbrownai/google)).
- **Ollama** uses the official Ollama SDK chat stream, with `host` or a preconfigured `client`. The maintainers' 2025-10-25 qualification (Ollama 0.40.11, `qwen2.5:14b` Q4_K_M, M1 Max) passed "7/10" provider cases and "12/20" Angular/React cases. Failures included schema-plus-tools runs that "omitted required lookups" ([Ollama](https://hashbrown.dev/docs/react/platform/ollama)). Peer: `ollama 0.6.3 || 0.6.4` ([npm @hashbrownai/ollama](https://registry.npmjs.org/@hashbrownai/ollama)).
- **Writer was removed.** "the Writer provider (`@hashbrownai/writer`) and `WriterKnownModelIds` are removed" in 0.6.0 ([C/CHANGELOG.md, 0.6.0](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/CHANGELOG.md)). The docs say it "is no longer published" ([Upgrade to v0.6](https://hashbrown.dev/docs/react/migrations/v0-6)). npm still serves `@hashbrownai/writer` 0.5.0, published 2026-07-13 ([npm @hashbrownai/writer](https://registry.npmjs.org/@hashbrownai/writer)).
- **Model selection is server-only since v0.6.** "hooks, resources and the core runtime no longer accept `model`" ([C/CHANGELOG.md, 0.6.0](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/CHANGELOG.md)).
- **Custom provider.** "accepts an AG-UI `RunAgentInput`, calls the provider's native SDK, and yields canonical `AGUIEvent` values". The page lists six responsibilities, including lifecycle ordering and abort handling ([Custom Provider](https://hashbrown.dev/docs/react/platform/custom)).
- **Browser-local models:** `experimental_chrome` (Chrome's built-in model), `experimental_edge`, `experimental_local` (detects Chrome, then Edge) and `experimental_webllm` with an app-owned engine. There is "no automatic hosted fallback" ([Local Models](https://hashbrown.dev/docs/react/recipes/local-models)). A 2026-11-06 snapshot reports Chrome Nano "No-tool smoke: 6/6" but "Tool-session creation failed" (same page).
- **Provider SDK peers:** all six streaming adapters depend on `@ag-ui/core 1.0.3` at 0.8.3 (npm documents above). 0.9.0 will pin AG-UI 1.0.4 ([C/CHANGELOG.md, 0.9.0](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/CHANGELOG.md)).

### Inferences
- Every adapter emits AG-UI, so any AG-UI-speaking backend is in principle a provider. The six adapters are a convenience for direct model calls, not the integration boundary.
- The per-adapter qualification notes, especially Ollama's measured pass rates, are unusually candid for a framework's docs. They also show that structured-output-plus-tools reliability is a model issue the adapter cannot fix.

### Gaps
- No documented per-provider matrix of which schema constructs each provider accepts. The docs say only that support "depend[s] on the provider and model".

## 3. Frameworks and minimum versions

### Takeaway
Hashbrown supports two frontend frameworks, React and Angular, with parallel docs. React's peer range has been `>=18 <20` since 0.3.0. Angular requires `^22.0.0` since 0.6.0; it was `^20` and later `^20 || ^21`. The Angular API is built on signals and `*Resource` functions.

### Cited Findings
- **Peer ranges at 0.8.3:** `@hashbrownai/react` needs `react` and `react-dom` `>=18 <20` ([npm @hashbrownai/react](https://registry.npmjs.org/@hashbrownai/react)), and `@hashbrownai/angular` needs `@angular/core` and `@angular/common` `^22.0.0` ([npm @hashbrownai/angular](https://registry.npmjs.org/@hashbrownai/angular)).
- **Angular history:** 0.1.0 to 0.3.0 required `^20.0.0`, 0.5.0 required `^20.0.0 || ^21.0.0`, and 0.6.0 onward requires `^22.0.0`. **React history:** 0.1.0 and 0.2.0 required `~18.3.1 || ~19.0.0`, and 0.3.0 onward requires `>=18 <20` (npm version documents above).
- The quickstarts assume "an existing React 18 or 19 app using Vite and TypeScript, Node.js 24" ([React Quickstart](https://hashbrown.dev/docs/react/start/quick)) and "an existing Angular 22 app using standalone components, Node.js 24" ([Angular Quickstart](https://hashbrown.dev/docs/angular/start/quick)). The Angular examples use `provideZonelessChangeDetection()` ([Angular Quickstart](https://hashbrown.dev/docs/angular/start/quick)).
- **Angular signal API:** `chatResource()`, `structuredChatResource()` and `uiChatResource()` expose state as `Signal`s, for example "`readonly subagents: Signal<readonly SubagentRun[]>`. Derive groups with `computed()`" ([Activities, Angular](https://hashbrown.dev/docs/angular/concept/activities)). The README shows `uiChatResource({...})` and `@for (message of chat.value(); ...)` ([C/README.md](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/README.md)).
- v0.8 requires bundlers that support package `imports` ("upgrade older bundlers and test runners before installing v0.8") ([C/CHANGELOG.md, 0.8.0](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/CHANGELOG.md)).
- **Threadplane** (an optional, separate chat presentation layer from cacheplane) needs React 19.2.4 or later, and its React packages are "private packages" that must be built from a pinned git revision ([Threadplane Chat](https://hashbrown.dev/docs/react/recipes/threadplane)). The Angular Threadplane packages "support Angular 20–22" ([Threadplane Chat, Angular](https://hashbrown.dev/docs/angular/recipes/threadplane)).
- The launch post called hashbrown "isomorphic", supporting server-side rendering ([launch post](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/www/content/blog/2025-06-25-hashbrown-launch.md)).

### Inferences
- The Angular-first heritage shows in the launch venues (NG Rome, Angular Air) and in npm downloads (see section 7), where Angular outpaces React. The `^22`-only peer range means Angular users must be on the current major.

### Gaps
- No Vue, Svelte, Solid or Web Components adapter is documented. The README mentions a "framework-free core" only for the atc example's app logic, not as a supported binding.

## 4. Server contract, deployment and streaming

### Takeaway
The client POSTs an AG-UI `RunAgentInput` (default route `/run`; the quickstart uses `/api/chat`). The server calls an adapter and streams AG-UI events back as SSE using `@ag-ui/encoder`'s `EventEncoder`, cancelling the provider call when the browser disconnects. The documented Node host is Express. A separate ASP.NET Core library (`Hashbrown.AspNetCore`, NuGet `0.1.0-preview.1`) and a Pydantic AI compatibility package cover .NET and Python. LangGraph, Mastra and Pydantic AI backends are qualified only partially, at the AG-UI boundary.

### Cited Findings
- **Flow.** "The client owns the interface and conversation state. Your server owns the provider connection and required policy. They exchange run input and AG-UI events" ([How Hashbrown works](https://hashbrown.dev/docs/react/start/how-it-works)).
- **Quickstart server:** Express with `express.json({ limit: '1mb' })`, an `AbortController` aborted on `res.close`, `res.setHeader('Content-Type', encoder.getContentType())`, and a `for await` loop writing `encoder.encodeSSE(event)`. "A disconnected browser cancels the provider request". The endpoint "is for local development… Before publishing an endpoint, add request validation, authentication, authorization, and usage limits" ([React Quickstart](https://hashbrown.dev/docs/react/start/quick)).
- **Default URL.** "Hashbrown's UI packages post to `/run` by default". React configures it with `<HashbrownProvider url="/api/run">` ([C/README.md](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/README.md)).
- **AG-UI adoption.** v0.6 made it mandatory: "servers must speak AG-UI… return `AsyncIterable<AGUIEvent>` instead of encoded frames", and "the legacy frame transport is removed" ([C/CHANGELOG.md, 0.6.0](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/CHANGELOG.md)). v0.7 moved to AG-UI 1.0 (`@ag-ui/*` 0.0.59 to 1.0.2), with `THINKING_*` events replaced by `REASONING_*` (same file, 0.7.0).
- **Securing a public endpoint** is a dedicated recipe ([Securing a Public Endpoint](https://hashbrown.dev/docs/react/recipes/public-endpoint)). The Ollama page notes that "A TypeScript assertion on the request body does not validate it" ([Ollama](https://hashbrown.dev/docs/react/platform/ollama)).
- **.NET.** The "tested reference uses .NET 10, Microsoft Agent Framework, and the upstream AG-UI SDK". It covers Responses and Chat Completions with OpenAI and Azure OpenAI, "streaming JSON and trusted UI, browser/server tools, and application confirmation with interrupt/resume". The library is `Hashbrown.AspNetCore` on SDK `10.0.402`, and the recovery examples need hashbrown SDK 0.8.1 or later ([.NET with OpenAI and Azure](https://hashbrown.dev/docs/react/platform/dotnet)). NuGet lists only `0.1.0-preview.1` ([NuGet index](https://api.nuget.org/v3-flatcontainer/hashbrown.aspnetcore/index.json)). `0.1.0-preview.2` is "prepared" but unpublished, and ".NET 8/9 and mixed-version rolling upgrades remain follow-ups" ([C/CHANGELOG.md, 0.9.0](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/CHANGELOG.md)). A runnable starter is in [C/examples/dotnet-starter](https://github.com/liveloveapp/hashbrown/tree/3da245d12d65a378095755b65448b5d9e985db47/examples/dotnet-starter).
- **Python.** `hashbrown-pydantic-ai` 0.1.0 is an "Optional AG-UI compatibility" adapter (`AGUIAdapter.dispatch_request`). It adds a `hashbrown.tool` outcome record and "no executors or storage", and requires "Python 3.11+, Pydantic AI 2.64–2.x, AG-UI 1.x and Starlette" ([C/packages/pydantic-ai/README.md](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/packages/pydantic-ai/README.md); version from `pyproject.toml`). The PyPI JSON API returned "Not Found" for `hashbrown-pydantic-ai` on 2026-11-18, so it appears unpublished.
- **Agent-framework compatibility page.** It holds "partial, versioned qualifications at the AG-UI boundary" across ten capability families, among them conversation, tools, approvals, state, structured output, trusted UI, media, activities, delegation and recovery. Profiles last qualified 2026-10-30 include `langgraph/local-sdk-seam` (`@ag-ui/langgraph` 0.0.45, `@langchain/langgraph` 1.5.3) and `mastra/buffered` (`@ag-ui/mastra` 2.0.1, `@mastra/core` 1.80.0). The page notes "Native checkpoint restore… not-tested" for LangGraph ([Framework compatibility](https://hashbrown.dev/docs/react/platform/compatibility)). Pydantic AI, Google ADK, Strands, CrewAI, AG2, Agno, LlamaIndex, the Vercel AI SDK and Microsoft Agent Framework (.NET) are listed as `planned` or `not-tested`; the Vercel AI SDK entry reads "Bridge/transport investigation required" (same page).
- **LangGraph** connects "through a standard AG-UI endpoint", with no B4 agent needed. The pinned bridge "omits standard subagent lifecycle/provenance", and "its cancellation terminal lacks an explicit cancelled outcome" ([LangGraph without B4](https://hashbrown.dev/docs/react/platform/langgraph)).
- **Serverless.** The repo's docs site deploys on Vercel (`www/vercel.json`, Next.js `next.config.ts` in the clone). The docs have no dedicated serverless deployment page; the only hosts shown are Express and ASP.NET Core (own reading of `llms.txt` page list).

### Inferences
- In practice the server contract is the AG-UI 1.0 HTTP+SSE binding plus a `forwardedProps.hashbrown` extension, carrying `responseSchema` and `ui`. Any AG-UI agent can serve hashbrown's plain chat and tool display. Generative UI and structured output also need the agent to honour that extension, or to adopt the schema from `createUiJsonSchema()`.
- Nothing in the contract needs a long-lived server. A streaming-capable serverless function should work (inference, not documented).

### Gaps
- No documented serverless or edge recipe (Vercel Functions, Cloudflare Workers, Lambda) and no WebSocket transport.

## 5. Human-in-the-loop, approvals, persistence, threads, resumable streams

### Takeaway
Hashbrown follows AG-UI's terminating interrupt model. The agent ends a run with an interrupt, the client exposes `pendingInterrupts`, and `resume()` sends answers for the whole batch in a new run. The docs stress that a direct provider adapter produces no interrupts, so an AG-UI agent server must create them. Persistence is the application's job: v0.6 removed built-in thread load and save, a `threadId` "does not load a transcript", and durable checkpoints come from b4.run (a separate product) or the .NET Postgres journal. Stream reconnect is not qualified.

### Cited Findings
- **Interrupt and resume.** "An interrupt pauses an agent run… Resume… continues the same user turn rather than inventing a new user message". "Your endpoint must be an AG-UI agent that creates interrupts and validates resume decisions. A direct provider adapter does not add approval checkpoints". "The client owns the form and submits every answer for the pending batch together". "An approval permits the next step; it does not prove that step ran or succeeded" ([Interrupt and Resume](https://hashbrown.dev/docs/react/concept/interrupt-and-resume)).
- **Interrupt fields.** Each interrupt "preserves the server's ID, reason, message, `responseSchema`, expiry, and optional tool, metadata, and subagent fields". `approved: false` is a resolved denial, while cancellation uses `status: 'cancelled'`. "The server must handle duplicate delivery and enforce expiry and ownership independently" ([Interrupt and Resume](https://hashbrown.dev/docs/react/concept/interrupt-and-resume)).
- **No client-tool approval gate found.** The Tool Calling page shows browser handlers that run when the model calls them. Its only approval reference points to `pendingInterrupts` and `resume()` ([Tool Calling](https://hashbrown.dev/docs/react/concept/functions)). The docs instead model approval as app-owned UI: a generated card is "a proposal", and the workbench enables **Accept plan** "only after a fresh, successfully completed response passes its two-step plan rules" ([Generative UI with React Components](https://hashbrown.dev/docs/react/concept/components); [Introduction](https://hashbrown.dev/docs/react/start/intro)).
- **Shared agent state** is "a JSON value exchanged alongside a conversation". "Passing state to a direct provider adapter does not automatically turn it into instructions, and setting state does not start a request" ([Shared Agent State](https://hashbrown.dev/docs/react/concept/shared-agent-state)).
- **Threads and persistence.** v0.6 removed thread loading and saving: "adapters no longer accept `loadThread` / `saveThread`… persist messages in your application" ([C/CHANGELOG.md, 0.6.0](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/CHANGELOG.md)). "A thread identifier connects the conversation logically; it does not save messages or create a durable checkpoint" ([How Hashbrown works](https://hashbrown.dev/docs/react/start/how-it-works)). The Persist and Resume Threads recipe has the app save completed text with an expected version, where a `409` means a conflict, and says "this application helper… is not a Hashbrown storage API". "A saved conversation does not contain tool calls, generated components, shared agent state, or a paused agent checkpoint" ([Persist and Resume Threads](https://hashbrown.dev/docs/react/recipes/threads)). Message history is seeded and replaced explicitly ([Message history](https://hashbrown.dev/docs/react/concept/message-history)).
- **Durable recovery via b4.run.** "b4.run supplies durable runtime stores; our application owns identity, authorization, and the effect itself". The reference uses b4.run 0.15.5 with `@b4run/postgres-storage` and routes such as `GET /api/production/threads/:id/recovery`, which "Read authorized history, pending approvals, and application state" ([Durable recovery with b4.run](https://hashbrown.dev/docs/react/platform/b4run)). b4.run's repo is `cacheplane/b4run` ([LangGraph without B4](https://hashbrown.dev/docs/react/platform/langgraph)).
- **Cold browser recovery (0.9.0, unreleased).** It adds "inert pending-browser recovery state and explicit `resumeConversationRecovery` settlement", and "Reading or restoring a snapshot never execute[s]" ([C/CHANGELOG.md, 0.9.0](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/CHANGELOG.md)). The .NET published pair "cannot cold-restore pending mixed approvals with an unresolved browser sibling" ([Native .NET mixed tools](https://hashbrown.dev/docs/react/platform/dotnet-native-tools)).
- **Resumable streams.** The compatibility catalogue defines `recovery.reconnect` as "Disconnect and reconnect an actual streaming subscriber". It is "not-tested" on the qualified profiles ([Framework compatibility](https://hashbrown.dev/docs/react/platform/compatibility)). No client API for rejoining a running stream is documented (own search for reconnect, rejoin and resumable in `llms-full.txt`).
- **Cancellation.** A `RUN_FINISHED` with `outcome: { type: 'cancelled' }` "settles the run as cancelled, rolled back like a local stop" ([C/CHANGELOG.md, 0.8.0](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/CHANGELOG.md)).

### Inferences
- In this repo's terms, hashbrown is on the AG-UI side of the "terminating vs in-stream approval" split in [agent-ui-research.md](../agent-ui-research.md). It has no equivalent of Vercel's in-stream `tool-approval-request` for browser tools.
- Durable state lives outside the framework, in b4.run, the .NET journal or app code. That fits this repo's plan of an append-only session log on the server with a thin UI projection.

### Gaps
- Whether the 0.8.3 React and Angular APIs expose `pendingInterrupts` and `resume()` exactly as documented, or whether parts are 0.9-only, needs source checking. The page marks only cold recovery as unreleased.
- The relationship between LiveLoveApp (hashbrown), cacheplane (Threadplane, b4.run, the `@cacheplane/partial-*` parsers) and TypeSafe is not stated in the docs I read.

## 6. Comparison with this repo's agent-UI research

### Takeaway
Hashbrown sits on the **declarative tier** of the three-level taxonomy, at its constrained end. The model emits schema-validated JSON that selects from developer-registered, already-implemented components (`exposeComponent`) and fills their props, with optional nesting. This is closer to A2UI and json-render than to the AI SDK's tool-result-to-component mapping. It reaches the **top tier only for computation**, not for UI: model-written JavaScript runs in QuickJS and returns data, but never renders markup. Its distinctive combination is client-owned typed generative UI with streaming partial props, browser-executed tools, a framework-agnostic schema language, first-class Angular support, and AG-UI as the wire. That makes it a headless AG-UI client comparable to CopilotKit's or assistant-ui's runtime layer, minus prebuilt chat components.

### Cited Findings
- **This repo's taxonomy:** low tier, "the app maps a tool result to a pre-built component"; middle tier, "the model composes a validated declarative spec from a catalogue"; top tier, "the model or a server ships arbitrary HTML rendered in a sandbox" ([agent-ui-research.md](../agent-ui-research.md)).
- **Hashbrown's own boundary.** "The model can select an exposed component and supply its values. It does not provide a new React component or arbitrary markup for Hashbrown to execute" ([How Hashbrown works](https://hashbrown.dev/docs/react/start/how-it-works)). "The fields are text bindings, so the model cannot inject component code or HTML" ([Generative UI with React Components](https://hashbrown.dev/docs/react/concept/components)).
- **Runtime boundary.** In the runtime lesson, "Code doesn't stream into a generated component". Results are "application-rendered data" ([JS Runtime](https://hashbrown.dev/docs/react/concept/runtime)).
- **Interop with other agent stacks.** `createUiJsonSchema` targets agents "Hashbrown doesn't run (CopilotKit, LangGraph, your own server)". The v0.7 changelog also cites "a CopilotKit renderer bundle" falling "from 244 KB to 117 KB minified", which suggests hashbrown's UI kit can render inside a CopilotKit app ([C/CHANGELOG.md, 0.7.0](https://github.com/liveloveapp/hashbrown/blob/3da245d12d65a378095755b65448b5d9e985db47/CHANGELOG.md)).
- **No A2UI or MCP Apps support.** A search of `llms-full.txt` for "A2UI", "MCP Apps" and "mcp-ui" returned no hits (own search, 2026-11-18). The Vercel AI SDK is only a "planned" compatibility profile ([Framework compatibility](https://hashbrown.dev/docs/react/platform/compatibility)).
- **Vercel Labs' UI SDK, for contrast:** a headless *behaviour* library (roving focus, selection, ARIA) across five frameworks, plus a "permissioned agent bridge" that lets agents operate an existing UI. In this repo's report it sits "beside the generative-UI renderers" ([vercel-ui-sdk.md](../vercel-ui-sdk.md)).

### Inferences (all placements are my inference unless quoted above)
- **Tier placement:** declarative tier, catalogue-constrained. Hashbrown's "spec" is a JSON tree of `{componentName: props}` validated by Skillet, which is close in spirit to A2UI's catalogue rule. It differs from A2UI in four ways. (a) The catalogue is the app's own React or Angular components, not a cross-platform standard catalogue. (b) The spec is the model's structured-output response, not a separate agent-to-UI message stream (`createSurface`, `updateDataModel`). (c) It has no separate data model or bindings. (d) It is not a published, renderer-neutral spec.
- **Versus AI SDK UI and CopilotKit "Controlled":** those map *tool calls or results* to components. Hashbrown lets the *final answer* be a component tree, so layout choice (which card or dashboard, and nesting) is the model's. That puts it a notch above the low tier.
- **Versus CopilotKit:** both are AG-UI clients. CopilotKit ships prebuilt chat UI, A2UI and MCP Apps renderers and an "Open Generative UI" sandbox. Hashbrown is headless and React/Angular-only, and adds browser-run tools, a QuickJS code tool, decisions, and adapters that call providers directly without an agent framework.
- **Versus assistant-ui:** assistant-ui is a runtime plus primitives for thread state (branching, editing). Hashbrown has no branching or edit-and-regenerate thread model and leaves persistence to the app.
- **Versus Vercel UI SDK:** they are complementary layers. UI SDK supplies accessible behaviours and an agent bridge for operating existing UI, while hashbrown has the model *choose* UI. Neither generates code that renders.
- **What hashbrown does that the others in this repo don't:**
  - (1) First-class **Angular** with signals and resources.
  - (2) **Partial-prop streaming** into typed components via `s.streaming.*`.
  - (3) A **sandboxed JS tool** for model-written code that runs in the browser, not on a server.
  - (4) **Decision models** with confidence, for UI selection.
  - (5) **Browser-local model transports** (Chrome, Edge, WebLLM) behind the same hooks.
  - (6) Unusually explicit, versioned **conformance evidence** per agent framework.
- **Fit for this repo's build:** hashbrown's model, in which the UI is a projection of AG-UI events, the server owns policy and credentials, and approvals are terminating interrupts, matches the "session event log is the UI contract" conclusion in `agent-ui-research.md`. Its trusted-component catalogue is a safe default for generative UI without iframes.

### Gaps
- No primary-source head-to-head (bundle size, render latency, failure rates) between hashbrown and CopilotKit, A2UI renderers or the AI SDK was found.

## 7. Adoption and maturity

### Takeaway
Hashbrown is young but very actively developed, and still pre-1.0. It has had 38 core versions since 2025-05-01, five breaking minor releases between July and October 2026, and four releases in five days in late October 2026. Its npm footprint is modest, about 27k monthly downloads for core versus about 2.9M for CopilotKit's React core. It is maintained by LiveLoveApp (Brian Love and Mike Ryan). It has two in-repo apps, `atc` (also live at atc.hashbrown.dev) and the `dotnet-starter`, and conference talks in 2025.
