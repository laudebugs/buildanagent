# Fact-check: the egress proxy and the secret scrubber

This log checks the claims that `packages/harness/src/credentials/`, the harness README's egress section and todo N20's outcome make on 2026-11-22. It checks them against the tests in `packages/harness/test/credentials/`, which run on this host (Node 22, `openssl` for the test certificate), against Node's documented `lookup` option, and against the IANA special-purpose address registries and AWS's instance metadata page, read on 2026-11-22.

Legend: ✅ confirmed · ✏️ corrected while drafting · ⚠️ unverified or our own inference.

| # | Claim | Verdict | Source and reason |
| --- | --- | --- | --- |
| N20-1 | A tunnel to a name, port, address literal or malformed target that is not allowed gets 403 and a log record, and the name is not looked up | ✅ | `proxy.test.ts`: the refused targets all return 403, the resolver's call list stays empty, and each record has the status, a zero byte count and a reason |
| N20-2 | A route request with the right sentinel and method reaches the upstream with the real header; a wrong method, sentinel or route is refused with nothing sent upstream | ✅ | `proxy.test.ts` against a local HTTPS server with a self-signed certificate that only the test trusts; the server's own record shows the real `authorization` value and no request for the refused ones. Changing the method, sentinel or address check made the matching test fail |
| N20-3 | The proxy refuses loopback, link-local, private, shared, benchmarking, documentation, multicast and reserved IPv4 ranges | ✅ | The IANA IPv4 Special-Purpose Address Registry (last updated 2025-10-09) lists 0.0.0.0/8 "This network", 10/8 and 172.16/12 and 192.168/16 "Private-Use", 100.64/10 "Shared Address Space", 127/8 "Loopback", 169.254/16 "Link Local", 192.0.0/24 "IETF Protocol Assignments", the three TEST-NETs "Documentation", 198.18/15 "Benchmarking", 240/4 "Reserved" and 255.255.255.255/32 "Limited Broadcast". `addresses.test.ts` checks each range's edges |
| N20-4 | It refuses IPv6 loopback, unspecified, unique-local, link-local, documentation and 6to4 addresses, and IPv6 addresses that wrap a refused IPv4 one (mapped, compatible, NAT64) | ✅ | The IANA IPv6 Special-Purpose Address Registry (2025-10-09) lists ::1/128 "Loopback Address", ::/128 "Unspecified Address", ::ffff:0:0/96 "IPv4-mapped Address", 64:ff9b::/96 (translation), 2001:db8::/32 "Documentation", 2002::/16 "6to4", fc00::/7 "Unique-Local" and fe80::/10 "Link-Local Unicast". `addresses.test.ts` checks the wrapped forms |
| N20-14 | The IPv6 prefixes 64:ff9b:1::/48, 100::/64, 2001::/23 (Teredo, benchmarking, ORCHID), 5f00::/16 and 3fff::/20 are special-purpose | ✅ | The IANA IPv6 Special-Purpose Address Registry (2025-10-09) lists them as "IPv4-IPv6 Translat." | N20-17 | A secret that Node would refuse in a header can't stop the process, and the proxy answers 502 and carries on | ✅ | `proxy.test.ts` with a secret holding DEL and one above U+00FF; removing the guard around the request made the case fail with an unhandled rejection |
| N20-5 | Multicast (ff00::/8) is refused | ⚠️ | The IPv6 special-purpose registry does not list ff00::/8, and the multicast registry was not read. | N20-6 | 169.254.169.254 is the cloud instance metadata address, and it is link-local | ✅ | AWS's EC2 instance metadata page gives `http://169.254.169.254/latest/meta-data/` and says "These IP addresses are link-local addresses and are valid only from the instance"; its IPv6 address `fd00:ec2::254` is unique-local, which the proxy refuses too |

An address literal is refused before it, because Node does not look an address up |
| N20-8 | The real secret appears in no log record, no response to the sandbox, no sandbox environment value and no scrubbed entry | ✅ | `proxy.test.ts` serialises the replies, the log and the environment and searches for the secret; the logger is never given a header. | N20-9 | A service that echoes the request's headers back reveals the credential | ⚠️ | Our inference from how the proxy passes responses through: it doesn't read or rewrite them. No such service was run, so the README states it as a limit |
| N20-10 | `scrubSecrets` removes a secret in strings and keys at any depth, and in percent-encoded, JSON-escaped and base64 forms, and keeps an entry's structural fields | ✅ | `scrub.test.ts` |
| N20-11 | `proxy.fetch` rejects with `egress_denied` for a host, port, literal or plain-HTTP URL that is not allowed, and a route URL gets injection | ✅ | `proxy.test.ts`: five refused URLs, none reaches the server, and a fetch of a route URL sends the real header |
| N20-12 | The proxy serves the same routes on a Unix socket | ✅ | `proxy.test.ts` sends a route request over `socketPath` and the upstream sees the real header |
| N20-13 | Any local process can use the loopback proxy's tunnels, but only one that knows a sentinel can use a route | ✅ | By construction: sentinels are 18 random bytes for each proxy, and the listener has no other credential. No test tries a second process |
