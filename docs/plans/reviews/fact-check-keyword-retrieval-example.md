# Fact-check: the Vercel AI SDK keyword retrieval example

This log checks the claims that `verify/vercel-ai-sdk/examples/17-keyword-retrieval.ts`, its header comment and its README section make on 2026-11-22 (todo T41), against the pinned `ai@7.0.162`, the mirrored docs at tag `ai@7.0.162`, Apache Lucene's documentation and the run itself.

Legend: ✅ confirmed · ✏️ corrected while drafting · ⚠️ unverified or our own inference.

| # | Claim | Verdict | Source and reason |
| --- | --- | --- | --- |
| T41-1 | `generateText` runs a tool's `execute` with the model's parsed input, sends the result back and calls the model again until it answers or `stopWhen` is met | ✅ | `docs/03-ai-sdk-core/15-tools-and-tool-calling.mdx`: `execute` "is called with the inputs from the tool call", and with `stopWhen` "the AI SDK will trigger a new generation passing in the tool result until there are no further tool calls or the stopping condition is met"; the example's tool records each query it received, and the transcript shows the call, the tool result and the answer |
| T41-2 | The scripted model's second request carries the tool's result as the last prompt message | ✅ | The example's scripted turn reads `requests[n].prompt.at(-1)` and builds its answer from the result's text; its checks that the answer repeats kb-01 or kb-06 pass, so the result was there, and the transcript shows the tool message before the second answer |
| T41-3 | The BM25 constants k1 = 1.2 and b = 0.75 are the defaults of Lucene and of SQLite's FTS5 | ✅ | Lucene's `BM25Similarity` documentation: default `k1` 1.2 and `b` 0.75; [U18's log](../../research/memory/fact-check-retrieval-and-memory.md), row 43, for FTS5's "hard-coded at 1.2 and 0.75" |
| T41-4 | The rarity term `log(1 + (N - n + 0.5) / (n + 0.5))` is Lucene's inverse document frequency, which never goes negative | ✅ | Lucene's `BM25Similarity` documentation gives "log(1 + (docCount - docFreq + 0.5)/(docFreq + 0.5))"; the term is positive for every n ≤ N, as the argument of the log exceeds 1 |
| T41-5 | A document's score is the sum over the query's words of rarity times a count that saturates with repetition and is damped for long documents | ✅ | The example's `bm25` function computes `rarity * count * (K1 + 1) / (count + K1 * (1 - B + B * length / averageLength))`, the standard BM25 term; the comment describes it in words |
| T41-6 | The example's search is deterministic: ties break by document id, and no clock, random number or network is used | ✅ | The sort in `bm25` orders by score and then id; two runs of `pnpm test` wrote byte-identical transcripts |
| T41-7 | The tenant filter runs before ranking, so a tenant's search never scores or returns another tenant's document, and the rarity of a word counts only that tenant's documents | ✅ | `searchTool` filters `docs` by tenant before calling `bm25`. The checks read the recorded searches: the globex search returned only kb-06 and the acme search's ids did not include kb-06. A further check reads the ids of the acme search for "settings export", `kb-10,kb-01,kb-04`: across both tenants "export" is common and the ranking begins kb-04, kb-02, kb-08, while within acme it is rare. Filtering the ranking afterwards, or cutting the top three first, fails that check (mutation-tested, rows T41-17 and T41-18) |
| T41-8 | The tenant comes from the session and not from the model | ✅ | The tool's input schema holds only `query`; `searchTool(tenant)` takes the tenant as an argument the example sets, and the recorded calls show each search's tenant |
| T41-9 | "I forgot my login credentials" shares no word with kb-02 or any other acme document, so BM25 returns nothing, while "reset my password" ranks kb-02 first | ✅ | The two checks compare `bm25` over the acme documents: no result for the paraphrase and kb-02 first for the other query; the scripted model then answers "nothing on that" |
| T41-10 | The planted document ranks first because it repeats the question's words, ahead of the real kb-01 | ✅ | The check reads `bm25(acme, question)[0]` and finds kb-10 for "How do I fix a failed export?"; kb-10's text repeats "failed export fix" and its title holds "fix a failed export" |
| T41-11 | The scripted model follows whatever result ranks first, and that is a property of our script, not of real models | ⚠️ | Our construction: the second turn is a function that repeats the first result's text. The header comment, the README and the example's checks say the model is scripted and that the example tests the retriever and what reaches the model |
| T41-12 | Planted text can steer retrieval in real systems, so the planted document is a realistic failure to teach | ⚠️ | [U18's log](../../research/memory/fact-check-retrieval-and-memory.md), rows 48 and 49, which checked the PoisonedRAG and BadRAG abstracts only (corrected by row T41-15); the README states that this planted document is our own construction and not a measured attack |
| T41-13 | No mock model in the example can call a tool that touches the host | ✅ | The last check reads every request's `tools` and requires exactly one function tool named `search_docs`; the tool reads an in-memory array loaded from `support-docs.json` and writes nothing |
| T41-14 | The example has no hybrid variant, and the README says so | ✅ | The example imports no embedding model; the README names this and the todo makes the variant optional |
| T41-15 | Correction of row T41-12: it rested on abstract-only rows, which the repo's rule marks ⚠️ | ✏️ | AGENTS.md: a claim checked only against an abstract is ⚠️ unverified. [U18's log](../../research/memory/fact-check-retrieval-and-memory.md), rows 48 and 49, cite the abstracts of arXiv 2402.07867 and 2406.00083. We did not read the papers' full text for T41, so the claim is ⚠️ here and the README and chapter note describe the planted document as our own construction |
| T41-16 | A tool result's output reaches the next request as a `tool` message whose first part is `tool-result` with `output.type` `json` and the tool's return value in `output.value` | ✅ | `@ai-sdk/provider-utils` `dist/index.d.ts` line 380 declares `ToolResultOutput` with a `json` variant (line 391); the example reads that part directly and throws if the shape differs, and its checks pass, including one with quotation marks in a result's text (kb-14) |
| T41-17 | Post-filtering mutations fail: ranking all documents and then filtering by tenant, and cutting the top three before filtering, each fail the scoping check | ✅ | Mutation runs on 2026-11-22: the first variant fails with "the acme search ranks within acme's own documents: rarity counts only its documents, and kb-13 is absent", and so does the second |
| T41-18 | The rarity term matters to the ranking: replacing it with a constant fails the check that a rare word outranks a common word a document repeats more often | ✅ | Mutation run: a constant rarity of 1 fails "a rare word outranks a common word that a document repeats more often" (kb-02 repeats "password" three times and "webhook" is in kb-09 only); a rarity of 0 fails the first check, which finds no hits |
| T41-19 | The "no tool beyond `search_docs`" check proves only what was offered, and the comment says so | ✅ | The last check reads each request's `tools`; the comment was reworded to say no other tool was within the model's reach, and the checks on the recorded `searches` assert what the tool returned |

**Totals:** 19 claims: 16 ✅, 1 ✏️, 2 ⚠️.
