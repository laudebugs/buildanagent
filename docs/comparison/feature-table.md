# Agent SDK feature table: four loops that differ most on safety defaults and state

*As of November 2026, for `@anthropic-ai/claude-agent-sdk@0.3.327`, `@earendil-works/pi-coding-agent@1.5.2`, `@openai/agents@0.21.0` and `ai@7.0.162`, all in TypeScript. Each cell links to the guide section or fact-check behind it. **(V)** means a runnable example in `verify/<sdk>/examples/` asserts the claim offline; **(D)** means the claim rests on the SDK's docs or package source; **—** means none of our sources covers it.*

The four SDKs share one core idea: a model calls tools in a loop until a stop condition holds. They differ in who runs that loop and how much they decide for you. Claude's SDK runs Claude Code's CLI as a subprocess and ships its full toolset and permission system. Pi runs a full coding harness in your process and leaves every safety gate to you. The OpenAI Agents SDK runs an in-process loop with guardrails, handoffs and resumable approvals. The Vercel AI SDK keeps only the loop and an approval policy, and leaves state to you. Read the table by group: **Safety** and **State** separate the four most sharply, while **Tools** and **Output** show how much they now share.

## Choose by the safety work you want to own

The table points to one decision. Pick the Claude Agent SDK if you want Claude Code's tools and permission system ready-made and can accept Claude-only models and a subprocess per session. Pick Pi if you want to own and read the whole harness, including its session tree and compaction, and will write the gates yourself. Pick the OpenAI Agents SDK if you need guardrails, handoffs and approvals that survive a restart, and will decide where traces go. Pick the Vercel AI SDK if you want the thinnest loop across providers and will bring your own state. The [deep comparison](deep-comparison.md) builds the same triage agent on all four and draws the lessons for our own stack.
