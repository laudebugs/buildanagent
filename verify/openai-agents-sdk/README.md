# verify/openai-agents-sdk

Offline verification harness for the OpenAI Agents SDK (JS) docs and our examples, pinned to `@openai/agents@0.21.0`. No API key is needed: model calls go to the SDK's own `ScriptedModel` from `@openai/agents/testing`.

## How it works

The SDK runs its agent loop in-process and resolves model names through a default `ModelProvider`, so the harness swaps the provider rather than the network:
- **Doc examples** run unmodified under `scripts/scripted-preload.mjs`. It imports `@openai/agents` (which installs the OpenAI provider), replaces that provider with a scripted one through `setDefaultModelProvider()`, and rejects any non-local `fetch`.
- **The scripted model** (`scripts/scripted-model.mjs`) is a `ScriptedModel` of `modelResponder()` steps. After a tool result it answers; otherwise it calls one function tool with arguments built from its JSON Schema. It answers with schema-shaped JSON when the agent has an `outputType`, and never calls hosted, computer, shell or apply-patch tools. This doc-example tier is unchanged; our own example `13-computer-use-approval.ts` separately checks how the runner executes and asks approval for computer calls it scripts itself.
- **Each run** gets a temp working directory with `fixtures/`, an allowlisted environment with `OPENAI_AGENTS_DISABLE_TRACING=1`, and a timeout. Sandbox examples run from their own folder, because they mount sibling folders relative to it.
- **Extraction** copies `examples/` with its layout, so the docs' `?raw` imports and the files' relative imports resolve, and marks the copies as ESM, as a reader's project would be.

## Region markers feed the book's listings

Some examples carry `// #region <name>` and `// #endregion` comments, which change no behaviour. The book's `::listing` directive shows the code between them, so a chapter quotes only code that `pnpm test` type-checks and runs. Rename or remove a region only together with the chapters that list it, because `check:book` fails on a region that no longer exists ([how to add a listing](../../apps/manual/README.md#a-listing-shows-a-region-of-a-real-file)).

## Transcripts record each example's run for the book's replays

`pnpm test` also writes `results/transcripts/<example>.json` for each example that calls the mock model; `14-realtime-session.ts` calls none, so it has no transcript. The transcript holds each request the example sent, each answer and each `check()` with its result, and, when the call stack shows it, the example line that led to each event.

`scripts/run-examples.mjs` preloads the recorder from [`scripts/transcripts/`](../../scripts/transcripts/), which records each `check()` from the `ok - ` line it prints, and only when the call stack shows `check()` printed it. `examples/lib/transcript.ts`, which `lib/check.ts` imports, wraps `@openai/agents/testing`'s `ScriptedModel`.

Recording only reads what the mock already holds, so it changes no verdict. The writer replaces the run's own directories, and the ids, timestamps and durations the SDK generated, with placeholders. An id the mock's script chose stays as written, and so does everything else an example scripts, such as a tool's input. Two runs on any machine therefore write the same bytes.

Commit the transcripts with the change that alters them, unlike a regenerated `run-examples.json`, which holds local paths and is restored before committing. CI's results-drift check fails when a committed transcript differs from the one a fresh run writes, and the book's replays read these files ([replays](../../apps/manual/README.md#a-replay-steps-through-a-recorded-run)).

## The subagent example keeps the subagent's reading out of the orchestrator's context

`examples/12-subagent-as-tool.ts` has an orchestrator call a research subagent through `agent.asTool()`, with each agent on its own `ScriptedModel`. Its checks show that the orchestrator's transcript receives only the subagent's summary, never the subagent's tool calls or the sources it read. They also show that each run's `rawResponses` report that run's own tokens, while the orchestrator's `result.state.usage` counts both runs. Because the nested run shares the orchestrator's run context ([context guide](../../docs/reference/openai-agents-sdk/source/docs/src/content/docs/guides/context.mdx)), read the subagent's own tokens from its `rawResponses`, not from its `state.usage`. The token counts are scripted, and no model measured them: with these counts, the run's total is 4× the orchestrator's own tokens. Anthropic's measured figures, about 4× the tokens of a chat for an agent and about 15× for a multi-agent system ([multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)), are separate measurements that the book cites beside this run.

## The computer-use example pauses a fake computer's Pay click for approval

`examples/13-computer-use-approval.ts` gives an agent the SDK's `computerTool()` and a `Computer` that is only an in-memory list of the actions it received, with a fixture screenshot per page state. It touches no screen, browser, file or network. `ScriptedModel`'s helpers build only function calls and messages, so the example scripts each computer call as a raw `computer_call` item inside `modelResponse()`, which the runner hands to the agent's `computerTool` (`@openai/agents-core`'s `dist/runner/modelOutputs.mjs`). Its checks show that the computer receives the click and the batched type and keypress actions in order, with one screenshot after each call rather than after each action. They also show that `needsApproval` is asked about every action, that the run pauses at the Pay click with that click not yet on the computer, that `approve()` lets it through once, and that after `reject()` the computer receives nothing more. A last check shows the model is offered only the computer tool.

Four details surprised us. The offered tool is named `computer_use_preview`, the default `computerTool()` name, with `type: "computer"`. The scripted model never sees a wire format, so the GA and preview shapes the [tools guide](../../docs/reference/openai-agents-sdk/source/docs/src/content/docs/guides/tools.mdx) describes do not apply to it. An action that throws is logged and the model receives an empty screenshot, so an example that must fail on a broken action asserts on the computer's own record. After `reject()`, the SDK sends the model a fallback 1x1 PNG as the call's result, with the rejection only in `providerData.approvalStatus`, and then adds the assistant message "Tool execution was not approved."; the model's next request therefore carries an image that is not the page. And the transcript recorder (`examples/lib/transcript.ts`) now writes a `computer_call` as a tool call and its result as a tool result, both named after the computer tool the request offered, and flags a rejected or failed result as an error; before that, they were opaque `other` parts. The example proves the SDK's computer-tool loop and approval flow offline. It does not prove how a real model or browser behaves.

## The realtime example scripts a voice session's server and checks what the session does

`examples/14-realtime-session.ts` runs a `RealtimeSession` on `ScriptedRealtimeTransport` from `@openai/agents-realtime/testing`, an in-memory transport that records every call the session makes and lets the example emit the events a server would send. No model, audio or network is involved, so what the model "said" is a script and the checks are about the session. They show that `session.history` equals the items the transport reported; that a scripted `function_call` runs the agent's `tool()` and the result returns through `sendFunctionCallOutput`; that a tool with `needsApproval` raises `tool_approval_requested` and runs only after `session.approve()`, while after `session.reject()` the model gets the rejection text and the tool does not run; and that `session.interrupt()` reaches the transport while a scripted `audio_interrupted` reaches the session's listener. The agent has two in-memory tools and no handoff, so nothing touches the host.

Three limits apply, as of `@openai/agents-realtime` 0.21.0 (November 2026). The testing guide's examples cover the history, tool and interruption checks but none approves a tool call, so the approval check is our own, and it passed. On this transport the two interruption events are independent: the session adds no `audio_interrupted` of its own when it calls `interrupt()`, while the real WebSocket transport emits `audio_interrupted` itself and sends a `conversation.item.truncate` event that cuts the reply to the audio the caller heard, unless the whole reply has already played. The example cannot show that truncation, or what a real model decides to say. And because the example sends no model request, the recorder writes no transcript for it, so a chapter lists its regions but has no replay of it.

The runner treats this example differently from the rest of the realtime sources, and fails closed. `scripts/realtime-classifier.mjs` decides which realtime sources to skip, and `scripts/realtime-classifier.test.mjs`, which `pnpm test` runs first, lists the sources that must run and the ones that must skip. A source runs only if it names no real transport (`OpenAIRealtimeWebRTC`, `OpenAIRealtimeWebSocket`, `OpenAIRealtimeSIP`, or a `'websocket'`, `'webrtc'` or `'sip'` string, comments included), imports `@openai/agents-realtime/testing` in a real import statement, and passes every `new RealtimeSession(` a `transport` that is an identifier set from `new ScriptedRealtimeTransport(`. A session built with no transport defaults to a WebSocket in Node, so it counts as needing a connection. A false skip only costs a run; a false run could reach the real API, because our own examples do not run under `scripts/scripted-preload.mjs`. As a second guard, the runner preloads `scripts/block-network.mjs` for every own example except in a live run: it rejects `fetch` and any socket to a host other than loopback, so an accidental real connection fails offline. Its allowlisted environment passes no proxy variables, so a connection through a loopback proxy cannot reach it either. No extracted doc block matches the exemption, so every realtime doc block that was skipped before still is.

## A live run sends one example to a real provider

The book's occasional live run ([`scripts/live/`](../../scripts/live/), started only by `.github/workflows/live-run.yml`) calls `scripts/run-examples.mjs examples --only <example> --live`. In that mode the runner preloads `examples/lib/live-register.mjs`, a Node.js resolve hook that hands every import of `@openai/agents/testing` in `examples/` the module `examples/lib/live.ts`. Its `ScriptedModel` ignores the script it is given and answers each call from the Responses API through the pinned `@openai/agents-openai`, with the key passed explicitly. The example's `calls`, `firstCall`, `lastCall` and `assertComplete()` therefore work as they do against a script. Each call has its output capped at the run's `maxTokens`, is refused when it offers a hosted tool such as shell, computer use or code interpreter, and goes through the cost guard first. The answer keeps only its output and usage, without the response and request ids, and the transcript goes to `results/live/<provider>/<example>.json`. Without `--live`, nothing in the live mode runs, so `pnpm test` and the committed transcripts are unchanged.

## Scripts

| Command | Does |
|---|---|
| `pnpm run fetch-docs` | Mirror the English docs, `examples/docs` and the license from git tag `v<pinned version>` into `docs/reference/openai-agents-sdk/source/` (committed) |
| `pnpm run extract` | Copy the example files and pull inline TypeScript blocks into `extracted/` (gitignored), mapping each file to the pages that embed it |
| `pnpm run typecheck:docs` | Compile every source against the pinned packages and classify errors → `results/typecheck-docs.json` |
| `pnpm run run:docs` | Run complete, type-clean sources on the scripted model → `results/run-docs.json` |
| `pnpm run factcheck` | Diff the guides' option tables, stream events and error list against the package → `results/factcheck-api.json` |
| `pnpm test` | Type-check and run our examples in `examples/` → `results/run-examples.json` (non-zero exit on failure) |
| `pnpm run verify` | All of the above except `fetch-docs` |

Tunables: `EXAMPLE_TIMEOUT_MS` (default 60000) and `EXAMPLE_CONCURRENCY` (default 4). Run one example with `node scripts/run-examples.mjs examples --only 05-approval-resume`.
